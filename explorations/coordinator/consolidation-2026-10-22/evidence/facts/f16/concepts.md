# Concepts for every worker, chunk f16

The entries name these concepts without a full definition, since other entries use them too. Each belongs in the `fortress-repo` skill, not in the revival part that is being rewritten.

| Term | Entries | Where to define it | What the definition needs |
|---|---|---|---|
| Appendix I and the specification's callouts | F-173, F-174, F-175, F-?1 | `references/specification.md`, or the core's part on the specification | Appendix I (`Specification/appendices/changes.tex`) records each change that the revival made to the text, with its change, rationale, original text and effect. A callout (`\revision`) in a chapter states where an implementation departs from the text, with its gap-ledger row. |
| The two overloading chapters | F-?1, F-174, F-223 | `references/specification.md` | `basic/overloading.tex`, "Overloading and Multiple Dispatch", holds applicability and run-time resolution. `advanced/overloading.tex`, "Overloaded Functional Declarations", holds the rules on an overload set. |
| The type group's papers | F-173, F-174, F-?1, F-223; also P-26, P-45, P-48 | `fortress-repo` core, beside the specification | The overloading papers in `Papers/`: OOPSLA 2011 (overloading with static parameters, its three rules) and POPL 2019 (the dispatcher that instantiates a generic declaration at run time). |
| Functional | F-174, F-223, and many others | `fortress-repo` core, "Fortress as a language" | The specification's noun for a function or a method. |
| The three overloading rules: No Duplicates, Return Type, Meet | F-174, F-175, F-223 | `fortress-repo` core, beside overloading | Already listed by chunk f14's `concepts.md`. |
| Fixing a type parameter, and `BottomType` | F-173, F-?1 | `fortress-repo` core, the static-parameters item | That item says "A type parameter that a call does not fix takes its bound" without saying what fixes one: an argument whose declared parameter type mentions the type parameter inside another type, or the expected type through the return type. `BottomType` is the specification's name for the skill's `Bottom`. F-173 says the rule for its own case. |
| Closed trait, covering, and the level of values | F-175 | `fortress-repo` core, beside `comprises` | A closed trait is already listed by chunk f0's `concepts.md`. Covering: a type covers another when every value of the second is a value of the first (P-60). At the level of values, every value of the trait is a value of a listed type, so another trait may stand between them; at the level of types, each immediate subtype is listed. |
| "It states P-N" and "It builds P-N" | every FACTS entry; F-175 and F-?1 in the cold read | `references/records.md`, the entry's form | Which one an entry uses, and what each says about the POSITIONS entry. |
| Native binding, helper, and `builtinPrimitive` | F-180; also P-58, F-32 | `references/library.md` or `references/compiler.md` | A native binding is a library body that calls Java. Walk binds it through a glue class named in `builtinPrimitive("…")`. The compiled path calls static helper methods in `nativeHelpers/`. P-58 is to make one form serve both. |
| The wrapper generator's skip | F-183 | `references/compiler.md`, beside line 62 | The wrapper generator skips a helper method whose descriptor has a byte, short or array parameter (`SignatureParser.unsayable`). A class type with no Fortress counterpart fails the whole import, which the skill already says. |
| The compiler prelude | F-173, F-180, F-183 | `references/compiler.md` | The compiled path's own standard library, `CompilerBuiltin` and `CompilerLibrary`, which it links in place of the interpreter's library until the switch-over. |
| Descriptor class and stamping | F-183; row 408 | `SKILL.md`, "The compiled run time" | A class's descriptor class is `<class>$RTTIc`. Stamping is the class loader's copy of a template with its static arguments put in. That section describes stamping without naming it. |
| Opening a value at a size | F-181, F-146; row 307 | `references/compiler.md`, or the core's static-parameters item | Reading, at a call, the size or type argument of a value of a closed trait whose listed type takes it in a `where` clause, from the value's class and its run-time descriptor. F-181 says it in words. |
| The rule for numerals, and the tie it settles (added by the judge) | F-173 | `fortress-repo` core, the static-parameters item, or `references/specification.md` | Where the types into which a numeral converts are incomparable, as `ZZ32` and `NN32` are, the numeral is read as a `ZZ32`, or as a `ZZ64` or a `ZZ` when its value does not fit (`Specification/basic/inference.tex`, "A Numeral Whose Conversions Tie"). It settles only a tie that a numeral makes, in the choice of a declaration and in the instance of a type parameter that only numerals fix. |
| Expected type, and a call's static type (added by the judge) | F-173, F-?1; P-48, P-49 | `fortress-repo` core, the static-parameters item | The expected type is the type that a call's context requires (P-49); at checking, it narrows a type parameter that takes its bound. A call's static type is the type the checker gave it; at run time, it narrows the instance of a declaration that only dispatch reaches (P-48). The two are the same narrowing at two times. |
| Declared domain (added by the judge) | F-174; also F-252 | `references/revival-changes.md:46` defines it; the core's overloading item can point there | The set of argument types that a declaration's declared parameter types accept, at every instance within its bounds. |
| The code generator's guards (added by the judge) | F-181; row 701 | `references/compiler.md`, "What the compiled path cannot compile yet" | The checks at the head of `forFnDecl`, `forObjectDeclPrePass` and `forTraitDecl` (`CodeGen.java`) that refuse a declaration with a `where` clause of its own or a contract; the trait guard is `forTraitDecl`'s. |

Concepts that only one entry uses are defined in it: the naked-`Any` rule and the positional restriction (F-174), the non-strict rule (F-223), `NatParam` (F-181), `ZZ32Vector` and `StringVector` (F-183).
