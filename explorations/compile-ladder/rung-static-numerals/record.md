## Revival change

**The change.** The team's compiled path typed a numeral by its prelude's `IntLiteral` or `FloatLiteral` and converted it when the program ran: its code generator emitted an `FIntLiteral` value and a call of the prelude's `coerce_ZZ32` on it at each evaluation, the pair its bytecode optimizer's `RemoveLiteralCoercions` pass matched (`ProjectFortress/src/com/sun/fortress/compiler/asmbytecodeoptimizer/RemoveLiteralCoercions.java:33-51` at b5b0f82c13; `compiler/runtimeValues/FIntLiteral.java` at b5b0f82c13). Now no numeral value exists at run time on the compiled path: each place of a numeral holds one value made before the program runs, a JVM constant where the compile-time evaluation of the place's type's own coercion from the numeral's type ends in an `int`, `long`, `float` or `double` (`ZZ32`, `ZZ64`, `NN32`, `NN64`, `RR32`, `RR64`), and otherwise a static final filled once when the component's class loads, by one call of that coercion compiled as a method of the numeral's four numbers as `ZZ` values (`ZZ`, a program's own types). A program's type's prefix minus on a negative constant runs once in that static final. Under walk, a folded constant at a library number type converts from its exact value. Tests: `ProjectFortress/library_tests/NumeralFoldIntegers.test`, `NumeralFoldFloats.test`, `ProjectFortress/compiler_tests/NumeralAcrossComponent.test`, `NumeralMinusOnceCompiled.test`, `NumeralCoercionOnceCompiled.test`, `ProjectFortress/src/com/sun/fortress/compiler/desugarer/NumeralCoercionFoldJUTest.java`, `ProjectFortress/tests/NumeralFoldedConstantLibraryWalk.fss`. The reason: the Working Draft gives numerals types of their own so that "library designers [can] decide how numerals should interact with other types of objects by defining coercion operations", and has the libraries define the coercions into the number types (`Specification-1.0-frozen/basic/expressions/literals.tex:132-148`); a numeral's coercion called at run time per numeral failed for a coercion of another component, "java.lang.NoClassDefFoundError: NumeralAcrossComponentApi$v".
