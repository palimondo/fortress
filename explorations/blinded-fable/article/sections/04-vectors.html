4. Vectors and matrices of differentiable scalars

microgpt keeps vectors as Python lists of Values and matrices as lists of rows, and writes the three linear-algebra operations it needs as comprehensions:

def linear(x, w):
    return [sum(wi * xi for wi, xi in zip(wo, x)) for wo in w]
# ... inside gpt():
x = [t + p for t, p in zip(tok_emb, pos_emb)]
attn_logits = [sum(q_h[j] * k_h[t][j] for j in range(head_dim)) / head_dim**0.5 for t in range(len(k_h))]
head_out = [sum(attn_weights[t] * v_h[t][j] for t in range(len(v_h))) for j in range(head_dim)]

The mathematics names these: a dot product, a matrix–vector product taken row by row, and a row-vector–matrix product.

{{math:dot}}

Fortress lets us give those names executable meaning. A Vec is a list of Values wrapped in an object so that operators can be attached to it; a Mat is a list of row Vecs. The wrapper costs six one-line delegations — bounds, indices, index/value pairs, size, subscript, slice — after which the library's DelegatedIndexed trait supplies everything a generator needs, so a Vec works inside comprehensions and under ∑ exactly like a list. The operators are then one line each: x + y, the dot product x DOT y (typeset ·), division by a scalar, concatenation x || y, scalar times vector by juxtaposition, and relu applied elementwise.

{{fig:gpt_vec}}

The last three lines define a second big operator: BIG || is the “concatenate all” version of ||, a monoid whose identity is the empty vector. It will join the attention heads.

A matrix subscripts as W[i] (a row), W[i, j] (an entry) and W[r] with a range (a block of rows); W.cols(r) selects columns. W.entries flattens the parameters for the optimizer. Juxtaposition is overloaded twice: W x is the matrix–vector product (each row dotted with x), and a M is the row-vector–matrix product ∑t at Mtj — the form in which attention weights multiply the cached values.

{{fig:gpt_mat}}

With these definitions the transformer below is written in the vocabulary of the formulas: W_q x, K q, alpha V, x + y, W_out relu(W_in x). The dot product of a row with x is a ∑ over Values, so every scalar multiply-add still becomes one node in the autograd graph, exactly as in the reference — the operators add notation, not a different computation.

Why wrappers, and not the library's own vectors

Fortress's specification abbreviates array types as T[n] and vector/matrix types as T^n, T^(m TIMES n), which typeset as the ℝn, ℝm×n of the papers. The sheet below (an exploration, not a running program) shows the candidate spellings side by side:

{{svgw:fig01_variants}}

Only the first two rows of “type spellings” execute in this interpreter, and only with literal sizes: Value[n] with a nat parameter does not unify with the runtime array (an implementation gap), and Value^n parses but denotes the library's Vector, which is restricted to Number (a library gap). The verified first design of this experiment (src/alt/v1_MicroGPT.fss) used explicit Array2⟦Value,0,m,0,n⟧ weights and the index form of the product; it reads as textbook algebra but every signature carries the type noise:
