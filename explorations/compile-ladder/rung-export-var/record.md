## Decisions this rung took, for the landing report

1. **The gated pass test uses an api and a component of the same name**, not the differing-name pair the batch record specified. Rejected alternative: the record's `ExportVarRungXApi.fsi` + `ExportVarRungXLib.fss` pair. It cannot be gated -- `fortress link` refuses it before codegen (`probes/link-and-walk-preedit.txt:4-9`) -- and passing it would have required repairing the repository's api-to-component discovery, which the record itself names as this rung's stop condition. The differing-name pair is kept, as the XXX expected-failure test.
2. **The rung edits two files the batch record did not name** (`scala_src/typechecker/STypeChecker.scala`, `scala_src/typechecker/impls/Operators.scala`) **and does not edit one it did** (`compiler/NamingCzar.java`). Rejected alternative: staying inside `CodeGen.java` and `NamingCzar.java`. The checker refuses the assignment before codegen runs, so a codegen-only edit could not make any program with an assignment pass; and the class name, which is what `NamingCzar` decides, is the deferred half. Neither file is touched by rungs W or B.
3. **The interpreter defect gets a ledger row and a committed probe rather than a gated XXX test.** Alternatives and reasons in `REPORT.md`, section "The three homes". Corrected at the gather stage: the reason is not that the interpreter corpus cannot express an expected failure — it can, `FileTests.java:711` — but that this batch forbids running `ant testSystem`, so the file could not be verified before landing.
4. **Mutability is read from the exporting api's index at the reference site, not registered for every imported api up front.** This is the alternative `repair-r1-atomic-static/REPORT.md:180` rejected for a component's own variables ("it puts the mutability decision in two places"), and R1's reasoning implies the shape it would prefer here: `forComponent` could register a binding for every variable of every imported api beside the component's own, keeping one decision site and leaving `forVarRef`'s fresh-import path as the fallback it was. Rejected for this rung because it reads an index per imported api per component, including apis whose variables are never referenced, to remove a second reader of one boolean — a judgement, not a measurement; neither cost was measured. The paragraph is in `REPORT.md`, section "The precedent search", and the shape a later rung should prefer if a third reader of `isMutable` appears in `CodeGen.java` is named there.
