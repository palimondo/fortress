# Concepts for every worker, chunk p5

An entry defines a concept only when that entry alone uses it: Scala's way of letting a sibling trait's body implement an abstract method (P-149), `SUM`'s fusion with `MAX` and `MIN` (P-151), why floats and `QQ` are only partially ordered (P-154), and the overloading check's skip of operators that are not words of capitals (P-155). P-151 also glosses the `where` clause in one sentence, since its decision is about the clause's forms; the full definition belongs in the core (below). The skill's core already defines walk, the compiled path, the gate, landing, functional methods, `excludes` and the switch-over; `references/compiler.md` defines the checker's timing and its results; `references/interpreter.md` defines the Meet Rule for Functional Methods, which P-149 now names as the rule by which walk refuses its object. The concepts below are used by several entries, or by one entry but owned by a rule for every worker, so the entries name them without explaining them.

| The forms of a `where` clause: the condition and the `where`-clause variable | P-151 (glosses it), P-154, P-152 (row 787) | The `fortress-repo` core's "Static parameters" bullet | A `where` clause states conditions on static parameters, such as `where { E extends StandardTotalOrder[\E\] }`, and may introduce static variables of its own, such as `where [\E\]`, which states no condition (`Specification/basic/trait-parameters.tex`, "Where Clauses": "A where clause may introduce new static variables"). | Exclusion of parameter types with static parameters, read by existential reduction | P-152 (and P-45; F-258) | `references/compiler.md`, beside the overloading rules; today `references/revival-changes.md` | The core says that two overloads stand if their parameter types exclude each other. With static parameters, both paths read exclusion over the whole parameter type: the generic instances that a value of both types would have must have equal static arguments, and the types exclude where those equalities cannot hold, or where at the instance that they force some position excludes. P-152's example, `o` over `P[\T\]` and `Box[\T\]` beside `Q[\T\]` and `Box[\T\]`, is the short form; the core's rule that no type extends two instantiations of one generic trait is why `Box[\T\]` fixes `T`. The cold reader could follow the example but could not decide a case unlike it. |
