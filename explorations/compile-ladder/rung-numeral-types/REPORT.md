## What changed and why

**The library.** `Library/FortressLibrary.fsi:454-494` and `.fss:668-721` declare, beside `Ratio`, `trait Numeral extends Number comprises { NaturalNumeral, RadixPointNumeral }` with the four getters abstract (`digits`, `fractionDigits` and `radix` at `ZZ32`, `digitValue` at `ZZ`), and the value objects `NaturalNumeral(digits: ZZ32, radix: ZZ32, digitValue: ZZ)`, whose `fractionDigits` is 0, and `RadixPointNumeral(digits: ZZ32, fractionDigits: ZZ32, radix: ZZ32, digitValue: ZZ)`. Each has `asString`, the numeral as the Working Draft writes one (its digits in its radix, at least `digits` of them, upper case, the radix point after `digits - fractionDigits` of them, `_r` where the radix is not ten), `asFloat(self): RR64` by one rounding, and its reversed `=` pairs: `NaturalNumeral` at the eight number types, `RadixPointNumeral` at `RR64`, `QQ` and `RR32`, each `do c: T = self; (c = b) end` as the library writes its pairs (`.fss:418` at the base). The number types' coercions, renamed or new, each with its pair:

| type | coercions from the numeral types, and their bodies | pair |
|---|---|---|
| `RR64` | `coerce(x: NaturalNumeral) = asFloat(x)`, `coerce(x: RadixPointNumeral) = asFloat(x)` (`.fss:389-390`) | both (`.fss:419-420`) |
| `QQ` | `Ratio(x.digitValue, 1)`; `x.digitValue / r^(x.fractionDigits)` for `r: ZZ = big(x.radix)`, reduced by `ZZ`'s `/` (`.fss:565-569`) | both (`.fss:588-589`) |
| `AnyIntegral` | `ZZ32`, `ZZ64` or `ZZ` by the value, which is never negative (`.fss:723-728`) | none, as at the base |
| `ZZ32`, `ZZ64`, `NN64`, `ZZ` | `x.digitValue.asZZ32`, `.asZZ64`, `.asNN64`, `x.digitValue` (`.fss:829`, `:935`, `:1045`, `:1155`) | `NaturalNumeral` (`:845`, `:956`, `:1064`, `:1175`) |
| `NN32` | `x.digitValue.asNN32` (`FortressBuiltin.fss:430`) | `NaturalNumeral` (`:453`) |
| `RR32` | `numeralRR32(x.digitValue, x.radix, 0)` and `numeralRR32(x.digitValue, x.radix, x.fractionDigits)` (`FortressBuiltin.fss:214-215`) | both, new (`:258-259`) |

`RR64` comprises `{ Float }` (`.fsi:294`); `Float`'s `asFloat(self): RR64` (`FortressBuiltin.fss:82`); the `^` over the numeral in `ZZ32`, `ZZ64`, `NN64`, `ZZ` and `NN32` renamed, its body `self^(b.digitValue.asZZ32)`; `pi` and `e` at `RR64` (`Library/Constants.fsi:16-17`, `.fss:15-16`); `ReflectiveQuickCheck.fss:40` chooses `theType[\ZZ32\]()` where it chose `IntLiteral`, and the arm `theType[\IntLiteral\]() => Just[\AnyGen\](genZZ32)` (`:157` at the base), which repeated the `ZZ32` arm above it, is dropped. `value object IntLiteral` and `value object FloatLiteral` leave `FortressBuiltin.fsi` and `.fss` with their 24 glue bindings; no line of the one library names either now. The glue classes `interpreter/glue/prim/IntLiteral.java` and `FloatLiteral.java`, and walk's `FIntLiteral` and `FFloatLiteral`, stay in the tree, unused (fork N11).

**The helper pair** (`ProjectFortress/src/com/sun/fortress/nativeHelpers/simpleDoubleArith.java:264-307`): `public static double numeralToDouble(BigInteger v, int r, int m)` and `public static float numeralToFloat(BigInteger v, int r, int m)`, the value `v / r^m` rounded once to the nearest double or float, ties to even, subnormals included, by an integer quotient at the format's last significand bit and its remainder; two private helpers (`lsbExponent`, `roundedQuotient`) whose types all map to Fortress, as the wrapper generator needs. The bindings: `private numeralRR64(v: ZZ, r: ZZ32, m: ZZ32): RR64` in `FortressLibrary.fss:668-670`, which both numerals' `asFloat` call, and `private numeralRR32(v: ZZ, r: ZZ32, m: ZZ32): RR32` in `FortressBuiltin.fss:208-210`, which `RR32`'s coercions call; walk carries `ZZ` in `BigInteger`, `ZZ32` in `int`, `RR64` in `double` and `RR32` in `float` (F-299). Walk's default for a radix-point numeral calls `numeralToDouble` in Java (`Numerals.java`), so the default and `RR64`'s coercion round alike.

**Walk's numerals** (`ProjectFortress/src/com/sun/fortress/interpreter/evaluator/values/Numerals.java`, new). `Evaluator.forIntLiteralExpr` and `forFloatLiteralExpr` (`Evaluator.java:1632`, `:1636`) return the value of the numeral's site, made once: its default, a subclass of `FInt`, `FLong`, `FBigNum` or `FFloat` (their constructors opened to the package) that carries a `Site` with the four numbers. The digits as written come from the numeral's text, since the node keeps the value and not the trailing zeros (`3.14150` has `digitValue` 314150, `fractionDigits` 5). The places:

- a typed binding, a field and an assignment (`LHSEvaluator.java:115`, `:220-230`, `BaseEnv.java:332`, `LazilyEvaluatedCell.java:69`), a parameter (`NonPrimitive.java:247`, `:272`), and a declared return type (`FunctionClosure.java:212-221`, `MethodClosure.java:85-89`, `Numerals.atReturn`): where the default does not fit the type, `Coercions.coerce` makes a numeral the numeral object at a numeral type, else converts it through the place type's coercion whose parameter type is the narrowest holding the numeral type, with no chain through the default (`Coercions.java:59`, `:88-115`, `:268`); the result is kept for the site and type (`Numerals.converted`), so a site gives one object of a reference type; a store keeps the default alone (`Numerals.plain`, deep for tuples);
- an integer numeral outside an integer type's range is not converted, so the place refuses it as walk refused one at a binding before: 'Type mismatch binding 3000000000' (`Numerals.inRange`);
- dispatch (`OverloadedFunction.java:2278-2342`, `:2712`): a declaration fits a numeral as it is where its parameter is the numeral's own type or admits its default; of those, the one that the defaults alone fit, unless the own-type fit's domain lies strictly below it; with no fit, the coercion attempt, each numeral converting only from its own type; and a tie among those, an ambiguous coercion, reads each numeral at its default; a functional method chosen at a numeral's own type receives the numeral object before walk finds the method on it (`Coercions.withNumeralObjects`). The three dispatch caches key a numeral apart from a value of its default type (`Numerals.keys`; `OverloadedFunction.java:99`, `OverloadedMethod.java:29`, `GenericFunctionOrConstructor.java:24`);
- the head of `EvaluatorBase.inferAndInstantiateGenericFunction` (`EvaluatorBase.java:90`): the inference reads each numeral at its default, and where the numerals at one type parameter's positions include a radix point, one beyond `ZZ32` by a `ZZ32` stand-in, so that walk's promotion gives `RR64`; the call's numerals then convert at the instance;
- `SEQV` (`FOrdinaryObject.java:48-49`): two numeral objects compare by `digitValue / radix^fractionDigits`, reduced, across both numeral types;
- `Init.java:46` empties the sites between runs.

**The checker.** `Types.INT_LITERAL` and `FLOAT_LITERAL` are no longer final and switch with the libraries, as `CHARACTER` does: the prelude's `IntLiteral` and `FloatLiteral` under the compiler's, `FortressLibrary`'s `NaturalNumeral` and `RadixPointNumeral` under the one library (`Types.java:61-62`, `:75-95`). `Functionals.isNumeral` counts a numeral with a radix point, and `numeralReading` reads one as `RR64` (`Functionals.scala:418-444`), the prototype's tie rule, written inside the two functions and with no new function, since rung C adds functions near them.

**`strToFloat`** (`Library/FortressLibrary.fss:4839-4840`): its `10^k` and `10^(|frac|)` became `ten^k` for `ten: ZZ32 = 10`. Without it the count stage found two errors there ("The stages").

## Decisions

1. **Walk's numeral is its default, a subclass of `FInt`, `FLong`, `FBigNum` or `FFloat` carrying the four numbers, one value per site, and every store keeps the default alone.** Ways not taken: the numeral object at every evaluation (fork N7's way not taken: every `i + 1` would dispatch by coercion); a reading of the literal node at each place, which dispatch cannot do, since it receives values. Evidence: `x + 1` dispatches as before (walk suite), `y = 0.1` then a `QQ` place sees the plain `RR64`.
2. **Into the eight number types walk converts through the library's own coercion from the numeral type, called with the numeral object and kept for the site and type, not by a Java conversion per type.** The way not taken: fork N7's 'in walk's Java, by the same conversion as the library's coercion'. Evidence: the conversion is the library's by construction, one code path for the eight and a program's type; a site pays once. The integer types' range is checked in Java first, so an out-of-range numeral is refused with walk's binding message ('Type mismatch binding 3000000000', `NumeralOutOfRangeWalk`) rather than the coercion's `IntegerOverflow`. No decision on record covers the way; I acted on the brief's intent, the same value.
3. **Dispatch: the own-type fit, the default compared, the coercion attempt from the own type only, and a tie read at the defaults only on an ambiguous coercion.** Ways not taken: retrying at the defaults whenever no declaration applies, which would chain a numeral through its default into a program's `coerce(x: ZZ32)` (C4 refuses it; `NumeralNoCoercionRefusedWalk`); preferring the own-type fit always, which runs `ZZ32`'s `=(self, b: NaturalNumeral)` for `x = 0` through a Fortress object where `=(ZZ32, ZZ32)` fits. Evidence: fork N6, P-49.
4. **The dispatch caches' key adds, for a numeral, the bottom type, its default's type and its numeral type.** Ways not taken: a second cache for numeral calls; no caching of them. Evidence: `u = 0` and `u = z` for a `ZZ32 z` choose different declarations at the same types.
5. **The inference hook reads numerals at their defaults and, beside a radix point, a numeral beyond `ZZ32` by a `ZZ32` stand-in.** The way not taken, my first: each numeral of the group as an `RR64` value, under which walk infers the object `Float` and the team's `commonSuper` failed. Evidence: `second(0.5, 3000000000)` is the `RR64` 3000000000.0, `commonSuper` passes.
6. **The return conversion in `FunctionClosure` and `MethodClosure`, at a declared return type only; elsewhere the default.** Walk checks no return type, so a numeral that does not convert there is its default. The way not taken: conversion at bindings and fields only (fork N7's).
