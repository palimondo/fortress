## 1. The shadow

`P4/make-shadow.py` edits a copy of `ProjectFortress/src/com/sun/fortress/interpreter/evaluator/values/OverloadedFunction.java` with two calls, 16 lines. `P4/P4Probe.java` beside it holds the relation, the choice, the verdicts and the log (`P4/build.sh`, `javac` against the private home's frozen classpath, classes put first).

With `-Dprobe.p4` unset the copy is the tracked file. With it set, the shadow keeps today's choice and today's verdict and writes each disagreement to the file `-Dprobe.p4.log` names, each distinct line once.

- **The relation.** `a <= b` holds on declared domains when:
  - `b` is plain: `a`'s declared parameter types are a subtype of `b`'s as tuples. A type variable stands for itself, its declared bounds as its supertypes (walk's `SymbolicType`).
  - `b` is generic: walk's own inference (`EvaluatorBase.inferAndInstantiateGenericFunction`), given values that carry only `a`'s declared types, finds an instance of `b` whose domain `a`'s types are below. For a functional method's `self`, the supertype of `a`'s declared self type that instantiates `b`'s trait is used, as walk's inference finds it for a value (`EvaluatorBase.java:63-76`).

  This is the Types paper's existential reading of a generic declaration's domain (`reviews/overloading-judgement.md` sections 3.5 and 3.7, defect 1).
- **What it is applied to.** Only declarations with static parameters of their own: generic functions and methods. A functional method of a generic trait is walk's `GenericFunctionalMethod`. It carries only its trait's parameters (its `getStaticParams()` returns the self type's) and is instantiated from its self argument's type, not inferred from the call, so it keeps today's instance domain.
  - An earlier build read those as generic too. It logged dozens of spurious disagreements across the library's `+`, `=`, `MIN`, `MAX`, `CAP` and `|_|`. The cause is walk's symbolic trait parameters, which carry only the bound of the trait that declares them (`StandardMax[\T\]` where `StandardTotalOrder[\T\]` is meant), so its inference fails between related traits.
  - Those builds' passes were discarded, and every pass reported here ran on the final build (`P4/build.txt`).
- **The choice at a call.** `bestMatchInternal` gathers the declarations it finds applicable, a generic one instantiated at the arguments as today, with the instance it made. The shadow takes the one strictly below every other on the relation, greedily in the order today's loop walks, keeping the first on a tie as today. A line `DISPATCH` is written when that declaration is not today's, and `DECL-AMBIGUOUS` when it is not below every other applicable one. A set with no declaration of the kind above is not compared.
- **The verdict at load.** For every pair the load check compares where one declaration is of that kind, the shadow computes a declared-domain verdict:
  - exclusion as today;
  - otherwise the more specific one on the relation, with the return type as today's check reads it (declared ranges, `r1.subtypeOf(r2)`);
  - equal domains refused as duplicates;
  - neither below the other: the meet as today's `meetExistsIn` finds it.

  A line `LOAD` is written when this verdict differs from today's.
