33.1 Rational Numbers

The trait ℚ (QQ) encompasses all finite rational numbers, the results of dividing any integer by any nonzero integer, and three more elements: +∞ and −∞ (written 1/0 and −1/0), the results of dividing a positive or a negative integer by zero, and the indefinite rational (written 0/0), which is used as the result of dividing zero by zero or of adding −∞ to +∞.

The number types of this chapter are the integer types ℤ, ℤ64, ℤ32, ℕ64, and ℕ32 (Section 33.2), the rational type ℚ, and the floating-point types ℝ64 (RR64) and ℝ32 (RR32). They are siblings under the trait Number: each is a subtype of Number, and none is a subtype of another. Some conversions between them are coercions (Chapter 17), each declared by the type converted to; since coercions do not chain (Section 17.1), each pair is declared. Those among the integer types are given in Section 33.2; the others are these:

Each of the five integer types coerces from NaturalNumeral too. A coercion from a numeral type is generic over the numeral’s four numbers, the static arguments of its type, as coerce ⟦nat n, nat r, nat v⟧(x: NaturalNumeral⟦n, r, v⟧), and computes the type’s value from them (Section 13.1): exactly into the integer types and ℚ, and with one rounding, to the nearest value of the type, into ℝ64 and ℝ32. Since no value of a numeral type exists when a program runs, a numeral type declares no = with a number type, and no number type declares one with a numeral type.

Every other conversion between number types is written explicitly; in particular, a conversion into ℝ64 from ℤ, ℤ64, ℕ64, ℕ32, or ℚ is explicit, written asFloat(x) with the method that each of these types declares; Number itself declares no conversion, and the numeral types declare no asFloat.

Revised by the 2026 revival see Section I.1.50

Before this revision the passage named integer numerals among the sources of the coercion into ℝ64 only. The revival decided on 8 November 2026 that each of the eight number types converts from NaturalNumeral, and ℚ, ℝ64 and ℝ32 from RadixPointNumeral, and on 9 November 2026 that each such coercion is generic over the numeral’s four numbers, and that the numeral types, of which no value exists when a program runs, declare no asFloat and no = with a number type.

Revised by the 2026 revival see Section I.1.29

Before this revision the passage said that the Fortress standard libraries declare asFloat on Number. Each number type now declares its own, and Number declares none, so that a number type of a program’s own need not convert into ℝ64.

Revised by the 2026 revival see Section I.1.28

Before this revision the passage named ℝ64 as the one floating-point type, and the Fortress standard libraries declared ℝ32 a subtype of it, so that a value of ℝ32 was also a value of ℝ64, which Section 6.9 excludes. It now names ℝ32 beside ℝ64, a sibling under Number as the Fortress standard libraries now declare it, with the coercion into ℝ64 that the example of Section 17.8 relies on.

It is often desirable to know that a value lies in a subset of its type, such as the positive values, the nonzero values, or the finite values. Such subsets are not types of their own: a program tests a value at run time, with the comparison operators for its sign and, for a floating-point value, with the two checks that the Fortress standard libraries declare on ℝ64:

The getter check returns Just(x) for a finite value x and Nothing otherwise; the getter check∗ returns Just(x) for a value x that is not a NaN and Nothing otherwise.

Here we present the trait ℚ and its methods. Because ℚ holds 0/0, which is unordered with respect to every rational value, ℚ is neither totally ordered nor a field. The original design of the rational types, in which ℚ and seventeen refined rational types are instantiations of one trait, is kept as a superseded design in Section 41.1.

Revised by the 2026 revival see Section I.1.11

The Working Draft of February 2011 divided the rationals into eighteen types: ℚ, the type ℚ∗ that adds the two infinities, the type ℚ# that adds 0/0, and five refinements of each by sign, each a subtype of others and of the corresponding real types, and it said that the type system tracks them through arithmetic. The Fortress standard libraries never declared them, and the trait by which Section 41.1 defines them is refused by instantiation exclusion (Section I.1.1). The text above describes the number types the library declares, siblings under Number, with the coercions it declares; a subset such as the positive values is tested at run time. ℚ holds the values that ℚ∗ and ℚ# added, as the library’s rational type does and as Chapter 16 already says (“For rational results, division by zero produces 1/0”). Because it holds 0/0, the listing below no longer gives it the field and order traits of the original design, which that design itself withheld from ℚ#.

Revised by the 2026 revival see Section I.1.12

The Working Draft of February 2011 declared ℚ a subtype of the real numbers and of ℚ∗, a field with the nonzero rationals ℚ≠ as its multiplicative group, and totally ordered; it typed the results of the reciprocal, of division and of exponentiation as ℚ∗ or ℚ#, those of the absolute value and of the four hyperfloor and hyperceiling operators as ℚ≥ and ℕ, and it declared seventeen check methods, each returning a refined type or throwing CastError. The listing and the method entries below take the type the Fortress standard libraries declare where they declare the method, and ℚ or ℤ where they do not; the two comparisons by CMP become the one the library declares. The check methods leave the listing: the library declares check and check∗ on ℝ64 (Section 33.1) and no check by sign. What the method entries said “for types ℚ∗ and ℚ#” they now say of ℚ, which holds those values. The coercions from the five integer types are new, with the method entry that follows.

The four traits that the listing’s extends clause names after Number are those the Fortress standard libraries declare on ℚ; their laws hold for the finite rationals and need not hold where 0/0 or an infinity takes part, as the laws of the same traits on ℝ64 need not hold where a NaN takes part.

Revised by the 2026 revival see Section I.1.25

Before this revision the listing extended Number alone, the field and order traits of the original design having left it (Section I.1.12); it now names the traits the Fortress standard libraries declare on ℚ, and the sentence above says where their laws hold.

33.1.1 coerce (x: ℤ)

coerce (x: ℤ64)

coerce (x: ℤ32)

coerce (x: ℕ64)

coerce (x: ℕ32)

Each of these coercions converts an integer to the rational number with the same value.

33.1.2 coerce (x: Identity⟦+⟧)

coerce (x: Identity⟦·⟧)

coerce (x: Identity⟦×⟧)

coerce (x: Identity⟦juxtaposition⟧)

coerce (x: Zero⟦·⟧)

coerce (x: Zero⟦×⟧)

coerce (x: Zero⟦juxtaposition⟧)

The identity for + is 0.

The identity for juxtaposition or · or × is 1.

The zero for juxtaposition or · or × is 0.

33.1.3 opr juxtaposition (self, other: ℚ): ℚ

Juxtaposition of rational expressions is equivalent to using the multiplication operator ·.

33.1.4 opr +(self): ℚ

The unary addition operator + simply returns its argument.

33.1.5 opr +(self, other: ℚ): ℚ

The binary addition operator + returns the sum of its arguments.

The sum of an infinity and either a finite rational or another infinity of the same sign is equal to the given infinity, but the sum of infinities of differing sign is 0/0, and the sum of 0/0 and any rational value is 0/0.

33.1.6 opr −(self): ℚ

The unary negation operator − returns the negative of its argument.

The negative of +∞ is −∞, the negative of −∞ is +∞, and the negative of 0/0 is 0/0.

33.1.7 opr −(self, other: ℚ): ℚ

The binary subtraction operator − returns the difference of its arguments, which is equal to the sum of (a) the first argument and (b) the negation of the second argument.

33.1.8 opr ·(self, other: ℚ): ℚ

opr ×(self, other: ℚ): ℚ

The multiplication operator · (DOT) returns the product of its arguments. The multiplication operator × (TIMES) does exactly the same thing.

The product of 0/0 and any rational value is 0/0, and the product of zero and an infinity (regardless of sign) is 0/0; the product of an infinity and any rational value other than zero and 0/0 is an infinity whose sign is positive if and only if the two arguments have the same sign.

33.1.9 opr /(self): ℚ

The unary reciprocal operator / returns the reciprocal of its argument. The reciprocal of zero is +∞.

The reciprocal of either +∞ or −∞ is zero, and the reciprocal of 0/0 is 0/0.

33.1.10 opr /(self, other: ℚ): ℚ

The binary division operator / returns the quotient of its arguments, which is equal to the product of (a) the first argument and (b) the reciprocal of the second argument.

33.1.11 opr ^(self, power: ℤ): ℚ

Exponentiation of a rational number to an integer power produces a rational result. If the power is 0, then the result is always 1, even if the rational number base is 0 (this definition is somewhat arbitrary but is computationally useful).

33.1.12 opr <(self, other: ℚ): Boolean

opr ≤(self, other: ℚ): Boolean

opr =(self, other: ℚ): Boolean

opr ≥(self, other: ℚ): Boolean

opr >(self, other: ℚ): Boolean

The comparison operators <, ≤, =, ≥, and > allow any rational value to be compared numerically to any other rational value.

The rational values are totally ordered except for 0/0, which is unordered with respect to all other rational values; moreover, for compatibility with floating-point arithmetic, 0/0 is unordered with respect to itself, and therefore these five comparison operators always return false if either argument is 0/0. The value −∞ is less than any finite rational value, and +∞ is greater than any finite rational value.

For ≠ see Section 34.1.3.

33.1.13 opr CMP(self, other: ℚ): Comparison

The CMP operator compares the arguments and returns one of the four values LessThan, EqualTo, GreaterThan, and Unordered.

33.1.14 opr MAX(self, other: ℚ): ℚ

opr MIN(self, other: ℚ): ℚ

opr MAXNUM(self, other: ℚ): ℚ

opr MINNUM(self, other: ℚ): ℚ

The operators MAX and MAXNUM return whichever argument is larger in the total order defined by <, ≤, =, ≥, >, and CMP, and the operators MIN and MINNUM return whichever argument is smaller. (For all four, if the arguments are equal, then the result equals that same value.)

The operators MAXNUM and MINNUM differ from MAX and MIN in their treatment of 0/0: if one argument is 0/0 and the other is not, then MAX or MIN returns 0/0 but MAXNUM or MINNUM returns the argument that is not 0/0.

33.1.15 opr |self| : ℚ

The absolute value operator |…| returns the negative of this rational number if the argument is less than zero, and otherwise returns the argument.

The absolute value of 0/0 is 0/0.

33.1.16 signum(self): ℤ

The method signum returns −1 if this rational number is less than zero, 0 if this rational number is zero, and 1 if this rational number is greater than zero.

The signum of 0/0 is 0/0.

33.1.17 numerator(self): ℤ

denominator(self): ℤ

The method numerator returns the numerator of this rational number, and the method denominator returns the denominator of this rational number, when this rational number is represented in lowest terms (such that the greatest common divisor of numerator and denominator is 1).

The numerator of +∞ is 1, the numerator of −∞ is −1, and the numerator of 0/0 is 0; the denominator of +∞, −∞, or 0/0 is 0.

33.1.18 floor(self): ℤ

opr ⌊self⌋: ℤ

ceiling(self): ℤ

opr ⌈self⌉: ℤ

round(self): ℤ

truncate(self): ℤ

The method floor, likewise the enclosing operator ⌊…⌋, returns the largest integer that is not greater than this rational number.

The method ceiling, likewise the enclosing operator ⌈…⌉, returns the smallest integer that is not less than this rational number.

The method round returns the integer that is closest to this rational number, but if this rational number is exactly halfway between two consecutive integers, then round returns whichever of the two integers is even.

The method truncate returns the ceiling of this rational number if it is negative, and otherwise returns the floor of this rational number. (This has the effect of taking the floor of the magnitude, also called “rounding toward zero.”)

All of these methods throw a DivisionByZero if this rational number is +∞, −∞, or 0/0, none of which has an integer value; so does a division by zero whose result is an integer (Chapter 16).

Revised by the 2026 revival see Section I.1.40

Before this revision the sentence said that all of these methods simply return the argument if it is +∞, −∞, or 0/0, a rational number where the entries above declare an integer result. It now says that they throw a DivisionByZero there, as the Fortress standard libraries do.

The hyperfloor operation ⌊⌊x⌋⌋ computes 2(⌊log2x⌋) and returns the result as a natural number. If the argument is equal to 0, the result is 0. If the argument is negative, an InvalidArgument is thrown.

The hyperceiling operation ⌈⌈x⌉⌉ computes 2(⌈log2x⌉) and returns the result as a natural number. If the argument is equal to 0, the result is 0. If the argument is negative, an InvalidArgument is thrown.

The hyperhyperfloor operation computes 2(⌊⌊log2x⌋⌋) and returns the result as a natural number. If the argument is equal to 0 or 1, the result is the same as the argument. If the argument is negative, an InvalidArgument is thrown.

The hyperhyperceiling operation computes 2(⌈⌈log2x⌉⌉) and returns the result as a natural number. If the argument is equal to 0 or 1, the result is the same as the argument. If the argument is negative, an InvalidArgument is thrown.

33.1.19 realpart(self): ℚ

The method realpart for a rational number simply returns its argument.

33.1.20 imagpart(self): ℚ

The method imagpart for a rational number simply returns zero.
