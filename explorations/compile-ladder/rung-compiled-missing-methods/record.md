## Revival change

**The change.** The team's code generator compiled an assignment to an object's `var` field, `c.t := v`, as a call of the field's setter at the value's static type, not the field's (`ProjectFortress/src/com/sun/fortress/compiler/codegen/CodeGen.java`, `forMethodInvocation`, and the team's note there that such calls "don't have an OverloadingType", `:7498-7503`), so where the value's type is strictly below the field's the compiled program died with `NoSuchMethodError`. It also wrote no method for a call that the type checker leaves several declarations (`for_RewriteFnOverloadDecl` split their set without its subsets, `os.split(false)`, and from the team's commit `2fb7488717` of 2012-05-09 `OverloadSet.generateAnOverloadDefinitionInner` writes nothing for a set without a principal member, `OverloadSet.java:2156-2157`), so `num(R)` for a functional method that `trait Q comprises { R }` declares and `object R` defines, a call on `self` of such a method in the trait, and `p(NarrowOf(1))` beside `p(x: Wide)` with a coercion and `p(x: Any)`, died with `NoSuchMethodError`. Walk ran all of them. The tree now passes the setter's value at the field's type, cast below self's trait where it has self's type, and writes the method of the declarations' set, with a method at the call's own signature where it is another declaration's: `compiler_tests/VarFieldAssignedSubtypeRun`, `FunctionalMethodComprisedObject`, `ComprisesSelfAbstractFunctionalMethodCall` and `CoercionAnyOverloadRungC` run and print `PASS`. The reason: "Assigning a left-hand field reference calls the corresponding setter method on the reiver object, passing the new value", whose type "must be a subtype of the type of the left-hand side" (`Specification/basic/expressions/bindings.tex:60-61`, `:86-87`); a functional method is a top-level function overloaded with the others (`Specification/basic/traits.tex:616-626`), and a call dispatches to the declaration applicable at run time than which no other is more specific (`Specification/basic/overloading.tex:302-311`); and the measured failures, 'NoSuchMethodError: ... FVoid VarFieldAssignedSubtypeRun$Cell.t(VarFieldAssignedSubtypeRun$High)' and '... \=num{...}', on the base. The skill's `compiler.md`, "Traps of the compiled path", lists two of these calls as dying (its lines 172 and 174).
