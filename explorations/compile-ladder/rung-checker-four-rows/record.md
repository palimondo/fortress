## Revival change

**The change.**
- An api's declaration for a function that leaves out its return type. The team's compiler gave such a function in a component the return type of the first api declaration of its name, whatever its parameter types (`ProjectFortress/src/com/sun/fortress/scala_src/typechecker/ApiTypeExtractor.scala:117` at a874948ac; dotted and functional methods at `:91` and `:98`). The tree takes the api declaration of the function's own parameter types, and none where several fit a declaration that leaves out a parameter type (`OmittedReturnTypeFromApi`, `OmittedMethodReturnTypeFromApi`). Reason: "Type Inference for Components" expands each construct "corresponding to declarations in APIs exported by C" with the api's types (`Specification/basic/components/type-inference.tex:29`). Measured: `opr BIG LEXICO(g)` took `BIG LEXICO()`'s `BigReduction[\TotalComparison,TotalComparison\]`, 'Function body has type TotalComparison, but declared return type is BigReduction[...]' at `Library/FortressLibrary.fss:130`, depending on the order of identity hashes.
- The top-level overloading check and abstract functional methods. The team's compiler checked a component's top-level overloads over declarations with a body only (`ProjectFortress/src/com/sun/fortress/scala_src/typechecker/OverloadingChecker.scala:120` at a874948ac). So an abstract functional method beside an unrelated top-level function of its name passed, where the same pair with a body was refused. The tree reads every functional method, abstract ones too, and leaves out an abstract one that a subtype's declaration implements with the same parameter types (`XXXFunctionalMethodMeetTopLevelAbstract`, `AbstractFunctionalMethodImplementedByComprised`, `AbstractFunctionalMethodOfGenericTrait`). Reason: "A valid overloading between a functional method declaration and a function declaration is determined by applying the (more restrictive) Meet Rule for functions" (`Specification/advanced/overloading.tex:525-529`); walk refuses the abstract pair at load already, 'first parameters x:[String] and self:[S] are unrelated'.
- The per-provider message's kind word. The team's compiler called every trait or object 'trait' in 'Invalid overloading of m in trait O' (`OverloadingChecker.scala:284` at a874948ac). The tree says 'object' for an object (`XXXDottedMethodMeetAbstractSibling`). Reason: the line tested the compilation unit, which is never an object's index.
- The fourth row, 681, changes no team source's behaviour: the team's compiler had no size inference variables (`Formula.isNatTerm` is the revival's own, 3f297441c). The tree now does what the specification says, inferring `get[\i-1\]` (`NatArithInferChecker`).
