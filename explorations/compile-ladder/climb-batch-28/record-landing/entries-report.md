- P-40 **Sizes are checked, and a size that inference leaves unknown is an error only where it is used.** A size is a `nat` or `int` static parameter, such as the length of an array in its type. The compiled checker checks sizes, and refuses a size beyond `NN32` or `ZZ32` (F-140, the bound on both paths). Wherever the array design, the compiled path's design for arrays (P-85), creates a JVM array, it checks the length there, at run time, and refuses one over 2^31-1. A size that inference leaves unknown is an error only when it reaches a type, a name or a value. So a declaration may declare a size that none of its types uses, and pass. A call that cannot fix a size of the declaration that it would choose is refused, also inside an overload set, instead of passing over that declaration. In the rule that no type extends two different instantiations of one generic trait, two instantiations differ when any static argument but an operator differs, so `Vec[\3\]` and `Vec[\4\]` are two; boolean arguments count too once the checker has boolean parameters. A size used as a number, as in the range `0#n`, converts to `ZZ32` where one is needed, as a numeral does. The 17 vector and matrix operators of the `FortressLibrary` api declare only the sizes that their types use, the change of `explorations/perf-probes/array-sites/e3-rebased.patch`. It finishes the team's own fix of 2008, which removed those sizes from the component only. The JVM length check waits for the array design; under walk such an array stops at its store's factory with walk's own error, which no catch sees (row 527). The checker still passes over a declaration whose unfixed size occurs in its own parameter type (row 400). The checker compares no boolean arguments (row 406).
