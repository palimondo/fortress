## Findings

The run front-loaded everything it could not undo. Four minutes of reading, then five probe components that between them settled the view object, the loaders, the transpose spelling, the API boundary and the cost of the library's product — and only then, after the longest thinking block of the run, the whole program written in one command. That program needed two repairs before it ran and none after: from 02:36:06 the numbers were right, and the remaining twenty-eight minutes went to the check component, the documents and waiting for two check runs.

The probes are where the language actually pushed back, and it pushed back on the library rather than on the design. Four of the five failures in `p02_loaders.fss` are string and integer handling — `strToFloat` overflowing a 32-bit accumulator on a mantissa the weight files use everywhere, `split()` returning nothing, `AND` evaluating both operands, a `ZZ64` that is a `ZZ32` until it meets a `ZZ64` — so the loader is 25 lines of hand-written float parsing and a character scanner inside a program whose mathematical core needed no such workarounds. The layout the brief fixed, by contrast, went in as stated: the flat vector, the nine views, the one-hot scatter-adds, the arithmetic masks and the whole-vector Adam all survived to the committed program unchanged.
