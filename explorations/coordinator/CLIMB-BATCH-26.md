# Climb batch 26

## 1. For the curator

### The words this record uses

- **Walk** is the interpreter. The **compiled path** checks a program's types with the **checker**, then makes JVM bytecode with the **code generator**. Until the **switch-over** the compiled path uses its own small library, the **prelude**; after it, the interpreter's library, the **one library**.
- A **native binding** is a library declaration whose body is `builtinPrimitive("…")`. Its string names a **glue class**, Java over walk's own values, which only walk can call, or a **helper**, a static Java method over plain Java values in `nativeHelpers/`, which both paths call (P-58). A **family** is a set of bindings moved together. A **carrier** is the Java type in which walk passes a declared type, or `self`, to a helper.
- **The count** and **the distance** are the checker's errors on the one library: the count on its main component, the distance on its fourteen core components. Both are 0 (F-53).
- **Walk's load check** is walk's check of the overload sets when it loads a program; it refuses a pair of declarations that it cannot prove valid.
- A **local function** is a function declared inside a block, as `body(i: I): L = …` inside `__bigOperator`; the code generator calls the node a `LetFn`. A **closure** is the object that the code generator makes for a function value, with the variables it captures as fields.
- **Appendix I** is the specification's appendix of changes; a revised passage carries a **callout** that names its entry there.
- A **rung** is one change, built by one worker and checked by a second, the skeptic; a **batch** is a few rungs landed together after the **gate**. A **guard** is a test that passes before the change and after it; an **`XXX` test** records a known defect and turns red when the defect is fixed.

### The question for the curator

**Question 1. A local function compiled as a closure of its own class (a), or as a static method lifted out of the block (b).** Default: (a).

- **The ways.** (a): each local function of a block becomes a class of its own, made as the code generator makes a function expression's (`ProjectFortress/src/com/sun/fortress/compiler/codegen/CodeGen.java:3503-3567`): the variables it captures are the closure's fields, it is made when the block runs, and a call goes through its `apply`; the functions of one block see one another without a mutable cell (fork 9). (b): lambda lifting, as Scala's compiler lifts a local `def` to a private method: each local function a static method of the component's class, its captured values passed as leading parameters along every call of the group, a closure made only where the function is passed as a value, and a lifted method generic over the enclosing declaration's static parameters where its body names them.
- **What it touches of microGPT.** After the switch-over, every `for` loop over a range runs the library's recursive local `loop'` or `lop` (`Library/RangeInternals.fss:1313`, `:1328`, `:1495`, `:1515`, `:1536`, `:1560`), every `SUM` runs through `__bigOperator`'s local `body` (`Library/FortressLibrary.fss:1317`), which is passed as a value under either way, and microGPT's `step` declares typed local functions (`explorations/run-c4/src/MicroGptFlat.fss:54-55`; `explorations/apl/mg/MicroGptApl.fss:79-81`). Under (a) a recursive split calls through the closure's `apply`, under (b) through a static method. HotSpot inlines an interface call that one class receives as it inlines a static call, and (a) allocates one closure each time the block runs, so the planner expects no difference of speed. Nothing compiles against the one library before the switch-over, so nothing can measure it now; phase 6 times microGPT compiled (PLAN, phase 6).
- **The principles.** The team's later word, its code: the code generator compiles a function value as a closure class (`forFnExpr`), and walk binds each local function as a closure in the block's environment, where the group sees itself (`ProjectFortress/src/com/sun/fortress/interpreter/evaluator/BuildLetEnvironments.java:55-81`); the team's own guard refuses local functions without a word on how (`CodeGen.java:3015-3025`, "no local functions"). The library is silent. The peers split: Scala's compiler lifts a local `def` to a method of the enclosing class; Swift's nested functions are closures over what they capture. So the principles that speak point to (a), and it is put to you for microGPT's speed alone.
- **Cost.** (a) is rung L as sized, about 0.65M. (b) threads each captured value through the group's calls and makes a lifted method generic where the block is, about 0.85M by the planner's reading. Either can be undone by one later rung of the code generator.
