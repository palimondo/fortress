## Findings

The brief's ordering held, and it is visible in the transcript as an inversion of round one's. Round one read the library one primitive at a time while translating; this run spent its first ten minutes reading and its next seven thinking, and did not write a line of the program until 06:43 — thirty-two minutes into fifty-four. What it produced in that window is a deliverable rather than a private note: the survey table at `design.md:207–256`, sixteen families with line numbers into `FortressLibrary.fss` and a second table of what is absent, each absence mapped to the one declaration that fills it. Every operator the vocabulary later declares is in that second table, and nothing in the first table was rewritten.

The probes were run as batches in the background, not one at a time, and this is where the wall-clock savings are. Five batches covered nine, four, eight, eight and two probes; the attention comparison and the render pipeline were written *while* a batch was running, and the two check runs were launched as one command at 06:49:46 so that the gap rows, the tour, the design section and the README were all written against a check that was already in flight. The thread is never waiting on itself except for the 77 seconds at the end.

The language pushed back in a single place, and that place is generic dispatch. Five of the eleven new gap rows and four of the run's sixteen dead ends are the same subject: a `nat`-generic function cannot be passed as an argument (156), `Any` in a `nat`-generic signature is an interpreter bug (157), two generic declarations of one operator need an excluding parameter pair (159), a covariant collection of two `nat` instantiations has no common supertype (ledger 96), and an API cannot declare a postfix operator (166). Each was met once, isolated into a standalone component within one or two edits, and routed around; none of them changed the design. The route around 156 and 157 is the more interesting one, because it is what removed every static parameter from the model: the vector functions are written over runtime-sized arrays, not over `Vector[\RR64,s\]`.

The alternatives were judged as the brief asked, on reading rather than on speed, and the run said so with a number attached. The attention block's rank-3 form is 1.4× slower at one thread than the loop it replaced and was shipped anyway, because `A←sm⍤1⊢MK+⍤2⊢(Qh+.×⍤2⊢⍉⍤2⊢Kh)÷HD*0.5` becomes one Fortress line under it and ten statements under the loop. Rather than assert the cost, the run measured four spellings of the losing form to establish that the price belonged to the design and not to the wording, then wrote the measurement into the ledger as row 165 where it can be argued with. The row lift went the other way: all three forms read identically at the call, so the cheapest was taken.

The line budget is the one place where the brief's target was missed and the run said which lines missed it. The model is 82 code lines against a target of 50, and `design.md` names nine specific costs with a ledger row against each — the two `^T` declarations that an API cannot hold, the shape table that a top-level array literal cannot be, the nine weight reads that a comprehension cannot do, the twelve-line `run` where the Dyalog has a one-line driver. The claim that is fully met is the one the brief made countable: zero subscripts in the model, verified by a `grep` whose text is quoted in the design note.

The reuse the review asked for is visible in what the vocabulary does *not* contain. The survey's `Vector`/`Matrix` rows list `scale`, `pmul`, `dot`, `t()`, `+`, `-` and the juxtaposition products as used unchanged, and round one's hand-written `/` on a matrix is gone.
