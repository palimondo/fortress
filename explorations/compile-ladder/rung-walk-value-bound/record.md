## Revival change

**The change.** The team's walk takes two overloaded parameter lists to exclude each other wherever every parameter at which they differ is an object type of one of them (`ProjectFortress/src/com/sun/fortress/interpreter/evaluator/values/OverloadedFunction.java:511` at c1ce2a35e1, the team's `distinct |= unequal && (allObjInstance1 || allObjInstance2)`), and so compares no return types for such a pair. The tree now reads a generic function beside a declaration without static parameters, whose parameter types some instance of the generic accepts, by the overloading rules on their declared domains: `pickFirst[\T extends Number\](a: T, b: T): T` beside `pickFirst(a: NN32, b: NN32): String` is refused at load, 'fails the Return Type Rule' (`ProjectFortress/tests/GenericBesidePlainObjectReturnRuleWalk.fss`), and beside `pickFirst(a: NN32, b: NN32): NN32` it loads and the plain declaration runs for two `NN32` values (`ProjectFortress/tests/GenericBesidePlainObjectValidWalk.fss`). A plain declaration that writes no return type is not judged there. Two declarations without static parameters keep the team's reading. The reason: the Return Type Rule compares the more specific declaration's result with that of every instance of the other that applies to its arguments (`Specification/advanced/overloading.tex:555-559`), and the compiled checker refuses the first pair's kind. The team's walk also refuses every type that is not a value type below a value type (`ProjectFortress/src/com/sun/fortress/interpreter/evaluator/types/FTraitOrObject.java:97-104` at c1ce2a35e1), the type parameter of a generic method included: `Holder[\RR32\]().held()`, for `held[\T extends S\]()` in `Holds[\S\]`, stopped with 'non-value subtype of value type RR32'. The tree now passes a type parameter, which is no declared type, and the call runs (`ProjectFortress/tests/TraitGenericMethodValueBoundWalk.fss`).
