## 3. What the specification settles, and how

It settles the item twice over, and in the direction of the trial patch.

1. **`shift` is a functional method of ℤ.** `Specification/basic-lib/basic-integers.tex:695-702`: `shift(self, k: IndexInt): ZZ`, "The result of `shift(x,k)` is ⌊x·2^k⌋ … positive values of k shifts the bits to the left, and negative values of k shifts the bits to the right." The explicit `self` makes it a functional method, called `shift(x, k)`, not `x.shift(k)`; the team's own dormant draft has it in exactly this form beside `even` and `odd` (`Library/incomplete/basic/Fortress.Number.fsi:162`, `:172-173`). Option 2 of `REPORT.md` section 5 (a dotted method) and option 3 (another spelling) are therefore against the specification's form, and option 4 (leave it undeclared) is against Pavol's decision. The option set had one member consistent with both, and it is the trial.

2. **A parameter named `shift` in the library is then a static error, so the parameters must be renamed.** `Specification/basic/declarations.tex:426-431`: "It is also a static error for multiple declarations with overlapping reaches to declare the same name in the same namespace unless the declarations are overloaded or one declaration shadows the other." `:435-436`: "The reach of a functional method declaration is the component containing that declaration", which for `shift` on `ZZ` is `FortressLibrary`, the component that also holds `trait Range`'s `shiftLeft(shift: I)` (`Library/FortressLibrary.fss:3668-3671`). `:459-461` gives a parameter its own reach inside that component, so the reaches overlap. The list of permitted shadowing at `:476-529` admits a keyword parameter (`:508-511`), `self` and `result`, and fields or dotted methods; a positional parameter is not on it, and `:533` closes the list: "No other shadowing is permitted in a Fortress program." A variable and a function are not overloaded. So within `FortressLibrary` alone the collision is a static error under the specification, independent of the implementation. For the importing components (`RangeInternals`, `List`, and every program) `:454-456` gives an imported declaration the reach of the importing component, which is the reading the shared implementation enforces (`ProjectFortress/src/com/sun/fortress/scala_src/disambiguator/ExprDisambiguator.scala:745-763`, `checkForShadowingVar`, which rejects a variable whose name is any variable or function in scope). The worker's `probes/ShadowEven.fss` shows the same rule already in force for `even` and `numerator` (`probes/ShadowEven.txt`), two of the five functional methods `trait ZZ` declares today (`Library/FortressLibrary.fsi:539-543`).

Rule 4 of the shared prefix says a divergence is settled by the specification; here both the declaration and its consequence are settled, and the worker's own report cites the settling passages (`REPORT.md` section 5, second paragraph). What the worker took to Pavol as "a decision for Pavol" (that `shift` becomes a name no program may bind under `walk`) is the specification's rule at `:454-456` and `:533` applied to a name the specification itself declares. It is the language as written, and it is the same condition `even`, `odd`, `numerator`, `narrow` and `widen` are under today.
