## Revival change

**The change.** The team's compiled checker compared a trait's or object's dotted methods, its own and those it inherits, as one overloading (`ProjectFortress/src/com/sun/fortress/scala_src/typechecker/OverloadingChecker.scala:312-318` at the team's last commit), and that set held no getter (`:146` there); the team's library declared getters wider than the getters they keep from being inherited: `NN32`'s `zero` and `one` at `Number` (`ProjectFortress/LibraryBuiltin/FortressBuiltin.fss:264-265`), `SimpleMappedIndexed`'s `bounds` at `Range` (`Library/FortressLibrary.fss:4031`), `VoidReduction`'s `reverse` at `Reduction` (`:3638`), `ArrayList`'s `extractLeft`, `extractRight` and `indexValuePairs` (`Library/List.fss:264-280`), and the rank-2 and rank-3 ranges' `indexValuePairs` at `Generator` (`Library/RangeInternals.fsi:526-620`, `Library/RangeInternals.fss:1400-1695`), which under walk took no subscript. The tree now refuses a getter whose return type is not a subtype of the return type of the getter of its name that it keeps from being inherited, reading each receiver as the plain type that declares it (`compiler_tests/XXXGetterReturnTypeNotSubtype`, `compiler_tests/SelfTypedGetterNarrowedReturn`); each of those library getters answers the inherited type, and the ranges' pairs take a subscript (`tests/RangeBodiesWalk`). The reason: the Return Type Rule (`Specification/advanced/overloading.tex:555-559`) and "The return type of the overriding declaration must be subtype of that of the overridden declaration to preserve type safety" (`Specification/basic/traits.tex:678`); and the measured failure, the code generator stopping the whole of `FortressBuiltin` against the one library on `NN32`'s getters, 'Likely bug in static analysis, apparently malformed overload set not rejected for FortressBuiltin..NN32.one():Number', and a program's widening getter below a self-typed trait the same way against the prelude.
