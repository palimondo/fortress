2.1 A vector and a matrix

A vector is a list of numbers. A matrix is a grid of numbers, in rows and columns. "A 2 by 3 matrix" has 2 rows and 3 columns: the rows are named first.

Inside a function, Fortress writes both as literals:

m: Matrix[\RR64,2,2\] = [1.0 2.0; 3.0 4.0]
v: Vector[\RR64,2\] = [5.0 6.0]
m: Matrix⟦RR64,2,2⟧ = [1.0 2.0; 3.0 4.0]
v: Vector⟦RR64,2⟧ = [5.0 6.0]

Spaces separate the elements of a row, and a semicolon ends a row. So mm has the rows 1, 2 and 3, 4. Matrix⟦ℝ64,2,2⟧Matrix[\RR64,2,2\]Matrix⟦RR64,2,2⟧ is the library's type for a matrix of floats with 2 rows and 2 columns. Vector⟦ℝ64,2⟧Vector[\RR64,2\]Vector⟦RR64,2⟧ is its type for a vector of 2 floats. Both are kinds of ArrayArray, the type of Part 1, with the sizes added.

2.2 A matrix times a vector

The product of the matrix mm and the vector vv is a new vector. Fortress writes the product as the two names side by side, m vm v. A run printed:

m v (2): 17.0 39.0

Each element of the result comes from one row of mm. Take the row, multiply its elements with the elements of vv, pair by pair, and add:

  • Row 0 of mm is 1, 2. With vv: 1 times 5, plus 2 times 6, is 17.

  • Row 1 of mm is 3, 4. With vv: 3 times 5, plus 4 times 6, is 39.

The step "multiply pair by pair and add" has a name: the dot product of two vectors. Fortress writes it ·DOT·. For the vector vv with itself, a run printed:

v DOT v = 61.0

That is 5 times 5, plus 6 times 6.

Two things follow from the way the product is made.

  • The matrix must have as many columns as the vector has elements. Otherwise the pairs do not match.

  • The result has as many elements as the matrix has rows.

So a matrix with 27 rows and 16 columns turns a vector of 16 numbers into a vector of 27 numbers. The model's last matrix does exactly this: it turns the 16 numbers that stand for a position into 27 scores, one for each token.

In Fortress, two values side by side with a space between them form an operator of their own, juxtaposition. The library declares what it means for each pair of types. For a matrix and a vector it is this product. For two numbers it is multiplication, so 4 nEmbd4 nEmbd is 64.

2.3 The order matters

With the vector on the left, the result differs:

v m (2): 23.0 34.0

Now each element comes from one column of mm. Column 0 is 1, 3: 5 times 1, plus 6 times 3, is 23. Column 1 is 2, 4: 5 times 2, plus 6 times 4, is 34.

Two matrices have a product too. Take a second matrix, nn, with the rows 0, 1 and 1, 0. A run printed both orders:

m n (2 x 2):
    2.0 1.0
    4.0 3.0
n m (2 x 2):
    3.0 4.0
    1.0 2.0

m nm n is mm with its columns swapped. n mn m is mm with its rows swapped. The rule for two matrices is the rule above, used many times. Take row ii of the left matrix and column jj of the right matrix. Their dot product is the element of the product in row ii and column jj.

  • A and B are the two matrices, left and right.

  • Aik is the element of A in row i and column k.

  • The sign ∑ with k under it means: add the terms for every k. Here k runs along row i of A and down column j of B at the same time.

For the pairs to match, the left matrix needs as many columns as the right matrix has rows. A matrix of 16 by 64 times a matrix of 64 by 16 gives a matrix of 16 by 16: the two inner sizes must be equal, and the two outer sizes are the result's.

2.4 The transpose

The transpose of a matrix is the same numbers with rows and columns exchanged: row 0 becomes column 0, row 1 becomes column 1. The program writes it mTm^T. A run printed:

2.5 Many vectors at once: why the program writes x wTx w^T

The function stepstep works on 16 rows at once, one for each position. It keeps the 16 vectors of a stage as the 16 rows of one matrix. To put every row through a matrix ww, the program writes x wTx w^T. A small case shows why this is right. Take mm from above as ww, and a matrix xx with three rows:

x: Matrix[\RR64,3,2\] = [5.0 6.0; 1.0 0.0; 0.0 1.0]
x: Matrix⟦RR64,3,2⟧ = [5.0 6.0; 1.0 0.0; 0.0 1.0]
x m^T (3 x 2):
    17.0 39.0
    1.0 3.0
    2.0 4.0

  • Row 0 of xx is 5, 6, the vector vv. Row 0 of the result is 17, 39, which is m vm v.

  • Row 1 of xx is 1, 0. Row 1 of the result is 1, 3: mm times that vector, which picks column 0 of mm.

  • Row 2 of xx is 0, 1. Row 2 of the result is 2, 4: column 1 of mm.

So row ii of x mTx m^T is mm times row ii of xx. The reason is the rule for two matrices. The element in row ii and column jj is row ii of xx with column jj of mTm^T, and column jj of mTm^T is row jj of mm.

The function stepstep has this form seven times, each time with another matrix of parameters in the place of ww. Read x wTx w^T as "every row of xx, put through ww". The sizes follow the rule. In line 55, for example, the left matrix is 16 by 16 and ww is 64 by 16. The transpose of ww is 16 by 64, so the result is 16 by 64: every row of 16 numbers has become a row of 64 numbers.

A postfix operator binds more tightly than juxtaposition, so x mTx m^T means x (mT)x (m^T) and needs no parentheses.

2.6 One vector of parameters, nine matrices

A weight is another word for a parameter, and a weight matrix is a matrix whose elements are parameters. The model has nine. This list gives each one's index, its name in the files of starting values, its name in the function stepstep, what the name is short for, its size and its job.

  • 0, wte, in stepstep also wtewte: the weights of the token embedding. 27 by 16, 432 numbers. It is the token table. Row tt is the embedding of token tt: the vector of 16 numbers that stands for that token.

  • 1, wpe, in stepstep also wpewpe: the weights of the position embedding. 16 by 16, 256 numbers. It is the position table. Row ii is the embedding of position ii: the vector of 16 numbers that stands for that position.

  • 2, lm_head, in stepstep lmlm: the language model's head, which is the field's name for a model's last matrix. 27 by 16, 432 numbers. It turns a position's final vector into 27 scores, one for each token.

  • 3, 4 and 5, attn_wq, attn_wk and attn_wv, in stepstep wqwq, wkwk and wvwv: attention's weights for the query, for the key and for the value. 16 by 16 each, 256 numbers each. Attention is the stage in which a position reads earlier positions. For that, it makes three vectors from each row, called the query, the key and the value, each with one of these matrices. Part 4 reads it.

  • 6, attn_wo, in stepstep wowo: attention's weights for the output. 16 by 16, 256 numbers. Attention's result goes through it.

  • 7, mlp_fc1, in stepstep f1f1: 64 by 16, 1,024 numbers. MLP is short for multi-layer perceptron, the field's name for the model's second block, which Part 5 reads. FC is short for fully connected. This is the first of the block's two matrices.

  • 8, mlp_fc2, in stepstep f2f2: 16 by 64, 1,024 numbers. The second matrix of that block.

The counts add up to 4,192. The program keeps all of them in one vector, pp. The nine matrices lie in it one after the other, each one row after row.

A token's embedding is the same wherever the token stands. In the row of yuheng, the mark, token 26, stands at position 0 and again at position 7. So rows 0 and 7 of gather(wte, ids)gather(wte, ids) hold the same 16 numbers.   • At position 0, the first number goes from 0.0821 to 0.0599: the position's embedding moves it by -0.0222.

  • At position 7, the same 0.0821 goes to -0.0406: the position's embedding moves it by -0.1227.

Every later line of stepstep gets only the sum, xx. The same token at two positions gives two different rows of xx, so the model can give two different answers. The addition does only this: it makes a row depend on its position.

The rows of wpewpe are parameters, like the rows of wtewte. They start as the random numbers of the file wpe.txt, and training changes them. No formula computes them. The numbers above show it: the row for position 7 is not the row for position 0 moved further in one direction. Some numbers are larger and some are smaller, with no order.

The table has 16 rows, so the model can read 16 positions and no more.

Other models tell positions apart in other ways. Two of them, for comparison:

  • The first transformer paper, of 2017, also adds a vector for the position to the token's embedding. It computes that vector by a formula, from sines and cosines of the position's number, which rise and fall slowly in some columns and fast in others. Training does not change it.

  • Rotary position embeddings, RoPE for short, add nothing to the token's embedding. They work inside attention. They take the numbers of each query and each key in pairs, and turn each pair, as a point in a plane, by an angle that grows with the position. The score of a query and a key then depends on the distance between the two positions.

microGPT has neither. It has the learned table wpewpe, as GPT-2 has.

The matrix xx has 16 rows and 16 columns, and the two 16s mean different things. The rows are the positions: blockSizeblockSize. The columns are the numbers of one embedding: nEmbdnEmbd. With a batch of two documents, xx would have 32 rows and still 16 columns.
