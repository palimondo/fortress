## 1. The Return Type Rule over every instance

The paper asks, for `d1` more specific than `d2`, that every instance of `d2` applicable to a type be matched by an instance of `d1` with a return type below it (`Papers/Types/rules.tick:174-180`), and checks it by the special arrow `∀[Δ1, Δ2] (S1 ∩ S2) → T2` (`Papers/Types/overloading-check.tick:166-172`). The base checked one instance: it solved the domain match once and substituted that solution into `d2`'s return type (`ProjectFortress/src/com/sun/fortress/scala_src/overloading/OverloadingOracle.scala:88-100` at `811053f15`), keeping only an unsolved size quantified (rung N's `escaped`, `:92-100`).

Candidates:
- (a) The paper's theorem as the team coded it, commented out in the file (`OverloadingOracle.scala:241-265`): every static parameter of `d2` kept quantified. Measured by probe P1 to refuse the compiler prelude's own `nest` overloads in every compiled program, 18 of `GenPlainRTR`'s 19 errors under it (`explorations/compile-ladder/plan-7b/probes/P1.md` section 3), because the checker's meet of two arrow types does not reduce through instantiation exclusion. Not buildable without a change to the shared meet, which this rung may not make.
- (b) The overloading judgement's construction (`explorations/reviews/overloading-judgement.md` section 3.5): a static parameter of `d2` is replaced by the solver's solution only where the constraint of the domain match, with the parameters' bounds, implies it equal to that solution; every other one stays `d2`'s own parameter in the special arrow, as rung N already kept a size. Measured by P1 to refuse `GenPlainRTR` and to keep the prelude and `GenPlainSub`.
- (c) The judgement's option 3, the two declarations' parameters identified by position. Not answer 9's rule for the Return Type Rule; it is the positional rule's reading (section 2).

Taken: (b), `forcedArgs` (`OverloadingOracle.scala:133-152`) and its use in `satisfiesReturnTypeRule` (`:83-127`). A parameter is forced when `Formula.implies(c, T = sol)` holds, `c` being the subtype constraint of `fd <: gd` with each parameter's upper bound; an unsolved size is never forced. Where the domain cannot be instantiated with inference variables at all, every parameter counts as forced, which is today's single solution; whether any program of the corpora or the library reaches that branch was not measured.

The paper's general form and this one (the POPL recheck's item 1.2, `explorations/reviews/decisions-review/popl-recheck.md` section 1.2): the POPL 2019 paper's existential reduction (section 4.2, p. 11:14) collects the constraints that keep the intersected domain off `Bottom`, solves them and compares the reduced domain, carrying bounds it cannot solve as constraints. This rung's reduction is its special case: it forces an equality only where the solver's constraint implies it, in practice through instantiation exclusion (`T -> SequentialGenerator[\G4\]` against `T -> Generator[\G1\]` forces `G1 = G4`). The paper's `ArrayList`/`List` set, which the recheck expected the narrower reduction to refuse, is accepted by this checker, before and after the edit; its three declarations all return `String`, so the Return Type Rule holds for every pair whatever the reduction, and which rule accepts the pair of the first two was not traced. The test is `ProjectFortress/compiler_tests/OverloadExistentialMeetLink.test` with `XXXOverloadExistentialMeet.test`.

A kept parameter's bound is read with the forced parameters' solutions (`kept`, `OverloadingOracle.scala:107-110`, through `StaticTypeReplacer.replaceStaticParam`, as `STypesUtil.fullyReplacedMethodDomain` reads a method's parameters under a replacer, `ProjectFortress/src/com/sun/fortress/scala_src/useful/STypesUtil.scala:1547-1550`). The first build kept each unforced parameter as declared, so a kept bound naming a forced parameter named a variable the extended analyzer did not hold: `g[\X, Y extends Box[\X\]\](x: Box[\X\], y: Y)` beside `g(x: Box[\ZZ32\], y: SubBox)`, which forces `X = ZZ32`, was refused with an internal error, "X is not in the kind env", a pair the Return Type Rule accepts (both return `String`) and the base compiled and ran. The base did not need the substitution: it substituted every parameter and kept only an unsolved size, whose bound names no other parameter. Found by the rung's skeptic (`SKEPTIC.md`, check 4) and repaired in its repair round (`JUDGE.md`, D1), gated by `ProjectFortress/compiler_tests/OverloadBoundNamesForced`. The special arrow's where clause stays `None`, as on the base.

Way back: `forcedArgs` returning `true` everywhere restores the base's rule.

## 2. The positional rule

Answer 9: two generic declarations in the more-specific relation agree on their static parameters position by position. Under Q4 = (1) the condition is the return type's, as the judgement words it; the domain condition (Java's, Q4 = (2)) is not built. Under the POPL recheck's item 1.3, taken at its default, it is a restriction of the compiled implementation, which hands a call's written static arguments to a dispatched declaration by position; the paper renames type parameters freely and would accept a reordering override.

Choices inside the rule, each the rung's:
- **Its scope: two declarations with as many static parameters of their own** (`satisfiesPositionalRule`, `OverloadingOracle.scala:161-175`; lifted parameters, a trait's, are not the declaration's own). The rule as first built applied to every pair where both declarations have static parameters of their own; on the whole of `compiler_tests` it refused the team's `Compiled12.invariantInference` and `invariantInference2`, whose declarations of one and of two static parameters are in the more-specific relation and are dispatched by run-time inference (REPORT.md section 6). The compiled dispatcher reads an arm at the template's static parameters only when the two have as many (`ProjectFortress/src/com/sun/fortress/compiler/OverloadSet.java:1342-1353`, the count at `:1345`), and a JVM override has as many as the method it overrides, so a pair of different counts is never handed each other's arguments. Candidates: every pair with static parameters on both (refuses the team's two tests, whose programs are right); the equal-count scope (taken).
- **Its kinds.** Two declarations of as many parameters whose kinds differ at a position are refused, since the dispatcher does not check an arm's kinds (`OverloadSet.java:1350` tests the template's only).
- **Its message and its place.** It is checked in `returnTypeCheck` after the Return Type Rule and only when that rule holds (`OverloadingChecker.scala:540-556`), so a pair the Return Type Rule refuses is not refused twice: P1's three positional refusals on the library (`Col`'s and `Row`'s `subarray`, `SimpleMappedIndexed`'s `map`) are pairs today's rule already refuses, and each keeps one error, class R3.

Way back: the `else if` at `OverloadingChecker.scala:552-556` removed.

## 3. The Meet Rule's closed-trait case (row 492's checker half)

Item 26's decision asks the checker to accept two overlapping declarations whose domains are neither below the other when visible concrete declarations, each strictly below both, together hold every value of the overlap (the proof addendum's Cover-Meet, `explorations/reviews/comprises-type-level-proof-addendum.md`, "One replacement premise").

The device (`coversOverlap`, `OverloadingOracle.scala:177-239`; called from `coverageRule`, `OverloadingChecker.scala:527-538`, after the Subtype, Meet and exclusion tests fail, `:475-479`): the overlap is a list of parts, one per argument position, each a list of conjuncts (at the start, the two domains' types at that position). A part is empty when two of its conjuncts are proven to exclude (`TypeAnalyzer.definitelyExcludes`); it is covered when its intersection type is a subtype of a covering declaration's domain (`TypeAnalyzer.lteq`); otherwise a conjunct that is a closed trait is cut by its clause, its static arguments substituted (`TypeAnalyzer.comprisesClause`), into one part per listed type. The covering declarations are those of the family, of the same self position, below both domains (`OverloadingChecker.scala:535-537`); incomparability of the pair makes each strictly below both. What it cannot settle is a refusal: a part with no closed trait left, a clause the helper cannot substitute whole, a part repeated on its own path (cycle detection), more than 1,000 cuts in one query, a varargs or keyword domain, and any declaration of the three with static parameters. The search is a work list, not a recursion.

Choices, each the rung's:
- **Where the helper lives.** In `OverloadingOracle.scala`, beside the overloading rules, not in `TypeAnalyzer.scala`, which the rung's section allowed for a helper the overloading check alone calls. So the shared type analyzer file is not in the diff at all: `subtype`, `meet`, `equivalent`, `normConjunct` and the normalizer are the base's, and the query has no caller outside the overloading check (REPORT.md section 5).
- **Its scope: functions and functional methods, ground declarations.** A functional method's self type (`TraitSelfType`, `S & {U, V}` in the checker's messages) is cut by its named trait's clause, its static arguments substituted as for a trait type (`listed`, `OverloadingOracle.scala:206-217`); a value of it is a value of the named trait, so the cut's parts hold every value of the overlap. The first build read only a trait type, so a functional method declared in the closed traits themselves and in the type both clauses list was refused, which walk runs; the repair round added the case (`JUDGE.md`, D4, a decision of the judge's under the rung's section, against narrowing the claim), gated by `ComprisesMeetFunctionalMethod` (`tag(s) = 3`) and its control `XXXComprisesMeetFunctionalMethodUncovered`. For functional methods, coverage is judged in each trait or object that provides the two declarations, over the declarations that type provides, as the Meet Rule for functional methods is worded (`Specification/advanced/overloading.tex:396-411` at `811053f15`; `coverageRule`, `ProjectFortress/src/com/sun/fortress/scala_src/typechecker/OverloadingChecker.scala:527-538`): so a trait between the two closed traits that provides both and declares no covering method is refused, "Invalid overloading of choose in trait M" (the second skeptic's `SkFnBetween`, which walk runs), though the functions' form of the same family (`CoverageReturnGood`) is accepted. Dotted methods (`isMethod` with no self position) and families with static parameters get no coverage and are refused as today. The Meet Rule for dotted methods asks for a declaration provided by the one trait or object with a receiver below both (`Specification/advanced/overloading.tex:344-356`), and a generic family's coverage would need the instantiation argument the addendum leaves to later work ("Source and scope").
- **Its bound.** Cycle detection on the path, as the addendum asks, and a cap of 1,000 cuts whose excess is a refusal, so that no clause shape can make the query run long; neither the library nor the corpora reach the cap (no new refusal on the count or distance stage).

Candidates not taken: widening `normConjunct`'s one-clause case to the two-clause distribution (the judgement's way 2 as a normalizer change), which the rung's section forbids since subtype, meet and equivalent share it; an exact type-level meet `S ∩ T = V`, which is the nominal identity the addendum says the coverage judgement does not assert.

What it assumes and does not repair: row 487, the closure of closed traits across components (`TypeHierarchyChecker.everyKnownSubtypeListed` sees only the trait table it has). The coverage argument holds where closed families are closed; the rung claims no more than its tests show.

Way back: `validOverloadingInner`'s last line restored to `else { oa.excludes(fa, ga) }`.

## 4. The type of a call that sits between two closed traits

Item 26's decision types such a call by the intersection of its candidates' return types. Built in `typedApplication` (`Functionals.scala:632-794`), which `checkApplication` now wraps: the call's type is the most specific candidate's return type, or, for a tie among candidates that fit without coercion, without promotion and without written static arguments, whose parameter types are not all equivalent, in a family none of whose declarations has static parameters, the meet of the tied candidates' return types (`tieType`, `:686-691`). The type reaches the expression's type at the four sites that typed a call by the head's return type (a subscript, a method invocation, a function application and an operator application, `:931`, `:967`, `:1055`, `:1117`; four on the base, `Functionals.scala:889`, `:925`, `:1013`, `:1075` at `811053f15`), and each attempt's expected-type check (`kept`, `:694-695`).

Choices, each the rung's:
- **The scope: a family without static parameters**, not only tied candidates without them. Astra's boundary (POSITIONS 2026-09-29, PLAN item 26): the addendum's proof justifies the intersection for ground declarations, the more specific ones that may run included, and not for a generic declaration needing a run-time instantiation, where one instantiation must meet every static promise at once. The scope taken is narrower than that boundary, which excludes only generic declarations that may run: a generic declaration that cannot apply to the argument, such as `choose[\X\](b: Box[\X\])` with `object Box[\X\]` beside a call on an `M`, also keeps the call at the head of a sort, whose choice follows declaration order and varies from run to run (`XXXCoverageReturnGenericFamily`, row 543). A generic argument type already instantiated, `G[\ZZ32\]`, is ground, and `ComprisesBetweenTwoClosed` is typed by the rule. The rung's skeptic measured the narrowing (`SKEPTIC.md`, D6), and its judge decided it (`JUDGE.md`, D6) between two candidates: (1) narrow the condition to the declarations that may run, every declaration whose existential domain does not provably exclude the argument's static type required ground (`OverloadingOracle.excludes`), which sends the intersection type into more ties, the library's among them, while code generation crashes on a method call on that type (row 540), and rests on one more exclusion judgement per call; (2) keep the scope, gate the shape and put the narrowing to Pavol. Taken: (2). The typing kept is sound, since what runs is below the head and so returns a subtype of the head's return type by the Return Type Rule.
- **Coercion.** A tie with a coercion the call needs, or a promoted candidate, keeps batch N's rules (the numeral tie, the same-types tie, the signalled ambiguity); coverage never chooses between conversions. Rung I's tie tests keep their verdicts (REPORT.md section 6).
- **The Return Type Rule is a premise.** `CoverageReturnBad`'s family is refused on the Return Type Rule (`choose(v: V): LeftResult` against `choose(t: T): RightResult`), whatever its coverage.

Candidates not taken: today's head of a sort, which depends on the order the declarations are written in and, measured on the base, flips between the compile and the link of one program in one JVM (REPORT.md section 4); the tied candidates alone required ground (outside Astra's boundary).

Way back: the four sites' `callType` replaced by `bestArrow.getRange` and `kept` by the sort's head.

## 5. The Return Type Rule on an object domain (for Pavol)

The paper's Return Type Rule quantifies over the types not equivalent to `Bottom` to which the more specific declaration applies (`Papers/Types/rules.tick:174-180`), and its theorem sets aside the instances of the special arrow whose domain is `Bottom` (`Papers/Types/overloading-check.tick:176-178`). An object trait type excludes any type that is not its supertype (`Specification/basic/types-vals-vars.tex:255-258`), so below `Circle` in `ident[\T\](x: T): T` beside `ident(x: Circle): Circle`, with `object Circle`, there is only `Circle`, and every instance of the generic declaration applicable to it returns a supertype of `Circle`: the paper accepts the pair. The construction of section 1 keeps `T` quantified in the special arrow and checks instances whose domain meet `Circle ∩ T` is `Bottom` (`T = Square`), so it refuses the pair, and with it `f[\T\](x: T): T` beside `f[\U\](x: Box[\U\]): Box[\U\]` with `object Box[\U\]`. On the base both compiled and the run failed verification, `VerifyError: Bad return type`, so a valid program moved from a run-time crash to a compile-time refusal. Found by the rung's skeptic (`SKEPTIC.md`, D5) and gated as an expected failure, `XXXOverloadReturnObjectDomain` (row 542). Not changed here: the construction is the one answer 9 adopted ("Agreed, the judgement's recommendation"), and setting aside the instances whose domain meet is `Bottom` is a type-theoretic change to a decided rule (`JUDGE.md`, D5). The candidates for Pavol: keep the refusal, as now; or refine `satisfiesReturnTypeRule` to set such instances aside, for batch 8 or later.

## 6. The 2019 proof and what rests on the 2011 rules (the POPL recheck's item 1.4, a default)
