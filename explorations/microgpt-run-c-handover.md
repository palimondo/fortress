## The APL side quest, where it stands and how it closes

Goal as Pavol set it: convert APL syntax into efficient Fortress code over Fortress's native arrays, not an interpreter of APL in Fortress. The design and the ladder are in `explorations/apl/README.md`; the base is `explorations/apl/base/` (`AplCore.fss/.fsi` the library, `AplSyntax.fsi` the grammar). Rung 7 (tacit) is skipped by decision: the programs have one tacit line, rewritten. Rung 8 (nested arrays) is not built; strands of arrays became Fortress tuples in rung 5.

Mechanisms established, all in `explorations/apl/gaps.md` (85 rows, not yet in the main ledger): glyphs as host operators where the operator table allows; templates expand to host code; rank in the type with overload families over `RR64`/`Vector`/`Matrix`/`Array3`; rank read off the source text for `⍴ ⌷ ↑ ↓ ⍉`; a glyph handed to an operator is a zero-parameter host lambda over a frame stack (`aplCall`, `aplAlpha()`, `aplOmega()`, `aplSelf()`), the only form that survives nested dfns; guards as `if … then … else rest end`; `⍤1 ⍤2 ⍤0 1` over row and plane views with the result rank chosen by overloading on the first cell's result (`aplAsm1/2`, result type `Object`); `+.×` is the shipped `DOT`; outer products direct for the common glyphs; `¨` over simple arrays and over tuples; destructuring `a b c ← e` as a lambda over a tuple; `\ ⍀ ⍣` and general `f/`. APL names are a closed set in the grammar, one line per name, three sets (arrays, functions, tuple members); a word of two or more capitals cannot be a name.
