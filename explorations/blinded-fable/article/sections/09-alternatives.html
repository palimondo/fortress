9. Alternatives explored, and why this form

Three complete, verified programs were written before choosing; each passes the same 52 checks against the reference. They differ in how vectors are typed, how the matrix–vector product is written, and whether the model carries state.

The array design (v1) is closest to Fortress's own library idiom — sizes in types, indices under the ∑ — and its formulas typeset well, but the interpreter does not accept the abbreviated Value[n] types, so every signature spells Indexed⟦Value,ℤ32⟧ or Array2⟦Value,0,m,0,n⟧, and its attention had to be written per component because a sliced array is no longer a sized array. Moving to Vec/Mat (v2) is what made softmax(K q/√d) V expressible. Turning the token loop into a sequence function (v3) removed the mutable cache and made positions independent iterations; it also shortened the loss to a single call. The remaining visible seams in v3 are: Mat(⟨ W_q x | x ← X ⟩) where a paper writes XWq⊤ (a matrix–matrix product was not needed anywhere else, so none was defined); .cols(c) for head selection; the parenthesized (headsh)[t] forced by the interpreter bug; and the BIG ‖ spelling of head concatenation.

Autograd representations

Pairs (chosen), parallel lists (Python's shape) and closures (micrograd's original) are compared in section 2; all three run. The pairs form is the only one whose operator definitions carry no static-argument annotations.

One ∑ for scalars and vectors

A single reduction over an Additive trait with an explicit Zero lets the same ∑ sum Values and Vecs, so the head output could be written ∑t αt vt instead of alpha V. It runs correctly (the interpreter checks types at run time), but the static result type is Additive; the specification's overloading rules leave no way to give the nullary ∑ a result type that depends on the body. This is the one place where a genuinely nicer notation was declined for typing honesty.

What “canonical” means here

The chosen form is canonical in the sense that every operation of the model is written with the operator or big operator the mathematics uses, on types that name the mathematical object (Value, Vec, Mat), with no annotations in the model's definitions, and that the same definitions execute and reproduce the reference bit-for-bit up to summation order. It is not unique: the array form is equally correct and arguably more idiomatic for Fortress's numeric library; it was set aside because of interpreter gaps, not because of the language.
