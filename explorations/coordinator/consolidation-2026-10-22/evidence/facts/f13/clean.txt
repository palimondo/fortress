- F-143 **Under walk, a type parameter whose bound mentions itself and that nothing at a call fixes is left open.** Such a bound is an F-bound, as in `mk[\T extends Cmp[\T\]\]()`. The open type is below every type, and every value matches it. A reduction or a comprehension that writes no static argument is first instantiated by its declared type or by its elements' join (F-228). So the open parameter reaches one only where neither fixes it, as in an empty reduction that no declared type directs, which takes `ZZ32`'s identity (row 716). A call such as `mk()` also leaves it open. A tuple, arrow or generic type that holds the open type admits no more than it would at `BottomType`, so `(Int, Int)` is not below `(OPEN, OPEN)` (row 663, contested). In a skeptic's probe, a declaration whose parameter type is the open type was the most specific one, and so was chosen for every argument; no gated test holds this. Gated by `tests/InferUnfixedFBoundedWalk.fss` and `OpenTupleDispatchWalk.fss`. Detail: `compile-ladder/rung-walk-open-param/REPORT.md` sections 1 and 11; its `SKEPTIC.md` section 3, finding 3 (the probe).
- F-144 **The identity-less reductions are typed at their element type: `AssociativeReduction[\R\]` lifts to `Maybe[\R\]`, and its `simpleJoin` and every `lift` take `R`.** A reduction that extends `AssociativeReduction` declares `simpleJoin` at its element type; walk refuses one at `Any` at load. One with static parameters escapes that check and stops at its first join (row 665). A static argument that names the lifted type is `Maybe[\R\]`, since walk refuses `AnyMaybe` there. With the element type unwritten, `BIG MINMAX` and the four tuple forms run under walk. A plain-bounded monoid operator with no static argument is instantiated as F-228 says: in one measurement each, `BIG SQCUP`, `BIG SQCAP` and `List`'s nested `BIG CONCAT` ran; `PrefixSet`'s `BIG UNION` and `PureList`'s `BIG CONCAT` were not measured, and no gated test holds any of them. Gated by `tests/Unwritten*Walk.fss` and `ReductionSimpleJoinAtAnyWalk` (the refusal at `Any`). Detail: `compile-ladder/rung-reduction-types/REPORT.md` section 1; `compile-ladder/rung-walk-elements/REPORT.md` section 7 (the operators that ran).
- F-145 **Walk refuses at load an object that leaves an inherited abstract method uncovered.** Bodies at narrower parameter types define an abstract method only where together they cover its parameter types, with `comprises` clauses read, as P-147 decides: each position is split through the clauses, and every combination of parts must lie inside one body. A search that does not settle refuses the object: a cycle, a symbolic or unreadable type, 10,000 steps or 4,096 combinations. A generic object is not checked (row 665), and an object whose one covering definition has a static parameter of its own is refused (row 728). The compiled checker covers the same way, within the same bounds, except where a method has static parameters of its own (row 725). Walk's other checks at load of an object are the `override` check (F-147) and the Meet Rule for Functional Methods (F-142). Gated by `tests/AbstractMethod*Walk` (`AbstractMethodCoverUnsettledWalk` among them) and `compiler_tests/AbstractMethodCoveredPairs`. - F-147 **Walk refuses an `override` that overrides nothing; an inherited declaration is overridden only where each of its parameter types is a subtype of the `override`'s and not all are equal.** This is the traits chapter's "strict subtype" (`Specification/basic/traits.tex:585-589`). Walk checks the `override` of a trait, object or object expression with static parameters once, at its declaration. An object inherits nothing that a trait's `override` overrides, so an abstract `override` leaves it without a body (rows 614, 649). Walk does not read all the bounds of the static parameters in an object expression, which takes them from the function around it, or in a generic trait or object that extends a type under a `where` clause. There it accepts an `override` over an inherited declaration whose parameter types mention a static parameter and differ from the `override`'s (row 693). The `fortress-repo` skill gives the rule's other cases (`references/interpreter.md`, "What walk checks"). Gated by `tests/Override*Walk.fss` and `AbstractOverrideUndefinedWalk`. Detail: `compile-ladder/rung-walk-override/REPORT.md` section 1.
- F-228 **Under walk, a reduction or a comprehension that writes no static argument instantiates its big operator by a declared type, else by the join of its elements' run-time types, else at its bound, where an F-bounded parameter stays open.** It builds P-48. The declared type is a local variable's, or a top-level or local function's declared return type, also where the clause form ends a block. A method's return type, a top-level variable, a field, an assignment, a function expression, a branch, a call's argument and another clause form's body do not direct it. Otherwise the clauses run once into the library's collector, and the operator is instantiated at the elements' join; the reduction then runs over the collected elements, so each body runs once. With no element and no declared type, a plain-bounded static parameter takes its bound, and an F-bounded one stays open (F-143). A big operator whose declared result is a trait of its own is read through the `BigReduction`, `Comprehension` or `BigOperator` that the trait extends. So `__bigOperator`'s `body(i: I)` is typed. Left open: an empty clause form that no declared type directs (row 716), a comprehension that no declared type reaches (rows 20 and 717), and an argument of a call (rows 510 and 705). Gated by `tests/UnwrittenListMapComprehensionWalk`, `UnwrittenComprehension*Walk`, `ComprehensionTypedBindingWalk`, `UnwrittenSetBigOperatorsWalk`, `UnwrittenEmptyFloatSumWalk`, `IntMapComprehensionTypedWalk` and `UserBigOperatorResultTraitWalk`. Detail: `compile-ladder/rung-walk-elements/REPORT.md` sections 1 and 5 (5.3 lists the contexts); `compile-ladder/rung-walk-overload-if/REPORT.md` section 1, "Row 718".
- F-238 **Under walk's load check, an exclusion that two generic declarations show only at one shared symbolic instantiation is withdrawn where their instances do not exclude.** Walk reads two generic functions of one name and one list of static parameters at one shared symbolic instantiation, and two instances of one generic object as two object types, which exclude. So `o[\T\](x: P[\T\])` beside `o[\T\](x: Q[\T\])`, with `trait P[\T\] excludes { Q[\T\] }`, excludes at one `T`, though a type that extends `P[\ZZ32\]` and `Q[\String\]` has both. A pair whose exclusion is withdrawn goes on to the reading on declared domains (F-252), and a refusal there names the rule that the pair breaks (F-257). Gated by `tests/GenericBoundsNoMeetWalk`, `NoDuplicatesRuleWalk`, `NoDuplicatesRuleSizeWalk`, `GenericOverloadInstancesApartWalk` (refused), `GenericBoundsMeetWalk`, `GenericFBoundsMeetWalk`, `GenericPairExcludingWalk`, `GenericSizePairNestedWalk`, `ShuffleTest` and `GenericPairExcludesTogetherWalk` (load). Detail: `compile-ladder/rung-walk-overload-if/REPORT.md` section 1, "Row 373", and section 9.

- F-248 **Under walk, the library's generic `distribute[\K\]` keeps every fused answer of a nested reduction, and a nested reduction without a fused pair runs.** A nested reduction is fused where the outer reduction distributes over the inner one, so the library takes a faster path. The library declares the team's generic, `distribute[\K\](r: ActualReduction[\R,K\]): PossibleReductionPair[\K\]`, with no method over `Any` beside it. `GeneratorDeclarations` and microGPT's quick pair keep their answers, and `MAX` and `MIN` over `SUM`, and `SUM` over `PROD`, still take the fused path. The team's commented line in `Generator2.distributes`, the explicit `r.distribute[\L1\](q)`, would stop every fused pair under walk (row 744); the library does not run it. Gated by `tests/GeneratorDeclarations` and `NestedReductionFusion`. Detail: `perf-probes/generic-distribute/REPORT.md` sections 1 and 5.
