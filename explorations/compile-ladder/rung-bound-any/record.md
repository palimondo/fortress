## Revival change

**The change.**
- The team's source, the compiled path: `Shell.useCompilerLibraries()`, which `compile`, `link`, `build` and `typecheck` call, opened with `setExtendsObjectPreDesugaring(true)` (`ProjectFortress/src/com/sun/fortress/Shell.java:372` at `a874948ac`; Steele, 2012, `91e71e62e`, `c61723f61`, `afb02f41d`). So `PreDisambiguationDesugaringVisitor.forStaticParam` wrote `extends Object` into every empty `extends` clause of a program's own declarations, sizes included (`ProjectFortress/src/com/sun/fortress/compiler/desugarer/PreDisambiguationDesugaringVisitor.java:194-208`). Walk turned it off (`Shell.java:380`). The team's tests pinned it: `ProjectFortress/compiler_tests/XXX6bu.test:16` and `XXX6bv.test:16` printed `[\T extends Object\]`, and `ProjectFortress/tests/doubledOverloading.fss` declared `a[\E\](v: E)` beside `a(): ()`, which only the bound `Object` keeps apart. The Working Draft of February 2011 said `extends Object` (`Specification-1.0-frozen/basic/trait-parameters.tex:49-50`).
- What the tree now does: the compile command reads a type parameter declared without a bound as bounded by `Any`, as walk does.
  - `object Seal[\X\] end` takes `Seal[\Any\]`, and the program links and runs (`compiler_tests/ImplicitBoundAny`).
  - A generic object at a pair links and runs, and `m: Maybe[\()\] = nothingAt()` compiles and runs.
  - `q = id((3, 4))` then `q + 1` is refused, '(ZZ32, ZZ32)->ZZ32 is not applicable to an argument of type ((IntLiteral, IntLiteral), IntLiteral).'; under the bound `Object` it compiled and ran `id(3)`.
  - The team's `doubledOverloading.fss` now writes `a[\E extends Object\]` and `b[\F extends Object\]`. As the team wrote it, it is refused, 'For a, the return type of ()->() ... should be a subtype of the return type of [\E\]E->A[\E\]'.
  - Until the switch-over, a generic that concatenates such a value onto a `String` writes `T extends Object`, since the compiler's prelude declares `abstract opr || (self, b:Object): String` (`ProjectFortress/LibraryBuiltin/CompilerBuiltin.fsi:37`); otherwise '(String, Object)->String is not applicable to an argument of type (String, T).' (`compiler_tests/CoercionGenericFnCompiledRungC.fss:20-21`).
- The reason:
  - The specification's rule: "If a type parameter does not have an extends clause, it has an implicit "extends Any" clause" (`Specification/basic/trait-parameters.tex:52-53`). Its section also says "Type parameters are instantiated with types such as trait types, tuple types, and arrow types" (`:67`), which the bound `Object` refused: 'The static argument Any does not satisfy the corresponding bound Object.'
  - The type group's paper of 2019: "By default, each type parameter has an upper bound Any" (`research/extracts/ParkPOPL2019.txt:418`).
  - Under the bound `Object`, the compile command miscompiled `id((3, 4))` as `id(3)`, printing 'q + 1 =  4'.
