5.1 The feed-forward block

60 60 60 60 
60x3 = rows(rmsn, x2)60m0 = x3 f1^T60mr = 0.0 MAX m060x4 = x2 + mr f2^T
60x3 = rows(rmsn, x2)60m0 = x3 f1^T60mr = 0.0 MAX m060x4 = x2 + mr f2^T

These four declarations are the rest of line 60. They form the model's second block, the feed-forward block. Its other name in the field is MLP, short for multi-layer perceptron, and the files of its two matrices are named mlp_fc1 and mlp_fc2, where FC is short for fully connected. The block starts from x2x2, the matrix of Part 4: each row as it was before attention, plus attention's result.

  • x3x3 is x2x2 with rmsnrmsn, the function of Part 3 that brings a row to a standard size, on every row. It is the third and last use of rmsnrmsn in the forward pass.

  • m0m0 puts every row of x3x3 through f1f1, the block's first weight matrix, 64 by 16. Each row of 16 numbers becomes a row of 64 numbers.

  • mrmr replaces every negative number of m0m0 by 0. MAXMAX is the operator that gives the larger of two values. Between a number and an array, the library applies it to every element. The field's name for this step is ReLU, short for rectified linear unit, and the rr of mrmr stands for it.

  • x4x4 puts every row of mrmr through f2f2, the block's second weight matrix, 16 by 64, which brings it back to 16 numbers. Then it adds the result to x2x2. This is the second residual connection: the block's result is added to the block's input.

A run printed the sizes, how many of the 1,024 numbers of m0m0 are positive, and the first six numbers of row 1 before and after MAXMAX:

sizes x2 (16,16) m0 (16,64) mr (16,64) x4 (16,16)
m0 positive count 466 of 1024
m0[1,0..5] = 0.4039325142253399 -0.5951570653200444 0.0782116940127397 -0.13886643064580534 0.16013754453254497 0.01747112558184824
mr[1,0..5] = 0.4039325142253399 0.0 0.0782116940127397 0.0 0.16013754453254497 0.01747112558184824

The step from m0m0 to mrmr is small, and the block needs it. Without it, the block would be x3 f1T f2Tx3 f1^T f2^T. A product of two matrices is one matrix, so the two weight matrices together could do nothing that a single matrix of 16 by 16 cannot do. With MAXMAX between them, which of the 64 numbers pass depends on the row. A different row has a different set of numbers set to 0, and f2f2 then mixes a different set.

The two blocks have different jobs. Attention moves numbers between positions. The feed-forward block works on each position alone, on what attention brought to it.

5.2 From a row to 27 probabilities

61 
61pr = rows(sm, x4 lm^T)
61pr = rows(sm, x4 lm^T)

x4 lmTx4 lm^T puts every row of x4x4 through lmlm, the language model's head: the last weight matrix, 27 by 16. Each position now has 27 numbers, one for each token. They are scores: any size, any sign. The field's name for them is logits, and the output below prints them under that name.

rows(sm, …)rows(sm, ...) turns each row of scores into probabilities, with the softmax of Part 3. prpr, the probabilities, is a matrix of 16 by 27. Its element in row rr and column tt is the model's probability that the token tt comes next after position rr. This matrix is the model's answer.

5.3 The loss

61 
61loss = -(vm DOT log(pick(pr, tg))) / nv
61loss = -(vm · log(pick(pr, tg))) / nv

The loss is one number that says how wrong prpr is. Read the line from the inside out.

tgtg is the vector of the targets from Part 1: for each row, the token that comes next. pick(pr, tg)pick(pr, tg) takes from each row of prpr one element: the one in the column that tgtg names for that row. That is the probability that the model gave to the right answer. pickpick is a function of FlatArrays.fss:

loglog is the natural logarithm, the reverse of expexp, the exponential function of Part 3: log(exp(t))log(exp(t)) is tt. The logarithm of 1 is 0. The logarithm of a number between 0 and 1 is negative, and the smaller the number, the further below 0. FlatArrays.fss declares loglog for arrays, element by element. The run printed the logarithms with the sign changed:

So each row gets a penalty: minus the logarithm of the probability that it gave to the right answer. A probability of 1 gives the penalty 0. A probability of one half gives 0.69. The 0.0266 for y gives 3.63.

vm · …vm DOT ...vm · ... is the dot product with vmvm, the vector from Part 1 that holds 1.0 for a row that counts and 0.0 for the others. It adds the values of the seven rows that count and leaves the other nine out:

  • 3.628 plus 3.215 plus 3.561 plus 3.542 plus 3.074 plus 3.238 plus 3.304 is 23.562.

The minus sign in front makes the sum positive, and / nv/ nv divides it by nvnv, the number of rows that count, 7:

loss = 3.365966947584851   log 27 = 3.295836866004329

  • r runs over the 16 rows.

  • prr,,tgr is the element of prpr in row r and in the column tgrtg[r]: the vector pick(pr, tg)pick(pr, tg).

  • vmr is 1 for a row that counts and 0 for the others.

  • The sum over r of a product is the dot product, ·DOT·.

The loss is the mean penalty of the rows that count. The field's name for this loss is cross-entropy.

The second number of the output is a value to compare the loss with. A model that gives each of the 27 tokens the same probability has the penalty log(27)log(27) in every row, 3.296. The untrained model starts at 3.366, a little worse than equal probabilities. A model that gave every right answer the probability 1 would have the loss 0. A run of Karpathy's program over 1,000 steps had losses between 2.26 and 2.65 at steps 200 to 1,000, each on a different name.

5.4 The forward pass on one page

Lines 57 to 61 are the whole forward pass: five lines. The figure leaves out one step, the cut of qq, kk and vv into heads. Each stage is a matrix with one row for each position, except aa, which has one plane for each head, and the loss, which is one number.
