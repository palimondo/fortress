# Concepts for chunk c2

Chunk c1's `concepts.md` already lists the switch-over, the distance to the switch-over, the compiler's prelude, the compiled checker, the Working Draft, the Types chapter of the team's 2012 restart and "row N". This chunk uses them too: P-33, P-42, P-58, P-59, P-84, P-85 and P-155. Only the concepts below are new.

- **native binding**: a library body that is exactly `builtinPrimitive("…")`, whose string names the Java code that runs it. Used by P-33, P-58. P-58 defines it; the `fortress-repo` core should name it in one line beside "one library", since phase 4 starts with it.
- **glue class**: a Java class of walk that a native binding names; it takes walk's boxed values. Used by P-58 (and F-32). Define in the `fortress-repo` area part on the interpreter.
- **static helper**: a static Java method in `ProjectFortress/src/com/sun/fortress/nativeHelpers/`, over plain Java values, that the compiled path calls for a native. Used by P-58. Define in the area part on the code generator.
- **the class loader's stamping**: the compiled path's way of making a generic instance's class at its first use, by renaming the template's type parameters in its bytecode (`InstantiatingClassloader`). Used by P-84 (and F-18). The `fortress-repo` core's "The compiled run time" gives the mechanism; it should use the word "stamping" once, since the record uses it.
- **the array decisions A, B and D**: the open decisions of the compiled path's array design: A, how an `RR64` array made through the generic array traits gets a `double[]` store; B, where unboxed arithmetic happens; D, the sizes in the model's own types. Used by P-84, P-85. P-85 defines them; no skill needs them before the array work.
- **way A4**: the way for decision A in which the class loader stamps an `RR64` instance with a `double[]` field. Used by P-84 (and F-18). Defined in `reviews/array-design-ways.md`, section 3; P-84 glosses it, so no skill needs it.
- **the extends-`Object` setting**: the pre-desugaring switch that gives an unbounded type parameter the bound `Object`, on under `fortress compile` (`Shell.useCompilerLibraries()`) and off under walk and the distance stage. Used by P-42 (and F-289). Define in the `fortress-repo` area part on the compiler, where `compiler.md` now says that the switch-over ends it.
- **the distance and the checker count**: two different measures of the compiled checker. The distance counts its errors over the apis and components of the interpreter's library that its stage checks; the checker count checks only the `FortressLibrary` component and the apis it imports (F-53). Used by P-33, P-155. Define both in the `fortress-repo` core, beside the switch-over, and tell them apart: the cold reader mixed them up. The core's "The compiled checker already finds no error in the interpreter's library" (`SKILL.md:79`) should name what the distance counts.
- **rung**: one step of a climb batch: one change with its tests, gated with the batch. Used by P-155 (and P-59's test names). Define in the `fortress-repo` core, beside "gate"; no part defines it today.
- **the coercions that the checker inserts**: the `CoercionInvocation` nodes that the compiled checker puts into the syntax tree; walk has no case for them (F-9). Used by P-59 (and P-12). Chunk c1's `concepts.md` lists `CoercionInvocation` for the interpreter part; define it there, beside `interpreter.md`'s line on coercion.
- **the overloading check and the export check**: two separate checks of the compiled checker. The overloading check tests that the overloads of one name are valid; the export check compares a component's declarations with its api's. Since row 584 was fixed, the overloading check reads the symbolic operators; the export check still skips the top-level ones (row 782). Used by P-155. Define both in the area part on the checker, so that "the check" in a record entry can be told apart.

Added by the judge, from the second cold read:

- **the library's generic array traits**: the array types of the interpreter's library that are generic in their element type, such as `Vector[\T, nat s0\]`, whose default object `__DefaultVector` keeps its elements in `mem: PrimitiveArray[\T,s0\]` (`Library/FortressLibrary.fss:2534`, `:2557-2558`; `reviews/array-design-ways.md`, section 3). Decision A asks how an instance at `RR64` gets a `double[]` store while other element types keep a boxed one. Used by P-84, P-85. Define in the `fortress-repo` part on the library, beside its arrays.
- **decision C**: the array design's fork on which library the array layer goes into, the compiler's or the interpreter's (`reviews/array-design-review.md`, section 3, "Decision C"). The one-library decision (P-37) answers it, so the open array decisions are A, B and D. Used by P-84 and P-85, which name A, B and D and not C. Define it beside "the array decisions A, B and D", above.
- **the library's two subscript operators**: the two subscripts that `Indexed[\E, I\]` declares, `opr [i: I]: E` for one index and `opr [r: Range[\I\]]` for a range of indices. The team's appendix of proposed features calls the pair "not really a valid overloading" (`Specification/appendices/future.tex:186-207`). Used by P-155 and P-156. Define in the `fortress-repo` part on the library, beside "Fortress as a language"'s word on `[i]`.
- **the subscripts' index bound**: `I extends Index`, the bound on every index parameter of the library's generic indexed types, which makes the pair above a valid overloading, since `Range` excludes `Index` (P-156). Used by P-155. P-156 defines it; the library part should name it with the subscripts.
