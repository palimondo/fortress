Part 4 Attention

The one place where a position reads other positions. Every position makes a query, a key and a value; a query scores every key; softmax turns the scores into attention weights; these mix the values. With one real row of attention weights.

4.1 What attention is for

After the first forward line, row 4 of the matrix xx holds the embedding of the token e plus the embedding of position 4. It holds nothing about the tokens before it. To say what follows yuhe, the row needs to know about y, u and h too.

Almost every line of the forward pass treats each row by itself. A product of the form x wTx w^T puts every row through the same matrix, and rowsrows, the function of FlatArrays.fss from Part 3, applies a function to every row. No number moves from one row to another.

Attention is the exception. In it, each position computes an average of vectors from the positions up to and including its own, and adds the average to its own row. Position ii reads position jj when a vector of position jj enters the average of position ii.

The average is weighted: each position that is read counts with a number between 0 and 1, and these numbers add up to 1. Such a number is an attention weight. The word is close to "weight matrix" and means a different thing. A weight matrix holds parameters, which only training changes. The attention weights are computed anew in every forward pass, from the rows themselves. The computation has four steps:

  1. Three products make a query, a key and a value for every position.

  2. A product of queries and keys gives scores.

  3. smsm, the softmax of Part 3, turns the scores into attention weights.

  4. A product of attention weights and values gives the averages.

4.2 Query, key and value

58 
58(q, k, v) = (x1 wq^T, x1 wk^T, x1 wv^T)
58(q, k, v) = (x1 wq^T, x1 wk^T, x1 wv^T)

The line binds three names to three products. x1x1 is the matrix of Part 3: the summed embeddings after two calls of rmsnrmsn. wqwq, wkwk and wvwv are attention's weight matrices for the query, the key and the value, three of the nine views of Part 2. Each product puts every row of x1x1 through one of them. So qq, the queries, kk, the keys, and vv, the values, are matrices of 16 by 16, with one row for each position.

  • Row ii of qq is the query of position ii. The model uses it when position ii reads.

  • Row jj of kk is the key of position jj. The model uses it when another position decides how much to read from position jj. This key is a vector of floats. It has nothing to do with the keys of Part 1, the integers that look rows up in a table.

  • Row jj of vv is the value of position jj. It is what position jj gives when it is read.

The score that position ii gives to position jj is the dot product of query ii and key jj. A dot product is large when the two vectors have large elements with the same signs in the same places, and it is negative when the signs disagree. So a high score means: this query and that key fit.

The words query, key and value describe the parts' places in the computation. They say nothing about what the numbers mean. The three matrices wqwq, wkwk and wvwv start as random numbers. What a high score between two positions is good for is decided only by training.

4.3 Four heads

The model does not use the 16 numbers of a query as one vector. It cuts every query, key and value into four pieces of four numbers: columns 0 to 3, columns 4 to 7, columns 8 to 11, columns 12 to 15. Piece number 0 of the queries works only with piece number 0 of the keys and of the values, and so on. Each of the four is called a head. A head is a complete attention computation on vectors of four numbers. The constants of line 17 say so: nHeadnHead, the number of heads, is 4, and headDimheadDim, the number of columns of a head, is 4.

One head gives each position one set of attention weights. Four heads give it four, so the model can read the earlier positions in four ways at once.

  • hh, short for heads, takes a matrix and returns an array with three indices. The program's comments call such an array a rank-3 array. A limit of today's tree

The library declares products for vectors and matrices only. A product of rank-3 arrays, plane with plane, is what this model needs, so FlatArrays.fss writes it as a loop over the planes. By your ruling, what a program builds that a fuller library would hold belongs in the library; this operator has not moved there.

In each plane, a matrix of 16 by 4 meets a matrix of 4 by 16, and the result is 16 by 16. Take its element in row ii and column jj. By the rule of Part 2, it is row ii of the plane of qhqh with row jj of the plane of khkh. That is the dot product of query ii and key jj. So plane 0 of qh khTqh kh^T holds every score of head 0: 16 positions that read, times 16 positions that can be read.

/ √ 1.0 headDim/ SQRT (1.0 headDim)/ √ (1.0 headDim) divides every score by 2, the square root of 4. By the usual account, a dot product of longer vectors adds more terms and grows, and the division keeps the scores in the same range for any headDimheadDim. The range matters because larger differences between scores make the result of softmax more uneven, as Part 3 showed. 1.0 headDim1.0 headDim is the float 4.0. Walk also accepts √ headDimSQRT headDim√ headDim and prints 2.0 for it; the line writes the conversion out.

4.5 The mask: no reading ahead

Position 3 has scores for all 16 positions, also for positions 4 to 15. It must not read those. The model's task at position 3 is to say which token stands at position 4. If position 3 could read position 4, it would read the answer.

29 
29mask: Array[\RR64,(ZZ32,ZZ32)\] = mat(blockSize, blockSize, fn (i: ZZ32, j: ZZ32): RR64 => if j > i then -(10.0^10) else 0.0 end)

maskmask is a top-level variable: a matrix of 16 by 16, built once when the component is loaded. matmat is a function of FlatArrays.fss that makes a matrix from its two sizes and a function of the index. The function here returns minus 10 to the power 10 where the column jj is greater than the row ii, and 0 elsewhere. A run printed the matrix's top left corner:

In line 59, mask + …mask + ... adds this matrix to every plane of the scores. Lines 135 and 136 of FlatArrays.fss declare ++ between a matrix and a rank-3 array. After the addition, row 3 of head 0 starts with the four scores as they were, and every later score is near minus 10 to the power 10:

masked[0,3,:] = -0.08175008584960282 0.10605658054206196 -0.13388403927731538 0.07289125011412394 -1.0000000000003387E10 -1.0000000000034449E10

Part 3 showed what softmax does with such a score: its result for that score is 0, exactly, and its other results are as if the score were not there.

Karpathy's program has no mask. It takes one position at a time and appends that position's key and value to two lists. The lists hold only the past, so the program never computes a score for a later position. The flat program computes all 16 positions at once, so it needs the mask to get the same result.

4.6 The attention weights

rows(sm, …)rows(sm, ...) applies smsm to every row of every plane. Lines 154 to 159 of FlatArrays.fss declare this form of rowsrows, for a rank-3 array. The result aa, short for attention, has the size of the scores: 4 planes of 16 by 16. Its elements are the attention weights.

Position 0 can read only itself, so its one attention weight is 1. Position 5 in head 2 spreads its attention weight over positions 0 to 5.

The starting parameters give nearly equal attention weights, as the rows above show. Two runs of smsm on four scores show the two ends:

sm [0 0 0 0] (4): 0.25 0.25 0.25 0.25

With equal scores, every position gets a quarter, and the average of the values is a plain mean. With one score 5 above the others, that position gets 98 percent, and the average is almost that position's value alone. Training changes wqwq and wkwk, and with them the scores. So it can move a head from the first case towards the second.

  • sij is the masked score that position i gives to position j, in one head. si is the row of the 16 scores of position i.

  • qi is row i of that head's plane of qhqh, and kj is row j of its plane of khkh. The dot between them is the dot product.

  • d is headDimheadDim, 4.

  • aij is a[head, i, j]a[head, i, j]: the attention weight with which position i reads position j. It is element j of smsm applied to the row si.

4.7 Mixing the values

59 
59hc = u(a vh)
59hc = u(a vh)

hchc holds the heads' results, side by side. a vha vh is again the product plane with plane. In each plane, the 16 by 16 matrix of attention weights meets the 16 by 4 matrix of values, and the result is 16 by 4. Row ii of the result is the sum, over every position jj, of the attention weight a[i, j]a[i, j] times the value of position jj. The attention weights of a row add up to 1, so this is a weighted average of the values.

The average does not know the order of the positions that it mixes: it only adds. What tells the positions apart is the position's embedding, which the first forward line added to every row. Through it, a query can fit the key of a near position better than the key of a far one.

4.8 Back into the row

60 
60x2 = xp + hc wo^T
60x2 = xp + hc wo^T

hc woThc wo^T puts every row of hchc through wowo, attention's weight matrix for the output. In hchc, each head's result sits in its own four columns. wowo mixes the sixteen columns.

Then the line adds the result to xpxp, the matrix of Part 3: the summed embeddings after one call of rmsnrmsn. It does not replace xpxp. So a row of x2x2 still holds what the row held before, its own token and position, and it now also holds a mix of what the earlier positions hold. Adding a stage's result to the stage's input in this way is called a residual connection. The model does it twice: here, and at the end of the feed-forward block in Part 5.

x2x2 is a matrix of 16 by 16, one row for each position, like every stage before it.
