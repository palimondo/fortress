+I.1.17 Initializing an array from a function
+Affected section Section 23.4.
+Change In Figure 23.1, the method that calls a function at each index and initializes the corresponding element with
+the result is named tabulate ; fill keeps the method that initializes every element with one value.
+Rationale This change does not follow from route A; the revival decided it on # September 2026. The library
+declares the element type E of an array without a bound and instantiates it at tuple types, which the implicit
+bound Object of Section 12.1 excludes; the interpreter reads such a parameter as bounded by Any, and so does
+the compiled type checker when it checks the library. E may then be Any or a function type, and a function
+passed to fill is a value of type E as well as a function from I to E : both declarations apply to the call and
+neither is more specific, which the overloading rules forbid (Section 24.3). The compiled type checker refuses
+the pair; the interpreter chose between the two by the argument’s run-time type, so that on an array of element
+type Any a function meant as the value was called at each index instead of being stored. Where the library
+derived a second name, it gave it to a form that takes a function (ivmap beside map ); most languages that have
+both operations name them differently, keeping fill for the value; and tabulate is Scala’s name for the other.
+Effect A program initializes an array from a function with tabulate . A call of fill with a function stores the function,
+on an array whose element type admits it. The library’s factories that build an array from a function are renamed
+with the method; this specification does not list them.
