## 3. The fix

**A power of numerals the checker does not compute was neither folded nor range-checked** (`7dd0adf0c`). `Naming.sizeOp` computed a power only up to the exponent 4096 (`ProjectFortress/src/com/sun/fortress/runtimeSystem/Naming.java:1211-1218` at `9d323883f`), and `TypeWellFormedChecker.sizeOutOfRange` read a size only once it folded to a numeral (`scala_src/typechecker/TypeWellFormedChecker.scala:48-51` at `9d323883f`), so a `nat` size of 2^5000 was accepted and run, and `1^5000`, whose value is 1, stayed spelled and stopped the class loader. The fix: `sizeOp` computes a power of 0, 1 or -1 at any exponent (`Naming.java:1212-1222`), and the range check refuses a size holding an operation on numerals that folding leaves uncomputed, which is then at least 2^4097 (`TypeWellFormedChecker.scala:45-74`), with the message it gives a numeral. Ways listed: raising the cap (still a cap, and an exponent of 4294967295 is half a gigabyte); refusing only a top-level power (leaves `Box[\2^5000 + 1\]` unchecked); refusing every uncomputed numeral operation, with 0, 1 and -1 computed so that none of them is wrongly refused (taken; walk's own precedent refuses an operation whose value it cannot compute, `interpreter/evaluator/EvalType.java:468-480`).

- Settled by POSITIONS, "Sizes" ("A `nat` parameter is an `NN32` value and an `int` parameter a `ZZ32`; a larger one is refused") and "Arithmetic in a size ..." ("the checker accepts a sum, difference, product or power in a size ... and range-checks what it folds").
