# P1: the instance of an F-bounded type parameter that nothing at a call fixes, under walk

## The question

Under walk, which instance does a type parameter take when nothing at a call fixes it and its bound mentions the parameter itself, as `T` in `opr SUM[\T extends AdditiveGroup[\T\]\](): BigReduction[\T,T\]` (`Library/FortressLibrary.fss:3251`), which the clause form `SUM[i <- 1#100] i` calls with no argument? Row 424's F-bounded half (`explorations/fortress-gap-ledger.md`, row 424). Folded in, as the same question: rung W's decision D2, a big operator's static parameters keep `BottomType` (`explorations/compile-ladder/rung-walk-instance/decision-record.md`), for the big operators whose parameter is F-bounded (`SUM`, `PROD`, `BIG MIN`, `BIG MAX`, the set comprehension); and row 555's F-bounded form, a lone F-bounded parameter whose arguments have several minimal common supertypes (rung W's `RpFJoin`, REPORT.md section 12; row 555's note), measured under each way as a probe.

## The ways, and what the text says of each

The texts read for every way:
- The inference chapter, `Specification/basic/inference.tex`, section "The Static Arguments of a Call" (`:100-105`): a type parameter that neither an argument nor the expected type fixes "likewise takes the intersection of its upper bounds: its declared bound, `Any` if it has none ... Inference never instantiates a static parameter at `BottomType`". It does not say what that intersection is when the declared bound mentions the parameter. Its list of what it does not yet describe includes "the element type of a reduction that only its generator clauses determine ...: the rule above gives a static parameter of the big operator that nothing at the call fixes its bounds, not the type of the elements" (`:237-240`).
- The reductions section, `Specification/basic/expressions/reductions.tex:23-44`: normative, a reduction is desugared by the type `N` of the expression; the revival's note, until an implementation does that, a clause form whose element type no argument fixes writes its static argument. The desugaring table, `Specification/advanced/parallelism-locality/defining-generators.tex:154-164`: `SUM[gs] e` of type `N` uses `SUM[\N\]` and `SumReduction[\N\]`.
- The paper, `research/extracts/ParkPOPL2019-extract.md` (FACTS, "The specification gives the run-time instance of a dispatched declaration by the POPL 2019 paper's rule ..."): the solver takes the intersection of the upper bounds and "never instantiates method type parameters with Bottom" (p. 11:19); the default upper bound is `Any` (p. 11:9); no method type parameter may appear in an upper bound (restriction (2), p. 11:11), so an F-bounded function such as `SUM` is outside its calculus, as top-level functions are (pp. 11:3, 11:25).
- The team's later Types chapter says nothing of inference; it says "The trait or object declaration may impose conditions on the arguments with which its static parameters may be instantiated" (`Documentation/Specification/Prose/Language/types.tick:256-258`).
- Walk binds a static argument without checking it against its bound: `EvalType.bindGenericParameters` (`ProjectFortress/src/com/sun/fortress/interpreter/evaluator/EvalType.java:217-300`, called for a function at `values/FGenericFunction.java:112` and for a type at `types/FTypeGeneric.java:205`) checks only the argument's kind.

11. **The parameter left open** (`P1-open.patch`). It is batch 8's checker (above). Under the chapter's rule a call has an instance only if the intersection exists, and the chapter does not say whether its absence is a static error.
