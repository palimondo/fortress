## What changed and why

P-174: "A coercion's body is a computation at compile time, with no method invocation: a number used as a value there converts where it stands, as a numeral does (P-173), into the type that its place fixes, and is refused statically where it does not fit ... where nothing fixes a type, it is an exact integer, `ZZ`." Fork N1 builds it on both paths, fork N2 writes the coercions so.

**Walk** (`interpreter/evaluator/values/Numerals.java`). `convert` bound each of the four numbers as an `FBigNum`. It now binds each as a number (`number`, `:123`): a numeral value of kind `STATIC` whose default is a `ZZ` whatever its value (`Site(BigInteger)`, `:104`, flag `number`). Walk's numeral machinery then converts it where its place fixes a type, as it converts a folded constant: at a library number type from its exact value (`exactAt`, through `Coercions.numeralCoercionFor`'s range check, so a number outside the type's range finds no coercion and the place stops with walk's message for the place, as 'got arg 3000000000:ZZ of type ZZ'); at a program's type through that type's coercion from `ZZ`; where nothing fixes a type it is its default, a `ZZ` (`w = v` binds an `FBigNum`). A number that the body returns as it is converts at the coercion's result type (`:555`, `atReturn`), so `ZZ32`'s coercion is `= v`. The dispatch cache does not hold whether a number fits a narrower type, since its default is a `ZZ` whatever its value, so a choice that converts a number at a library type is not cached (`ownCoercionFrom`, `:434`). At a call walk sends a number, as a numeral, to the most specific declaration that takes it, by its own conversion if need be (`OverloadedFunction.belowByNumerals`, unchanged).

## Where the fix belongs, and the precedent

`explorations/coordinator/map/spec-to-implementation.md` and `modules-and-phases.md` put a numeral's conversion in walk's `Numerals.java` and `Coercions.java`, the checker's `CoercionOracle.scala` (`buildCoercion`, `NumeralConversion`) and the code generator's numeral sites and `NumeralCoercionFold.java`. The precedent is the folded static constant: walk converts it at a library type from its exact value and at a program's type only through the coercion from its default; the checker's `buildNonTuple` does the same for a `STATIC` numeral. A number is that constant with `ZZ` for its default, so it reuses both. The library's own way (`library.md`) is the coercion bodies themselves: the library's integer coercions become `= v`, its float coercions call their natives with the numbers at the natives' `ZZ32` parameters.

## What the specification settles

P-174 and P-173 settle each case built: a number converts where its place fixes a type, is a `ZZ` where nothing does, and is refused statically where it does not fit. They also send a number at a call, as a numeral, to the most specific declaration that its conversion reaches (P-173's sentence on a call's parameter types, P-46); walk does so, and the compiled checker, which checks the body once, does not (row 1132; for the curator below).

## Decisions

- D1. Walk binds each number as a numeral of kind `STATIC` whose default is a `ZZ` (`Numerals.number`), so walk's own numeral conversion converts it where it stands. Not taken: an `FBigNum` with a conversion added at each place (bindings, parameters, returns), which repeats what walk does for numerals; a numeral as written with the number's decimal digits, which would reach a program's numeral coercion, where P-174 gives a folded constant only that type's coercion from its default.
- D2. A number that the body returns as it is converts at the coercion's result type (`Numerals.java:555`), so `ZZ32`'s coercion is `= v`; only a number, since a written numeral returned there would call the same coercion again. Not taken: converting every numeral result, which recurses.
- D3. Walk caches no choice that converts a number at a library type (`ownCoercionFrom`). Not taken: a finer key, which would encode four ranges in one type key.
- D4. The checker keeps a number typed `ZZ` and converts it where a place fixes a bounded number type by retyping the reference (`numberAt`). Not taken: typing it as a numeral type, which would send `ZZ32`'s own `= v` through `ZZ32`'s numeral coercion again, and whose digit count is unknown; a new node in `Fortress.ast`, larger and in the checker's generated tree.
