Of the ways to `true` that the review of them offers, the curator took its way B, whose rule is in the review's words, not his: a numeral is applicable to a parameter that fixes no type, at its default, and to a parameter whose type declares a coercion from the numeral's type, by that coercion (P-173); among the applicable declarations the most specific runs, and where two are not ordered, the one that the default fits. So `NN32`'s own `=` runs, and not the library's `=` over `(Any, Any)`, which the numeral fits at its default `ZZ32` and which answers `false` by `SEQV` (P-168). A value typed `Any` or `Number` fixes no type for the numeral beside it, which keeps its default. His own broader rule, to apply any conversion that reaches a specific declaration and to fall back to a plain one only when none does, so holds for a numeral's own conversion; for a value's coercion it is not taken. Walk and the compiled checker both infer static arguments with coercion, by the same promotion. The compiled path inserts the conversions statically. P-49 gives the order in which the checker tries a call. Row 537: the compiled dispatch between two generic declarations of one name with different bounds. Detail: `reviews/numeral-equality-ways-2026-11-10.md`, "Way B. A numeral goes to the most specific declaration that takes it; the default is the last resort".
- P-78 **`SUM` and `PROD` are one generic reduction each over the library's algebra, in place of the team's catch-all over `Number`, and take their identity from the static argument.** `SUM` is generic over `AdditiveGroup` and `PROD` over `MultiplicativeRing`. A reduction written with generators writes its static argument where nothing at the call fixes the element type. The compiled checker fixes it from the reduction's expected type, else from the type of its body, where a `SUM` or `PROD` leaves it out (F-364). It is written as in `SUM[\ZZ32\][j <- 0#n] f(j)`. A sum without generators is written as before, with no static argument: `SUM e` over a collection `e`, and the dot product `x DOT y`. `BIG MAXN`, `BIG MINN` and `BIG MINMAXN`, the team's `Number`-typed big operators for the maximum, the minimum and both, each with an identity, are gone; no program called them. `MAX` and `MIN` get no identity on the integers or the floats, so an empty `BIG MAX` or `BIG MIN` raises `EmptyReduction` (F-60: a maximum's identity is its type's least value, which a coercion into a wider type does not carry). Under walk, an empty `SUM` or `PROD` over another algebra, such as a user `AdditiveGroup`, still fails (row 436) until the specification's `HasIdentity` is built.
- P-79 **Every team demo is kept running as the tree changes.** The team demos are the programs in `ProjectFortress/demos/`; no suite or step of the gate runs them. If a change breaks a demo and the way to repair the demo is known, the batch that makes the change also rewrites the demo. A batch is a set of tasks, each called a rung, that agents build at once and land together. For example, the change that made `10^(-4)` an error (P-153, the integer power) also wrote `10.0^(-4)` in `BiCGSTAB.fss` and `BiCGSTAB2.fss`, and `10.0^(-6)` for `10^(-6)` in `npbft.fss`. A demo that fails for want of a feature is made to run again once the feature is built. So the demos known to fail today are to be respelled where the way is known. Under walk, the 52 demos that `DemoTests` lists reach their end (F-283). The compiled checker refuses `trips.fss` (row 817).
- P-173 **A numeral converts where it stands: where its place fixes a type, into that type at compile time from its exact value; where nothing fixes one, into the machine default, a `ZZ32`, or a `ZZ64` or `ZZ` when its value does not fit, and with a radix point an `RR64`.** A place fixes a type when its declared type has a coercion from the numeral type, as the eight number types have and a program's own type may (P-174); `Any`, `Object`, `Number`, an unbounded type parameter and no declared type take the default. So `x = 3` is a `ZZ32`, and `x SEQV z` is `true` for `z: ZZ32 = 3`; `bigN = 3000000000` is a `ZZ64` at its binding (row 946). The default applies to a numeral, a literal after the fold, never to an expression of a numeral type, and a `nat` parameter used as a value is a `ZZ32` where it is a size (P-40), and a `ZZ` where it is one of a numeral type's four numbers (P-174). A type parameter that several numerals fix takes the narrowest default that holds every value, an `RR64` where any has a radix point, each numeral converting into it exactly; a float numeral whose conversions into `QQ` and `RR64` tie reads `RR64`. At a typed place the conversion is exact or rounds once (P-76, P-172), and a numeral outside the type's range is refused statically; walk converts from the exact value at the same places, place by place, before it runs the checker (P-12). An expression of numerals alone folds exactly before the checker into a signed constant, which defaults as an integer numeral, as a `QQ` for a quotient, or as an `RR64` with a radix point: so `x = 7/2` is a `QQ`, `1/2 = 0.5` is `true`, and `-2147483648`, prefix minus on a numeral, folded, is a `ZZ32`. `gg(5, w)`, with `gg` declared at `(ZZ32, T)` and at `(Any, Any)`, runs the `ZZ32` declaration (P-49). The parameter types of the declaration that a call runs are places that fix a type, and a numeral argument goes to the most specific declaration that takes it, by its own conversion if need be, with its default as the last resort: `u = 0` is `true` for `u: NN32 = 0`, the numeral an `NN32` at `NN32`'s own `=` (P-46 gives the rule and its ground; row 1016 holds where walk departs, and row 1017 where both paths do). Why: the design completes the Working Draft's, whose numerals have types of their own so that a library decides by coercions how they meet other types (P-174 gives that ground). It bends P-26 in two places, the numeral types, whose names and static parameters are the Draft's (P-174), and the places that fix no type, where the compiler's prelude, the team's later word, keeps the numeral's own type; the curator takes the bend by his right to finish the specification. He declined exact defaults, `ZZ` and `QQ` (the 2012 restart gives `NN` and `QQ`, `literals.tick:25`), since microGPT's untyped hyperparameters (`MicroGptFlat.fss:18`) would then be rationals and every untyped index would need `asZZ32`.
