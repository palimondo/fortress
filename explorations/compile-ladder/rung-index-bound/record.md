## Revival change

### The change

1. **A tuple of indices is an `Index`.**
   - The team's sources:
     - The Working Draft: "Every trait type also excludes every arrow type and every tuple type, and the special types () and BottomType." (`Specification-1.0-frozen/basic/types-vals-vars.tex:215-216`) and "A tuple type excludes any non-tuple type other than Any." (`:272-273`).
     - The 2012 Types chapter: "Every trait type excludes \Void, \Bottom\ and every tuple type." (`Documentation/Specification/Prose/Language/types.tick:341`) and "A tuple type excludes \Bottom, \Void, and every trait type, arrow type or function type." (`:424`).
     - The checker made a tuple exclude every trait type and be a subtype of none (`ProjectFortress/src/com/sun/fortress/scala_src/types/TypeAnalyzer.scala:329-330`, `:560` at `00f2e1bdc`); walk made a tuple a subtype of no trait and every trait exclude every tuple (`ProjectFortress/src/com/sun/fortress/interpreter/evaluator/types/FTypeTuple.java:107`, `FType.java:203-204` at `00f2e1bdc`).
     - The library left the index parameter unbounded, `trait Indexed[\E, I\]` (`Library/FortressLibrary.fsi:1260` at `00f2e1bdc`), and the team's appendix of proposed features wanted "a type, say, Index which either excludes Range[I] or is a supertype of Range[I]", blocked because "we write a[1, 2, 3] where the arguments are passed as a tuple", needing "a magic to convert that tuple argument expression to something of type Index" (`Specification-1.0-frozen/appendices/future.tex:200-207`).
   - What the tree now does:
     - `trait Index extends Any end` (`Library/FortressLibrary.fsi:1245`); `ZZ32` extends it (`:533`); `Range` excludes it (`:2189`); every index parameter of the generic indexed types is `I extends Index` (`:1266` and the rest), and `Random`'s `UniformDistribution[\T extends Index\]` (`Library/Random.fsi:260`).
     - A tuple type whose element types are all subtypes of `Index` is a subtype of `Index`, and excludes `Index` only where one of its element types does: in the checker (`TypeAnalyzer.scala:331-333`, `:565-567`), in walk (`FTypeTuple.java:130`, `:200-201`, `:219-220`, `:412-422`; `FType.java:205`), and in the specification (`Specification/basic/types-vals-vars.tex:335-351`, `:238-246`). `()` is no `Index`.
     - `m[i, j]` passes its tuple `(i, j)` as before. The rule reads the library's trait by its qualified name, `FortressLibrary.Index`; a program's own trait `Index` is not it.
     - A program's generic over an indexed type's index parameter bounds it by `Index`: the checker refuses `f[\I\](a: Array[\RR64,I\])`, 'Ill-formed type: Array[\RR64,I\] The static argument I does not satisfy the corresponding bound Index.'; walk runs it.
     - The checker refuses a tuple expression of indices at a function whose one parameter's type is `Index` (row NEW-B-1), and a numeral there, which it types `IntLiteral`; walk runs both.
     - Test: `ProjectFortress/tests/TupleIndexBoundWalk.fss`; the checker's half: the full check of symbolic operators, whose 124 subscript errors are gone.
   - The reason:
     - Unbounded, `opr[i: I]` beside `opr[r: Range[\I\]]` is invalid at `I = Any`: the range subscript is the more specific there, and its result is no element (row 783). The checker, reading symbolic operators, refused the pair at 124 sites of the library.
     - With the bound and no rule, the checker refuses the tuple indices, 'does not satisfy the corresponding bound Index' at `(ZZ32, ZZ32)` and `(ZZ32, ZZ32, ZZ32)` (73 sites), and walk stops at the first pair: '** bug! Meet((Int,Int), Index) not a singleton: []' (`TupleIndexBoundWalk` run with the base's `FTypeTuple` and `FType`).
     - A conversion, the team's word, would change each index value that a subscript passes; the rule changes no value.
2. **`Index` stands outside `Object`.**
   - The team's sources: "every trait except Any and Object implicitly extends the trait Object if it does not do so explicitly" (`Specification-1.0-frozen/basic/traits.tex:181-183`), and the hierarchy "rooted at trait Object" (`:193-194`); the desugarer made every trait that names nothing but `Any` extend `Object` (`ProjectFortress/src/com/sun/fortress/compiler/desugarer/PreDisambiguationDesugaringVisitor.java:76` at `00f2e1bdc`); the checker made every trait type an `Object` (`TypeAnalyzer.scala:260` at `00f2e1bdc`); the specification's library declares its trait of all tuples outside `Object`, `trait Tuple extends Any excludes { Object }` (`Specification/basic-lib/objects.tex:180-186`).
   - What the tree now does: `Index` extends only `Any`; the desugarer keeps it so (`PreDisambiguationDesugaringVisitor.java:127-130`, `:169-171`) and the checker's shortcut excepts it (`TypeAnalyzer.scala:261-262`); a pair of indices is an `Index` and no `Object` on both paths (`TupleIndexBoundWalk`: `instanceOf[\Object\]((1, 2))` is `false`, `kind((1, 2))` runs `kind(x: Any)` beside `kind(x: Object)`); a trait, object or object expression whose `extends` clause names only `Index` (and `Any`) extends `Object` beside it (`PreDisambiguationDesugaringVisitor.java:91-123`; `TupleIndexBoundWalk`'s `Slot`); the specification, `Specification/basic/traits.tex:186-210`.
   - The reason: an unbounded type parameter is bounded by `Any`, which holds tuples where `Object` does not; were `Index` an `Object`, a tuple of indices would be an `Object`, or the subtype relation would not be transitive at `Index`. The checker over a program with `x: I`, `I extends Index`: 'Object->ZZ32 is not applicable to an argument of type I.'; over `object Slot(n: ZZ32) extends Index end`, `takesObject(s)` is accepted.
3. **`BoundedRange`'s narrowed `atMost` holds only at an index type.**
   - The team's library: `atMost(n: I): FullRange[\I\]` in `BoundedRange[\I\]` (`Library/FortressLibrary.fsi:2251`, `.fss:4099` at `00f2e1bdc`).
   - What the tree now does: `atMost(n: I): FullRange[\I\] where { I extends Index }` (`Library/FortressLibrary.fsi:2257`, `.fss:4105`); walk loads and runs it as before (`ant testSystem`, 669 tests, 0 failures).
   - The reason: `FullRange` takes the bound and `BoundedRange` cannot, since `Range`'s `truncL` and `truncR` return a `BoundedRange` and the open range `(:)` is a range over `Any`; written without the condition, the checker refuses the line: 'Ill-formed type: FullRange[\I\] The static argument I does not satisfy the corresponding bound Index.' After the switch-over the code generator's refusal of a method with a `where` clause of its own (row 701) reaches it, beside the sum reduction's two `distribute`s.
