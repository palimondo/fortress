# Concepts for every worker, chunk f2

The entries use these concepts, and other entries use them too. Some entries gloss a concept in a few words where a cold reader would stop. Each concept belongs in the `fortress-repo` skill, not in the revival part that is being rewritten. The skill already defines walk, the compiled path, the one library, a component, an api, the distance, the gate, an instantiation's class and a size's descriptor ("The compiled run time"), and an `XXX` test.

| Term | Entries | Where to define it | What the definition needs |
|---|---|---|---|
| Declared domain, symbolic instance | F-26, F-27; also F-252, F-253 | `references/interpreter.md`, a part on walk's overloading | A declaration's parameter types, with each type parameter standing for itself under its bounds. Walk builds it as the declaration's symbolic instance (`GenericFunctionOrConstructor.getDomain`). It is set against an instance's domain, the parameter types at the static arguments that a call infers. One declared domain lies inside another when walk's inference finds an instance of the other that holds it. |
| Static parameters of its own (the code's "own generic") | F-26, F-27; also F-252 | the same place | A generic function or constructor, or a functional method with static parameters in a trait or object without any (`OverloadedFunction.ownGeneric`). A functional method of a generic trait or object has none of its own: its trait's arguments come from its `self` argument. |
| Walk's load check | F-27, F-29; also F-252, F-102 | `references/interpreter.md` | The checks that walk runs as a program loads, before it runs: the overload sets (the parameter-by-parameter check, then the readings on declared domains) and the closure of `comprises` clauses. A failure refuses the program with a message; a test names that message in a `.test` key (`tests-writing.md:44`). Called from `Driver.java`. |
| Closed trait | F-29, F-27 | `fortress-repo` core, beside `comprises` (also listed by chunk f0) | A trait with a `comprises` clause. Its values are values of its listed types, so the checker and walk derive exclusions and covers from it. F-29 glosses it in one sentence. |
| Gap-ledger row | every entry ("row 417") | `fortress-repo` core, where it names the gap ledger | "Row N" is the row of `explorations/fortress-gap-ledger.md` with that number; `facts-extract.sh ledger:N` prints it. Its status says whether the gap is FIXED or open. The core names the ledger, but not the short form "row N". |
| Native binding, glue class, static helper | F-32; also P-58, F-61 | `references/interpreter.md`, "Natives", and `references/compiler.md` | A native binding is a library body `builtinPrimitive("…")`. Walk's string names a glue class under `interpreter/glue/prim/`, which takes walk's boxed values. The compiled path calls static helpers over plain Java values, in `nativeHelpers/`. `interpreter.md` defines the first two today, not the helpers' difference. |
| Compiler's prelude | F-32, F-34 | `fortress-repo` core, "How a program runs" | The three files of the compiled path's own library, deleted at the switch-over. The core names it without its name in the entries' words ("the compiler's prelude"). |
| Overload rewriting, dispatch generator | F-34 | `references/compiler.md` | The compile phase OVERLOADREWRITE, which makes a synthetic declaration for each overload set, and the code generator's step that writes each set's dispatch method (`CodeGen.generateTopLevelOverloads`). |
| Size, dead size | F-35, F-37, F-39; also P-40, P-41 | `fortress-repo` core, beside the descriptor | A size is a `nat` or `int` static parameter, as an array's length in its type (P-40 defines it). A dead size occurs in none of a declaration's parameter types, return type or body; it checks clean. |
| Operator static parameter | F-39; also P-41 | `fortress-repo` core, a line beside the size | A static parameter declared `opr`, whose argument is an operator name, as in `Op[\+\]`. It is a compile-time name on both paths and has no descriptor. |
