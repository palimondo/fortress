## Revival change

**The change.** The team's walk made a new string object at each evaluation of a string literal (`ProjectFortress/src/com/sun/fortress/interpreter/evaluator/Evaluator.java:889-891` at `a874948ac`) and compared two flat strings by their text (`interpreter/evaluator/values/FString.java:35-38` at `a874948ac`); the team's code generator wraps each evaluation of a literal in a new string object (`compiler/codegen/CodeGen.java:5268-5277`); neither implementation folds `"foo" || "bar"` into one literal, which the Working Draft says it yields (`Specification/basic/expressions/constant.tex:81-85`). Now two string literals of one text are one object on both paths, also one literal evaluated twice, and a concatenation by `||` of string and character literals is one string literal, folded before the type checker on both paths; strings stay reference objects, so a string built at run time is not strictly equivalent to an equal literal, except where Java answers the same string, as a whole slice does. So `"ab" SEQV "ab"`, `f() SEQV f()` for `f(): String = "ab"`, `("foo" || "bar") SEQV "foobar"` and `('a' || "bc") SEQV "abc"` are `true`, and `("a" || b) SEQV "ab"` for `b: String = "b"` is `false` (`ProjectFortress/tests/StringLiteralIdentityWalk.fss`, `ProjectFortress/compiler_tests/StringLiteralIdentityCompiled.test`). A concatenation of literals is a flat literal, not a rope, so a program or test that needs a rope or a string built apart joins a literal with a variable. On the compiled path `'a' || "bc"` now compiles, while a `Character` value before `||` and a string is still refused by the compiled path's own library (`ProjectFortress/compiler_tests/XXXCharacterBeforeStringConcatenationCompiled.test`). The reason: "Literals are values; they do not require evaluation" (`Specification/basic/expressions/literals.tex:25-26`); "All literals represent value objects" (`Documentation/Specification/Prose/Language/Expressions/literals.tick:29`); the fold of `constant.tex:81-85`; and the measured failure of both tests on the base, 'FAIL: two literals of one text are one object' on each path.
