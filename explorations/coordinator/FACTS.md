# Facts on record

## Execution model

- F-7 **Walk and the compiled path share the parser and the phases, and only the compiled path runs the static type checker.** Walk switches the checker off, and no switch turns it on, so walk shows a type error only as a failed dispatch at run time. The phases and where the two paths part: the `fortress-repo` skill, "How a program runs". Detail: `repo-internals.md`, "The two worlds".
- F-9 **`fortress typecheck` checks a program against the compiler's library, `Library/CompilerLibrary.fsi`, so it is no oracle for walk programs.** `Shell.java` calls `useCompilerLibraries()` for the command (row 69). The checker reaches walk's programs after the switch-over (P-12).
- F-11 **The code generator boxes every number, and boxing is the main representational cost of microGPT-shaped array code.** So a compiled `RR64` loop holds no `dadd` or `dmul` (the `fortress-repo` skill, "The compiled run time"). In Java models of microGPT's three kernels, boxed elements cost 6.3× (dot product), 6.5× (matrix product) and 2.6× (row lift) over `double[]`. No such kernel compiles yet: the compiler prelude has no array type (row 305), and the arrays reach the compiled path with the one library (P-37). Detail: `perf-probes/kernels/REPORT.md` sections 2 and 4.
- F-12 **The compiled scalar `RR64` loop `bench1t` runs in 0.74 s, against 13.06 s without the fixes of rows 302 and 303, a pair timed in one session.** Two costs remain. The `for` becomes the compiler prelude's `countedseqloop`, a recursive split over boxed indices with a closure call per element. Each value is boxed (F-11). The 9.34 s of the boxing and kernels reports is the unfixed tree in another session, so compare only a pair timed in one session. Detail: `compile-ladder/rung0/REPORT.md`, "The four timings".
- F-17 **The bytecode cache can come up empty after a library order that reports exit 0.** Running the same commands again, one at a time, made the jars. The cause is not known. Check the five jars before a compiled run (the `fortress-repo` skill's `build-and-caches.md`, "The library order"). Detail: `perf-probes/boxing/REPORT.md` section 1.
- F-18 **Generic instantiations are stamped out at class-load time by ASM rewriting of template bytecode.** `InstantiatingClassloader` does it the first time a program uses an instance. A size is part of the stamped class's name, as in `pNatMeth$Box⟦3⟧`, and its descriptor inside the class is `RTTIsize.of("<n>")` (F-129). Detail: `perf-probes/nat/java.md` section 1.
- F-19 **Implicit parallelism: a `for` loop is parallel unless every generator is `seq`, and a tuple's elements and an operator's operands are evaluated in parallel.** `FORTRESS_THREADS` sizes the work-stealing pool (the `fortress-repo` skill, "Parallelism and mutable state"). No program under `explorations/` writes `spawn` or `also`. Source: `Specification/basic/expressions/tuple-expr.tex:23-24`, `operator-app.tex:59`.
- F-20 **Sizes, the `nat` and `int` static parameters, are values at run time and check shapes only.** The compiled checker checks them (F-67), and a sized program loads and runs compiled (F-129). No optimization uses them. Under walk, a `nat` parameter does not unify with an array built at run time, while a literal size does (row 23). Walk matches sizes at dispatch, and a mismatch is a `ProgramError`, "Failed to find any matching overload", that no `catch` takes (row 254). Source: `Specification/basic/trait-parameters.tex:97`.
- F-21 **The specification's own declaration of `Nothing` compiles on neither path, and the reason is name resolution, not code generation.** The Working Draft's `object Nothing extends Maybe[\T\] excludes Just[\T\] where {T extends Object}` stops at `excludes`: an object has no `excludes` clause. Without it, both paths report `T is undefined`: a `where` clause on an object binds no type variable of its `extends` clause, as row 17 holds for a trait. The specification marks it "Not allowed", and the library writes `Nothing[\T\]` (P-90). Detail: `compile-ladder/rung-maybe/REPORT.md` section 5.
- F-22 **An exported function fails exactly as an exported variable does when a component's name differs from the api it exports, and the failure is the repository's, not codegen's.** Both paths look for an api's component under the api's own name, where the specification takes any component that exports it (row 320). `fortress link` and walk print "Could not find an implementation for API … on path", and a compiled run dies with `NoClassDefFoundError`. Name the api after its component. Gated by `compiler_tests/XXXExportVarRungXLinked.test`. Detail: `compile-ladder/rung-export-var/REPORT.md`.
- F-23 **A comment placed after a declaration that ends in an expression or a type becomes part of that declaration's source span and of the unambiguous name the parser derives from it.** The parser's `createSpan` trims back over spaces only, and a declaration that ends in `end` is unaffected (row 359). So a comment-only library edit can change the syntax tree, and a before-and-after comparison of parse trees or diagnostics maps positions back first. Detail: `compile-ladder/rung-library-comments/REPORT.md` section 6, D1.
- F-24 **Under `walk`, a native can raise a Fortress exception that a Fortress `catch` sees.** It throws a `FortressError` that holds the exception's object, as `Int.overflow()` does for `IntegerOverflow` (F-132; row 347, fixed). Any other Java exception of a native becomes a `ProgramError`, which no `catch` takes, so a division by zero ends the run (row 336). Gated by the `overflows(...)` assertions of `tests/IntSemanticsRungI.fss`. Detail: `compile-ladder/rung-int-semantics-walk/REPORT.md` section 4.1.
- F-25 **The compiled run's class loader takes its first load of a name under the JDK's class-loading lock, and a generic arm's first load is safe on four threads.** `InstantiatingClassloader.loadClass` locks `getClassLoadingLock(name)`, as the JDK's `ClassLoader` does (row 417, fixed). Gated by `compiler_tests/FirstLoadThreadsRungG`, which the gate's four-thread atomic runs also run. Detail: `compile-ladder/rung-generic-runtime/REPORT.md` sections 1 and 12.
- F-26 **Walk chooses between a generic declaration and another on their declared domains, not by the order they are written in.** It builds P-45 under walk. A generic trait's functional method is still compared by its instances; a generic dotted method is compared on its declared domain where exactly one of the two declared domains lies inside the other (`MethodStaticArgDeclaredDomain`). A generic instance chosen by converting an argument dispatches again, except for overloaded methods. The symbolic instance reads the static parameters' kinds and bounds, not a `where` clause. Gated by `tests/DispatchDeclaredDomain.fss` and `DispatchConvertedAgain.fss`. Detail: `compile-ladder/rung-walk-dispatch/REPORT.md` section 5.1.
- F-27 **Walk's load check reads a generic declaration beside a plain one on declared domains, and covers an overlap through `comprises` clauses, where its parameter-by-parameter check refuses.** It builds P-46 and P-60 under walk. An overlap passes only if one declaration below both covers all of it. It reads two generic declarations on their declared domains too, by the same rules (F-252), and refuses one valid set (row 539). Gated by `tests/ComprisesMeetWalk.fss` and `GenericBesidePlain*.fss`, among others. Detail: `compile-ladder/rung-walk-dispatch/REPORT.md` sections 5.3 and 5.4.
- F-28 **Walk instantiates a generic declaration declared to return `Any`.** `MakeInferenceSpecific` treats `Any` as it treats a trait type (row 157, fixed). Its visitor has no case for 11 of the syntax tree's 18 concrete type classes, and of those only the dimension forms can be written as a return type. Gated by `tests/GenericReturningAny.fss`. Detail: `compile-ladder/rung-walk-dispatch/REPORT.md` section 3.
- F-29 **Walk checks at load the `comprises` clauses of the program's main component.** It refuses an extender of a closed trait that the clause does not allow. It does not yet read the library's clauses (rows 595, 596), another component's (row 551), an object expression's (row 597), or that a listed type extends each instantiation (row 598). A `.test` file beside a test of `tests/` names its expected refusal by `load_exception_contains`. Gated by `tests/Comprises*UnlistedExtender` and the `XXX` files of rows 487, 549, 551, 597 and 598. Detail: `compile-ladder/rung-walk-load-check/REPORT.md`.
## The checker and the one library

- F-32 **The one library binds its natives by 424 `builtinPrimitive` calls, and the compiled path cannot reuse walk's glue classes behind them.** The glue classes take walk's boxed values. Against the compiler's static helpers, 147 bindings change only their text (P-58). 61 have a helper that nothing binds, 25 of them under a name that the compiler prelude gives another helper (row 348). 138 need a new helper, and 78 need more. Every program's output needs `Writer`'s natives. MicroGPT also needs `nanoTime`, whose compiled helper returns `RR64`, `getProgramArgsPrim`, which `System` calls as it loads, and `NativeArray`; the last two have no compiled analogue. They are PLAN's phase 4. Detail: `perf-probes/prelude/natives-shape.md` section 2.
- F-34 **Between the interpreter's library and bytecode stands the checker, not disambiguation, desugaring or code generation.** Compiled as it is, the library gives 1,417 disambiguation errors, all collisions between the two preludes, an artifact. With `FortressLibrary` the prelude, disambiguation, desugaring and the overload rewriting report none. Code generation, measured once, refuses 4 declarations that the checker passes: two `AsIfExpr`, one `LetFn` and one call on an intersection-typed receiver. The rest fall where the checker fails, or on synthesized overloads. The dispatch generator refuses 12 of 198 overload sets, each a functional method and a top-level function with one signature. Detail: `perf-probes/prelude/switch-over-distance-flat.md` sections 3 and 4.
- F-35 **The `FortressLibrary` api has 8 declarations with a dead size, a size parameter that occurs in no parameter type, return type or body.** They check clean, and they go only by a diff shown to the curator; the 17 vector and matrix operators' dead sizes went by decision E's diff (P-40; F-264). They stand in the oldest library in the history, of 2007-01-04 (`72ae6881b`), where the six vector forms, scalar ones included, carry the matrix product's `nat n, nat m, nat p` beside it, with no `where` clause; in 2008 Jan-Willem Maessen took them out of the component while fixing walk's unification ("tons of latent type bugs came out", `32153798d`), and the api kept them. Where the component omits a dead size, the export checker reports the api's declaration missing. Detail: `perf-probes/nat/REPORT.md` sections 2 and 7.
- F-36 **The code generator's `FnNameInfo.boundsFor` gives a size parameter a size argument, and every other kind a type argument.** A `bool`, `dim`, `unit` or `opr` parameter still gets a type argument, a latent defect; the checker refuses the first three by name (F-67). A size symbol stays in the mangled name and needs no descriptor. Only a literal size reaches the class loader, which takes its descriptor from `RTTIsize.of` (F-129). Detail: `perf-probes/nat/java.md` sections 1 to 3.
- F-37 **The one library's own sizes are the literals 0 to 3, and a compiled `typecase` on a size tests the value's own class.** A `typecase` tells `Vec[\ZZ32,3\]` from `Vec[\ZZ32,4\]` compiled by one `INSTANCEOF`, also when the size is a static parameter. A `typecase` that is a whole function body, with clauses that need a coercion, fails in code generation, size or not (row 340). Gated by `compiler_tests/NatRtCase` and `NatRtCaseGen`. Detail: `reviews/size-runtime-design-brief.md` section 5; `perf-probes/nat/size-probes.md` section 4.
- F-38 **The compiled dispatcher chooses an overload arm generic in a size by the value's size, and the arm reads its size.** Called with an argument typed `Any`, the dispatcher reads the size off the value's descriptor. The checker's return-type rule compares the arms' own sizes (row 410). The dispatcher skips the bound `Object` that the compile path gives a size parameter (row 412). Gated by `compiler_tests/NatRtDisp`, `NatRtDispSize` and `NatRtDispTrait`. Detail: `perf-probes/nat/size-probes.md` section 2.
- F-39 **An operator static argument is a compile-time name on both paths and by the specification, and no code reads it at run time.** The specification and walk substitute its name into the trait's methods; the compiled path carries it in the class name, with no descriptor. - F-40 **A size costs a few kilobytes at load and nothing on the hot path, and only the overload dispatcher reads a size off a value.** No optimisation uses a size.
