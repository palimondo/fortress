## Revival change

### The change

1. A `where` clause's constraint, in the checker. The team's compiled checker read a `where` clause's type bindings and none of its constraints (`case SWhereClause(info, bindings, _)`, its other kinds `NI.nyi("non-type where clause bindings")`, `ProjectFortress/src/com/sun/fortress/scala_src/typechecker/staticenv/KindEnv.scala:118-126` at `a874948ac`), and walk checks an object's own constraint at a use of its type ('String must subtype Shows') but runs a dotted call that breaks a method's condition on its object's parameter: `Holder[\String\]("s").showIt()` prints `h` (`ProjectFortress/tests/XXXWhereBoundDottedCallWalk.fss`, ledger NEW-K-2). The team's test `ProjectFortress/tests/GenericFnWithExcludes.fss:44` calls `g(O, P)` with `O` an `X[\1\]` and `P` a `Y[\2\]`, for `g[\U, V\](u: U, v: V) where [\nat n\]{U extends {X[\n\]}, V extends {Y[\n\]}}`, and expects it to run (`:45`); walk runs it. The tree's checker now:
   - refuses a dotted call whose every candidate breaks its `where` clause's constraint on its trait's or object's static parameter, and passes over such a candidate for another: 'Method Holder[\String\].showIt is not applicable: its where clause requires String to extend Shows.' (`ProjectFortress/compiler_tests/XXXWhereBoundDottedCallChecker.test`);
   - infers a `where`-clause variable that a constraint's bound names, so `g(O, P)` with `P` a `Y[\1\]` is accepted (`ProjectFortress/compiler_tests/WhereVariableBoundCallChecker.test`), and the team's `g(O, P)` with `P` a `Y[\2\]` stays refused, no `n` meeting both;
   - refuses a type, and a constructor call, whose static argument breaks the declaration's own constraint: 'Ill-formed type: Wrap[\String\] The static argument String does not satisfy the corresponding bound Shows.' (`ProjectFortress/compiler_tests/XXXWhereConstraintTypeUseChecker.test`, `XXXWhereConstraintExtendsChecker.test`).
   Not built: a constraint whose bound names the method's own static parameters or a `where`-clause variable, at a dotted call or a type's use; a static argument written at a top-level call (ledger row 470).
   Reason: "Static parameters may have constraints placed on them in a where clause" (`Specification/basic/trait-parameters.tex`, "Where Clauses"); the where calculus checks a method's bounds at a dotted call and asks for witnesses of the `where`-clause variables (`Specification/appendices/calculi/where/static.tex:241-257` and `:287-324`), and reads a type as well-formed only at such witnesses (`:399-410`).
2. A type `where`-clause variable in a `comprises` clause. The checker read a listed type at every type of the variable in the extender check, whatever its bound, and bounded an opened type by the binding alone. It now reads the listed type at the types below the variable's binding's bound and the clause's constraints on it, in both places: `object NBox[\E extends Object\](item: E) extends AnyNumBox`, for `trait AnyNumBox comprises { NBox[\E\] } where [\E extends Number\]`, is refused (`ProjectFortress/compiler_tests/XXXComprisesWhereBoundExtenderChecker.test`), as is an extender outside a constraint (`XXXComprisesWhereConstraintExtenderChecker.test`), and `fooOf(mk())` with `fooOf[\E extends Foo\](b: Box[\E\])`, for `trait AnyBox comprises { Box[\E\] } where [\E\] { E extends Foo }`, is accepted (`OpenTypeWhereConstraintChecker.test`). Walk still reads every type at load (ledger row 754). Reason: a listed type holds at every value of the variable, and an extender is a subtype of a listed type (`Specification/basic/traits.tex`, "Trait Declarations").
