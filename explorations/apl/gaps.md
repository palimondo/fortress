## Rung 2 — "Indexing"

| # | claim | status | class | spec citation | reproducer | found by | notes / workaround |

| 15 | a nonterminal's name may not be a word of **two or more uppercase letters**: such a word is an operator, not an identifier, and the api is rejected with a bare `Syntax Error` pointing at the name. The implementation's rule is also **looser than the spec's**: the spec requires "at least two different letters", but only the two-character repeat (`AA`) and the `XX_` form are excluded, so `AAA` is an operator in the implementation and an identifier in the spec | NEGATIVE-VERIFIED | implementation gap; spec divergence | `Specification/basic/lexical-structure.tex:1167-1172` ("An *operator word* … consists only of uppercase letters and underscores … and has at least two different letters") | `rung-2/p12a_oprword.sh` + `.out` (eleven candidate names), `rung-2/p12_name.out.0` (the full error) | rung 2 | `p12_g.fsi:20:7: Syntax Error` for a nonterminal called `WE`; the name had to become `WEx`. `Symbol.rats:108-116` lexes `OpName = id &{NodeUtil.validOp(opn)}` and `NodeUtil.java:1460-1477` is the rule: length ≥ 2, all uppercase-or-underscore, no leading/trailing `_`, and only `AA`-style two-character repeats and `AA_…` excluded. Accepted: `AA Ab AbC A W2 AB2`; rejected: `WE AB ABC AAA A_B`. |
| 16 | a **bare identifier can be a terminal** of a sub-grammar after all — not by splicing an `Id` gap (gap row 4) but by **spelling** the name: a character class of letters, concatenated right-recursively into a `String`, as the shipped `Xml.fsi` builds its attribute names. The class must be letter-then-letter-or-digit, APL's own rule | POSITIVE-VERIFIED | — | — (`syntax_abstraction_tests/Xml.fsi:120-133`, `Regex.fsi:141-142`) | `rung-2/p12_g.fsi` + `p12_name.fss` + `.out`; `base/AplSyntax.fsi` (`AplId`, `AplIdTail`) | rung 2 | `apl⦇ v ⦈` now reads the book's `v`. | 17 | with the name spelled, **APL's assignment arrow works at user level**: `v ← 9 2 6` is the book's own line, its value is the array as in APL, and the binding survives from one `apl⦇ … ⦈` to the next, because the template expands to a call on a workspace object rather than to a binding | POSITIVE-VERIFIED | — | — | `rung-2/p11_ws.fss` + `.out` (the store alone), `p12_name.fss` + `.out`, `p14_idx.fss` + `.out`, `Rung2.out` (Ex 3, 5, 17, 27-32, 37, 38) | rung 2 | The store is one reference `object` with `var` `List` fields, held in a component-level immutable binding (`aplWs: AplWs = AplWs()`); `aplSet` returns what it stored, so `a ← b ← 1 2` works. Indexed assignment has to rebuild the array — `AplArr` is a `value object` — which is exactly what `v[3] ← ¯1` expanding to `aplSet("v", aplIxSet1(aplGet("v"), …))` does. A Fortress value can be moved into the workspace through rung 1's escape: `w ← ⍎(hostm)` (`p14_idx.out`). |
| 18 | a template cannot expand to a **declaration** either, and the reason is sharper than gap row 8's: the template parser reads the left of `=` with its `AssignLeft` production, where a gap's text arrives null. No gap may sit left of either `=` or `:=` | NEGATIVE-VERIFIED | implementation gap | — (`TemplateParser.java:106-137`; the trace names `pNoNewlineExpr$AssignLeft`) | `rung-2/p16_g.fsi` + `p16_decl.fss` + `p16_decl.out` | rung 2 | `MacroError: Could not parse 'do <!@#$%^&*<Id t >*&^%$#@!> = ( <!@#$%^&*<Expr r >*&^%$#@!> ); …` / `Caused by: java.lang.IllegalArgumentException: Parameter 'text' to the IdOrOp constructor was null` at `TemplateParser3.pNoNewlineExpr$AssignLeft`. | 19 | a `*`-**repeated gap** spliced with `**` carries a list of arbitrary arity into the expansion, so a `;`-separated index list does **not** need one production per arity; what does need one is **elision** (`m[1;]`), because a bound optional gap is unimplemented and an elided axis would otherwise have to become a sentinel value in the array domain | POSITIVE-VERIFIED | — | — | `rung-2/p17_g.fsi` + `p17_ixlist.fss` + `.out`; the negative half is the apl-probes row on `b07b_optvar` (`MacroError: not supported now`, `ComposingSyntaxDefTranslator.java:509`) | rung 2 | `ixl⦇ 7[1;2;3] ⦈` → `7 indexed by 3 axes: 1 2 3`, from `b:Num `[ SPACE xs:Sep* SPACE l:Num SPACE `] => <[ lst((b), <\|[\ZZ32\] xs**, (l) \|>) ]>`. `base/AplSyntax.fsi` still writes one production per bracket shape — six of them — to keep the elision sentinel out of `AplArr`. |
| 20 | an **enclosure and a vector of coordinate vectors in an index position can be absorbed by the grammar**, so APL's scatter indexing runs over a flat numeric carrier: `⊂` is consumed by the production and a list of coordinate vectors becomes a k×rank **matrix** | POSITIVE-VERIFIED | — | — | `base/AplSyntax.fsi` (`AplAtom`, `AplCoord`), `base/AplCore.fss` (`aplPick`, `aplIdxOne`, `aplIdxCons`, `aplScatter`, `aplSquadEncl`), `rung-2/p13_core.out`, `rung-2/p14_idx.out`, `Rung2.out` (Ex 7, 8, 18, 19, 21) | rung 2 | `m[⊂1 1]` → `2`, `m[(0 0)(1 1)(2 2)]` → `4 2 3`, `(⊂1 1)⌷n` → two copies of row 1: five of the chapter's examples the goldens label "needs nested arrays" need no nesting at all, because what is nested is the *index*, not the indexed array.
