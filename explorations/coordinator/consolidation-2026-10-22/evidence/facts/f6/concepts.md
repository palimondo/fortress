# Concepts for every worker, chunk f6

The entries name these concepts without defining them, since other entries use them too. Each belongs in the `fortress-repo` skill, not in the revival part that is being rewritten.

| Term | Entries | Where to define it | What the definition needs |
|---|---|---|---|
| The interpreter's library, and the compiled library | F-79, F-81 to F-86; most of the section "The checker and the one library" | `fortress-repo` core | The interpreter's library is `Library/` with `ProjectFortress/LibraryBuiltin/FortressBuiltin.*`, the library that walk runs and that the switch-over makes the only one; the record also calls it "the one library". The compiled library is the compiler's own small prelude (`CompilerBuiltin`, `CompilerLibrary`), which the compiled path uses today. The entries now say "the interpreter's library", as chunk f0 does. |
| The distance, a site of the distance | F-83, F-85; also F-53, F-263, F-264 | `references/compiler.md`, beside the count stage | Chunk f0's `concepts.md` gives the definition. F-53 holds the current value and site list. |
| The Meet Rule, a meet, a functional method | F-76, F-80, F-81, F-82 | `fortress-repo` core, beside multiple dispatch | Two overloads whose parameter types overlap need a declaration at the meet, the intersection of their parameter types (`Specification/advanced/overloading.tex`). A functional method is a method declared with `self` among its parameters, called like a function; its Meet Rule compares the types without `self`. Two functional methods with `self` at different positions have no meet. |
| The checker's skip of operators whose names are symbols | F-80, F-81, F-82; also F-245, F-77 | `references/compiler.md` | The compiled overloading checker checks named functions and operators whose names are words of capitals, such as `CAP` or `MAX`, and skips every other operator, such as `+`, `=`, `||` and the subscripts (gap-ledger row 584; `OverloadingChecker.scala`, `isDeclaredName`, with `NodeUtil.validOp`). So an overloading error among those operators is invisible to the checker. F-245 measured what the skip hides. |
| A closed trait, coverage | F-76; also F-27, F-151, P-60 | `fortress-repo` core, "Traits and objects, no classes", beside `comprises` | Chunk f0's `concepts.md` defines a closed trait. Coverage adds: several declarations below two overloads together serve as their meet if every value of the meet is a value of one of their parameter types (P-60). The checker uses coverage only in its overloading rules, not in its general subtype test. |
| The numeral type `IntLiteral`, and walk's numeral | F-79, F-84; also F-57, F-74, F-262, F-263 | `fortress-repo` core, "Numbers are siblings, not a tower" | Chunk f0's `concepts.md` gives the definition. F-74 calls walk's numeral an `Int`; P-76 and F-79 name the Fortress types `ZZ32`, `ZZ64` or `ZZ`. The definition should say both names once. |
| A result-only type parameter | F-84; also F-70, F-78, P-48 | `references/compiler.md`, beside the checker's inference | A type parameter that occurs only in a declaration's result type, so that no argument fixes it. P-48 gives it the intersection of its upper bounds, narrowed by the expected type. |
| A slip, repaired in the library's own spelling | F-83, F-84, F-85; also F-77, F-264 and the rung reports | `references/library.md` | A slip is a small typing error in a library declaration that the compiled checker refuses: a declared type that differs from what the body answers, a wrong static argument, a getter called as a method. "Repaired in the library's own spelling" means repaired in a form that the library already uses elsewhere, so that the fix follows a precedent. The clean entries say "declarations that the checker refused" and "repaired in forms that the library already uses", so a reader needs this term only for the reports. |
| An export error | F-83; also F-53, F-264 | `references/compiler.md`, beside the distance | The compiled checker's check that a component matches its api: the same members, with the same header and type (`Specification/basic/components/apis.tex`). The `FortressLibrary` component has one export error for traits whose declaration differs from the api's, with one entry for each such trait. |

Concepts that only one entry uses are defined in it: the fused branch of `__bigOperator2` (F-85) and the expansion rule for varargs (F-86).
