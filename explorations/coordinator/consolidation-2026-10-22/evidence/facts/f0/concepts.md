# Concepts for every worker, chunk f0

The entries name these concepts without defining them, since other entries use them too. Each belongs in the `fortress-repo` skill, not in the revival part that is being rewritten.

| Term | Entries | Where to define it | What the definition needs |
|---|---|---|---|
| The distance stage, the distance to the switch-over | F-263, F-264; also F-53, F-229 | `references/compiler.md`, beside the count stage | The gate's stage that runs the compiled checker over the interpreter's library and counts all its errors, by root cause. They must reach zero before the switch-over. The checker count, beside it, stops at each component's first error. F-53 holds its current value. Its tools are `explorations/coordinator/tools/distance/run.sh` and `compare.sh`. The `coordinator` skill defines it today (`references/batch.md`), which no worker loads. The cold reader found the count stage in `compiler.md`, but not this one. |
| A closed trait | F-151 (said there in plain words); also F-227, gap-ledger row 686 | `fortress-repo` core, "Traits and objects, no classes", beside `comprises` | A trait is closed when its `comprises` clause lists every type below it, as `Number`'s does (`Library/FortressLibrary.fsi:286-287`; `reviews/array-fork2-judgement.md` section 0). The checker and walk then derive exclusions from the listed types: an element type under `Number` excludes `String`. A trait with no `comprises` clause, such as `MultiplicativeRing[\T\]`, gives none. The core says what `comprises` means, but not this. |
| The scalar extension | F-151; also F-119 | `references/library.md` | The eight generic operators `+`, `-`, `MIN` and `MAX` between an `Array[\T,I\]` and a scalar `T`, in both orders, each bounded by `Number` and the algebra trait that its body uses (`Library/FortressLibrary.fsi:2702-2712`; F-119). |
| The numeral type `IntLiteral`, and walk's numeral | F-151, F-263; also F-74, F-229, F-262 | `fortress-repo` core, in "Numbers are siblings, not a tower" | The compiled checker gives every integer numeral the type `IntLiteral` (F-262). Under walk a numeral is a `ZZ32` value, walk's `Int`, until walk has the checker's static types (F-74). `Number` comprises `IntLiteral` beside the eight number types that the core lists. `IntLiteral` extends `Number` alone, so it is no ring at its own type (`ProjectFortress/LibraryBuiltin/FortressBuiltin.fsi:179`). Under walk the name `IntLiteral`, written as an expression, is also a value, a zero (`FIntLiteral.ZERO`) that no numeral reaches, and its arithmetic answers a `ZZ32` (gap-ledger row 578; `tests/IntegerPowerContractWalk.fss`, `numeralType`). Added by the judge: the second cold reader could not tell how a type's name denotes a value. |
| `Vector` and `Matrix`, the array family with arithmetic | F-151, F-264; also F-119, F-158, F-229 | `references/library.md` | `Vector` and `Matrix` extend `Array1` and `Array2` with arithmetic. Their element bound is F-151's. `array1` and `array2` give one only at the eight number types, and a plain array elsewhere (F-229). |
| A sized array and the unsized `Array` | F-264; also P-40 | `references/library.md`, beside `Vector` and `Matrix` | `Array[\E,I\]` names an array by its element and index types alone, with no size (`Library/FortressLibrary.fsi:1471`). `Array1[\T,b0,s0\]`, `Array2[\T,b0,s0,b1,s1\]` and `Array3` carry each dimension's lowest index `b` and size `s` as `nat` static parameters (`:1591`, `:1695`, `:1812`), so the checker knows them. A range subscript answers the unsized `Array` (`Library/FortressLibrary.fss:2678`), so code that needs the sized type gets it back through `cast`. Added by the judge: the second cold reader lacked "sized". |
| The library's `cast` | F-264; also F-229 | `references/library.md`, beside the library's devices | `cast[\T\](x)` returns `x` at type `T`, or raises `CastError`. The library uses it where a value has its type at run time but the checker cannot see it. |
| PLAN items and the review queue | F-151 | The short orientation that replaces the revival part | `explorations/coordinator/PLAN.md` numbers the work and the curator's open answers. `review-queue.md` holds each choice built at a default that waits for his review. A worker follows such a pointer only to see that a choice is not yet his ruling. |

Concepts that only one entry uses are defined in it: `replica` (F-264). `Col` and `Row`, which the second cold reader lacked, are F-264's alone and change no action there: they are the library's objects that view one column or one row of an `Array2` as an `Array1` (`Library/FortressLibrary.fss:2821`, `:2832`). F-264 says "branch" and "lowest index" in place of "arm" and "base 0", so it needs no concept for them; F-229 still says "arms".
