# Concepts for chunk p

The `fortress-repo` core already defines the compiled path, walk, the one library, component, api and the exclusion rule ("Traits and objects, no classes"). The terms below are not defined there, or are defined with another meaning.

- **prelude** (P-37, P-26, P-43, P-158): The library components that every program imports without an import statement. On the compiled path today they are `CompilerLibrary`, `CompilerBuiltin` and `CompilerAlgebra`, with `AnyType`; under walk, `FortressLibrary` and `FortressBuiltin`. The prelude sweep (`reviews/foundations/prelude-lens.md`, section 0) uses the word more widely, for four wired files with `CompilerSystem`. Define it in the `fortress-repo` core, in the code's sense.
- **switch-over** (P-37): The change after which the compiled path reads the interpreter's library and the compiler's prelude files are deleted. The core names it without a definition. Define it in the short orientation.
- **bootstrap** (P-37): The curator's word for the compiler's prelude: scaffolding to remove ("the compiler second library is just a bootstrap and we need to get rid of it", 2026-09-20 14:39:06 UTC). The build's "bootstrap stubs" are another thing: class files of the compiler's library that the build compiles from `ProjectFortress/src/fortress/` (`references/build-and-caches.md`). Define it in the short orientation, beside the switch-over, and keep the two senses apart there.
- **type group** (P-26, P-43): The part of the team that built the type checker and the compiler. P-26 defines it; P-43 leans on it. Define it in the short orientation.
- **later word** (P-26, P-43, P-158): The type group's later positions, which win over the specification's early text where they conflict. P-26 owns it. Define it in the short orientation, with P-26's number. `exploring.md` copies P-26's list as a closed list ("These positions are:") and gives its second item the implementation's meaning. Make that copy point to P-26, and keep the list open.
- **the twelve components** (P-37): The library components that the gate's distance stage and the count stage check: `FortressLibrary`, `RangeInternals`, `FortressBuiltin`, `NativeArray`, `List`, `String`, `FlatString`, `Stream`, `NatReflect`, `TypeProxy`, `Writer`, `AnyType` (`explorations/coordinator/tools/distance/run.sh`). Define it in the compiled area part, `references/compiler.md`, beside the count stage. There, give the checker's zero its scope. The core's sentence "The compiled checker already finds no error in the interpreter's library" holds only for the twelve, at the distance stage's setting, the bound `Any` (F-289, F-290). A cold reader of P-37's "Why" took that sentence to mean that the checker already accepts the library.
- **Working Draft** (P-26, P-43): The team's unrevised specification, in `Specification-1.0-frozen/`, cited as "the Working Draft of February 2011". `references/specification.md` and the revival part define it; the core does not. Define it in the `fortress-repo` core, beside the specification, since P-26's "early text" and P-43's grounds both mean it.
- **route A, route C** (P-43, F-46, P-95, P-96): The two ways weighed for the number types. Route A keeps the exclusion rule and makes the number types siblings. Route C nests the tower again under the patents' forest rule, with a return-type rule over every level of a chain (F-46). The names are record-wide, so define them in the short orientation, beside the flat number types.
- **specialization** (P-26, P-43): P-26 defines it as an overload for one instantiation that dispatch chooses at run time. The `fortress-repo` core and its exploring part use the word for a class per instantiation. Give each meaning its own word in the `fortress-repo` core: a specialised overload (the language) and stamping, the class loader's class per instantiation (the implementation).
- **export check** (P-158): The compiled checker's comparison of a component with each api that it exports. Define it in the compiled area part, `references/compiler.md`.
