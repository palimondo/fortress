- P-146 **The checker reads `self` in a self-typed trait's method bodies as the implementing type (way 6).** In a trait `C[\X\]` whose parameter `X` extends `C[\X\]`, `self` in the trait's method bodies has the type `C[\X\] & X`; the signatures keep the plain trait type, as the POPL 2019 paper's assumption on declared types needs. A type that extends such a trait at another type is refused, Scala's conformance rule. The library's text gains no self type and no `comprises` clause, and walk is unchanged. It clears every self-typed body of the library but `Integral`'s `numerator`, which each integer type declares instead. Why: it reads the library as the team wrote it, as P-44 does, by one rule the peers share.
- P-147 **An object defines an inherited abstract method when its bodies of that name at narrower parameter types together cover the abstract method's parameter types (item 51).** It is the team's rule of 2012, in Steele's compiled checker and Welterweight's Covered rule, with `comprises` clauses read as the checker reads them; a body at the abstract method's own types is the plain case. So the team's `Pairs` and `FileConversion` stay valid, walk agrees with the checker, and the traits chapter's sentence is revised in the S1 form (P-96). Walk's allowance of any one narrower body goes.
- P-149 **An object that inherits an abstract functional method from one trait and its body from a sibling trait, and declares none of its own, is refused (Q1).** So `object O extends { A, B }`, with `pick(self)` abstract in `A` and given a body in `B`, must declare its own `pick`, as the specification's text and the type group's Welterweight calculus require and as walk already does; an abstract and a concrete declaration of one method in one trait are refused too. Why: the revival honors the designers' intent and does not change Fortress's nature for a convenience; other languages are consulted only to reconcile a conflict between earlier and later designers' choices, and here there is none.
- P-152 **Exclusion between two generic declarations is read over the whole parameter type, on both paths (the specification's existential reduction).** Two declarations whose parameter types exclude each other only together, through a shared parameter that fixes one static argument, are read as the specification reads them: the pair is valid where the declared domains meet the overloading rules. Walk and the compiled checker both change to read the whole parameter type, so that rows 740 and 741 close, and walk loads the program that it refused after climb batch 16. Why: the type group's paper of 2011 decides exclusion between parameter types with static parameters by existential reduction (`Papers/Types/exc-reduction.tick`; the team's later word, P-26), as the revised specification states (`advanced/overloading.tex`, "Declarations with Static Parameters"). Still to build: walk's reading of such a pair where one declaration has a `where` clause (row 787), and of an object type over a static parameter (row 788).
- P-154 **A list compares only elements that are totally ordered, while a pair of floats is ordered (ask 4, 2026-10-20: rung X's question 2).** So on the checker a list of floats or of `QQ` has no `<`. No lexicographic trait over partially ordered elements is added now: the team never wrote one, and the case touches neither the distance nor microGPT. Why: the team's later code bounds the element of both lexicographic traits by a total order (`Library/incomplete/advanced/Fortress.PartialTotalOrders.fss:117-140`; P-26), and conditional extension is a `where` form the team wrote (P-151). Still to build: walk's half (row 774; PLAN, phase 3, item 19), and a revision note at the specification's two sentences that order every list (`advanced-lib/algebraic-constraints.tex:519-522`, `basic/operators/opr-overview.tex:293-295`).
- P-155 **Symbolic operators are checked for overloading before the switch-over (ask 5, option 2, 2026-10-20).** The compiled checker's overloading check reads `+`, `^`, `||`, the subscripts and every other symbolic operator by the rules it applies to any function, so that the switch-over's zero is a true zero. Why: the skip is a gap the team knew (its open-issues list calls the library's subscript pair "not really a valid overloading"), not a rule, and an unchecked zero hides known errors. Each design that the check needs, such as a bound on the subscripts' index type that keeps ranges out, or a vector plus a number beside a vector plus a vector, is brought to him with the probe's measurement before its rung (`perf-probes/symbolic-operators-2/REPORT.md`). Still to build: the check and its rungs (row 584; PLAN items 38 and 59).

- P-69 **`LSHIFT`/`RSHIFT` are bit operators on the fixed widths; `shift` is exact on ℤ.** A count at or beyond the width gives 0 or the sign, and a negative count reverses. Shifted-out bits fall silently, as in every peer language. Compiled code shifts the machine word, never through ℤ. A count may have any integral width (row 380). Built on both paths, but for the compiled `NN32` and `NN64`, whose shifts are refused (row 442); the compiled path gets them, `shift` and the any-width count at the switch-over (P-38).
