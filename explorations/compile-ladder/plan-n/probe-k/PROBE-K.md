## 1. The shadow

`shadow.patch`, applied by `build.sh` to copies of the sources at `158aa7dce` and compiled with `javac` against the private home's classpath into a class directory that `run-pass.sh` puts first. Added lines by file (`awk` over the patch): `EvaluatorBase.java` 377, `OverloadedFunction.java` 131, `Coercions.java` 180, `Fcn.java` 14, the new `ProbeK.java` 125; none removed. - **Place 1, the inference** (`EvaluatorBase.inferRule`). The positions of a generic call are sorted by their declared type: a type parameter alone (`x: T`); a type that mentions a static parameter otherwise (`b: Box[\T\]`, `base: Matrix[\RR64,br,bc\]`); a type that mentions none (`m: ZZ64`). The first pass unifies the second kind as today, with a functional method's `self` and a varargs parameter, which are kept as today. A position of the third kind is left to the binding, which converts it (rung C's `Coercions.coerce` in `NonPrimitive`). A type parameter that stands alone at some position and that the first pass fixed keeps that type, and its arguments are left to the binding. One that the first pass did not fix takes the narrowest of its candidates that each of its arguments matches (`typeMatch`) or converts into (a coercion found for the value) and that its bounds admit (the upper bound and an F-bound checked as today's rechecks check them): the candidates are each argument's run-time type, every supertype of it, every type a coercion takes it into, and the plain bound. Narrowest means a subtype of, or convertible into, every other such candidate; when none is, today's join is kept. After the instantiation every argument must be admitted by match or by conversion; otherwise, or when anything throws, the answer is today's.
- **The reverse lookup** (`Coercions.coercionTargets`). The types a value converts into: every non-generic type with a lifted coercion named at the top level of the library, of the applied function's component and of the value's type's component, kept when a coercion from the value is found. This is what answer 8's promotion needs for `ZZ32` with `NN32` (`ZZ64`, neither argument's type).
- **Place 2, the coercion pass** (`OverloadedFunction.bestMatchWithCoercionRule`). The generic declarations are no longer skipped: each is instantiated by place 1 and its coercions are built against the instantiated domain, as for a plain one; the most specific is chosen as rung C chooses. `bestMatchInternal`'s code is unchanged, but the inference it calls is place 1's, so a generic declaration whose instantiation now needs a conversion leaves the subtyping pass and reaches the coercion pass (section 6).
- **Place 3, a generic target's coercion** (`Coercions.coercionForRule`). For a generic target such as `WideG[\ZZ32\]`, the lifted coercion is looked up by the generic's own name and instantiated with the target's static arguments before it is checked against the value.
- **The log**. `ProbeK.log` writes one line per difference to the file `-Dprobe.k.log` names: `INFER` (the declaration, the arguments' run-time types, today's instantiation or error and the rule's, with `cvN` for each argument the binding converts), `DISPATCH` (the declaration an overloaded call chooses, today and under the rule) and `COERCE` (the coercion found to a target, today and under the rule), each with the innermost call site and the innermost one outside the libraries (a stack of sites kept by `Fcn.functionInvocation`). A failure of the shadow's own code on the rule's side falls back to today's answer and is written `SHADOW-FAULT`; there were none in the passes of section 3. Each distinct call shape is inferred once per run, since walk caches an instantiation by its arguments' types, so a line names the first site that met it.
