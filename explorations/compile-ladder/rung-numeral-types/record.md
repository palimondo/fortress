## Revival change

**The change.** The team's library gave a numeral the interpreter's own objects: `value object IntLiteral extends { Number }` with 21 glue bindings and `value object FloatLiteral extends RR64` with 3 (`ProjectFortress/LibraryBuiltin/FortressBuiltin.fsi:199-246`, `:44` at the base), and the team's walk evaluated an integer numeral to a `ZZ32`, `ZZ64` or `ZZ` value by its value and a radix-point numeral to a `FloatLiteral` holding its text (`interpreter/evaluator/Evaluator.java:1631-1637` and `values/FFloatLiteral.java:21-33` at the base), so a float numeral stayed a `FloatLiteral` at an `RR64` binding and no number type but `RR64` received it. The tree now declares `trait Numeral` and the value objects `NaturalNumeral(digits, radix, digitValue)` and `RadixPointNumeral(digits, fractionDigits, radix, digitValue)` (`Library/FortressLibrary.fsi:454-494`); each of the eight number types converts from them, exactly or by one rounding, with an `=` pair both ways; and walk evaluates a numeral to its default, a `ZZ32`, `ZZ64`, `ZZ` or `RR64`, converting it from its four numbers where a binding, parameter, field or return type fixes a type, so `q: QQ = 0.1` is 1/10 and `y: RR64 = 0.5` is `SEQV` a computed 0.5 (`ProjectFortress/tests/NumeralTypesWalk.fss`), and a program's type receives the numeral object through `coerce(x: RadixPointNumeral)` (`ProjectFortress/tests/NumeralOwnTypeWalk.fss`). The reason: the Working Draft gives numerals types of their own because "converting it immediately to a floating-point number may lose precision" and so that "library designers [can] decide how numerals should interact with other types of objects by defining coercion operations" (`Specification-1.0-frozen/basic/expressions/literals.tex:132-148`), with the four numbers `n`, `m`, `r`, `v` (`:83-129`); and on the base walk refused `q: QQ = 0.5` ('RHS expression type FloatLiteral is not assignable to LHS type QQ'), answered `false` to `1/2 = 0.5`, and refused `s: RR64 = 3000000000` ('RHS expression type Long is not assignable to LHS type RR64'), `u: NN32 = 5` and `r: RR32 = 0.1`.
