# Rung L, rung-label-exit: the record lines

## For FACTS

**The compiled path runs `label` and `exit`: an exit is a thrown `LabelExit` that names one evaluation of its label block, and reaches it from a loop's body and from another task.** `CodeGen.forLabel` keeps a new `LabelExit.Target` in an immutable local under the label's name and takes, in a handler, the exits that name it; `CodeGen.forExit` throws `LabelExit.of(value, target)` (`ProjectFortress/src/com/sun/fortress/compiler/codegen/CodeGen.java:1776-1857`, `runtimeSystem/LabelExit.java`). A function expression or a task whose body exits captures the target as it captures any immutable variable, because every identifier counts as a free variable (`compiler/codegen/FreeVariables.java:98`) and the checker lets no variable share a label's name (`scala_src/typechecker/impls/Misc.scala:704`). A group of forked arms joins the arms that it forked before the exit passes it: at four threads every forked iteration of a parallel `for` runs to its end or to its own exit, and the label's value is the exit of the first arm in the arms' order; at one thread the iterations after the exit do not run. No `catch` clause takes an exit. What it means for the work: the one library's `Indexed.indexOf` compiles in its own form (the test's `Holder.indexOf`), and row 81's wall is gone. Four limits stand, each with its test: an exit out of an `atomic` block loses the block's writes (NEW-L-1); a `finally` clause on the exit's way does not run (row 890); a label block as a call's later argument fails verification (row 322); a label block whose value joins a numeral with a number stops the code generator (row 340), so a number beside an exit's value is bound to a typed variable first. Test: `compiler_tests/LabelExitCompiled`, which fails with 'Can't compile Label' without the two members. Detail: `explorations/compile-ladder/rung-label-exit/REPORT.md`, "What changed and why" and "Points to report reached".

## Revival change

### The change

The team's code generator had no case for a label block or an exit: `CodeGen` declared no `forLabel` and no `forExit`, so the node reached `defaultCase`, which refused the declaration with 'Can't compile Label' (`ProjectFortress/src/com/sun/fortress/compiler/codegen/CodeGen.java:1859`, `defaultCase`). Walk runs both, and matches an exit to a label by the label's name (`ProjectFortress/src/com/sun/fortress/interpreter/evaluator/Evaluator.java:628-645`, `:500-519`); its `try` offers an exit that passes it to the `catch` clauses as the library's `LabelException` (`Evaluator.java:1453-1456`).

The tree now compiles both (`CodeGen.java:1776-1857`, `runtimeSystem/LabelExit.java`). A compiled exit leaves the evaluation of the label block in which it was made, also from the body of a `for`, from a function expression and from another task; a parallel loop first joins the iterations that it forked, which run to their end or to their own exit; the label's value is one of the exiting values. No compiled `catch` clause takes an exit. Test: `compiler_tests/LabelExitCompiled`.

A compiled program must still keep to four spellings: bind a number that a label block yields beside an exit's value to a typed variable first, as `none: ZZ32 = -1` (`compiler_tests/XXXLabelNumeralValueCompiled`); bind a label block's value in a statement of its own, not as a call's later argument (`compiler_tests/XXXAtomicBlockLaterArgument`); do not rely on a `finally` clause between an exit and its label (`compiler_tests/XXXFinallyOnEscape`); do not exit out of an `atomic` block and rely on its writes, on either path (`compiler_tests/XXXExitOutOfAtomicCompiled`, `tests/XXXExitOutOfAtomicWalk.fss`). A function, a variable and a label in scope may not share a name: the checker refuses 'Cannot use an existing identifier … for a 'label' expression'. An exit that runs after its label block has completed ends a compiled program (`compiler_tests/ExitAfterLabelCompletedCompiled`). The skill's list of constructs that the code generator has no case for names `label` and `exit`, which it now has.

The reason, as evidence: the specification's section "Label and Exit" (`Specification/basic/expressions/label.tex:52-66`); the one library's `Indexed.indexOf` (`Library/FortressLibrary.fss:2189-2195`), above every string and array, was refused; the failing run 'Can't compile Label at …LabelExitCompiled.fss:13.29'.
