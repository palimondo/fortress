## The APL side quest, where it stands and how it closes

Goal as Pavol set it: convert APL syntax into efficient Fortress code over Fortress's native arrays, not an interpreter of APL in Fortress. The design and the ladder are in `explorations/apl/README.md`; the base is `explorations/apl/base/` (`AplCore.fss/.fsi` the library, `AplSyntax.fsi` the grammar). Rungs 1 to 6 are done and green, one directory each with `DESIGN.md` (rungs 3 to 6), `REPORT.md`, `PROBES.md`, probes with `.out`, and `RungN.fss` checked against the book's printed output in `explorations/apl/goldens/ch1..ch6`. Rung 7 (tacit) is skipped by decision: the programs have one tacit line, rewritten. Rung 8 (nested arrays) is not built; strands of arrays became Fortress tuples in rung 5.

Mechanisms established, all in `explorations/apl/gaps.md` (85 rows, not yet in the main ledger): glyphs as host operators where the operator table allows; templates expand to host code; rank in the type with overload families over `RR64`/`Vector`/`Matrix`/`Array3`; rank read off the source text for `⍴ ⌷ ↑ ↓ ⍉`; a glyph handed to an operator is a zero-parameter host lambda over a frame stack (`aplCall`, `aplAlpha()`, `aplOmega()`, `aplSelf()`), the only form that survives nested dfns; guards as `if … then … else rest end`; `⍤1 ⍤2 ⍤0 1` over row and plane views with the result rank chosen by overloading on the first cell's result (`aplAsm1/2`, result type `Object`); `+.×` is the shipped `DOT`; outer products direct for the common glyphs; `¨` over simple arrays and over tuples; destructuring `a b c ← e` as a lambda over a tuple; `\ ⍀ ⍣` and general `f/`. APL names are a closed set in the grammar, one line per name, three sets (arrays, functions, tuple members); a word of two or more capitals cannot be a name.

The closing steps, in order, after C4:

1. The program-specific APL design, `explorations/apl/microgpt/DESIGN.md` (this thread): what the flat-style program `explorations/apl/reference/hsu-flat/microgpt_concise.dyalog` needs beyond rungs 1–6 and how each maps onto C4's Fortress: the per-head rank (the Dyalog's rank 4 with `0 2 1 3⍉` becomes C4's rank-3 views, so `h` is `heads` and `u` is `unheads`), `v←{(⍵⊃SHP)⍴P[…]}` as the `PView`, `⊃,/,¨` as `flat`, the `∘←` state of Adam as the returned triple, `⎕NREAD` as the loader, `TOKM`/`LEN` as the corpus object, `⍤0 1` as `diag` and `pick`, guards, and which glyph rules are direct (the direct rules of rungs 1, 3, 5, 6 cost 3.8× less than the general forms).
2. The flat-style microGPT written in the APL sub-language, `explorations/apl/microgpt/MicroGptApl.fss` (an Opus worker implements against the design, this thread reviews), whose expansion is C4's Fortress or something that reads as it, checked against the same goldens with the same check (the check imports the APL component through an api exposing `step` and `adam`); checks at both pool sizes; a `REPORT.md` with the correspondence table Dyalog line → APL-in-Fortress line → expanded Fortress line, and the cost against C4.
3. The APL ledger merge: the 85 rows of `explorations/apl/gaps.md` plus the microGPT round's rows into `fortress-gap-ledger.md` through the merge worker (every reproducer re-run), `gap-cross-run.md` extended with an `apl` column, `apl/README.md`'s ladder table closed with the microGPT rung.
