## 2. What the revision states, and what it does not

The ranges section states:
- the components of an explicit range are values of type `ZZ32`; `a`, `b` and `c` produce such values (the `#` operand `n` is a component too);
- an integer numeral converts to `ZZ32`, as the literals section says libraries define coercions from numerals to integers (`Specification/basic/expressions/literals.tex:146-148`);
- it is a static error if a component has an integer type other than `ZZ32`;
- a loop whose counter must have a wider integer type runs over a range of `ZZ32` values and widens each element, shown as `for i <- 0#n do j: ZZ64 = i ... end`, where the binding converts by the coercion the integer chapter states (`Specification/basic-lib/basic-integers.tex:25`: `ZZ64` coerces from `ZZ32` and `NN32`).

It does not state: the public range traits' index type, which the decision keeps generic and the section never named; multi-dimensional ranges, which the section never described; the type of `|r|`; anything about static ranges (L2) or `nat` parameters as components (L3). Each is left as the Working Draft had it, so the revised text states no more than J's section builds (the batch record's stop).

## 5. Decisions taken inside the rung

1. **The ranges section says "its components are values of type ℤ32"**, not "a, b, c and n": the bullets use `n` both as a derived count (`ranges.tex:51`, `:59` now) and as the operand of `#` (`:68`), and the section's own word for the operands is "components" (`:101-103` now, "Non-static components of a range expression"). Rejected: adding `n` to "Assume that a, b, and c", which would collide with the count.
2. **The wider counter is shown with a typed binding, `j: ZZ64 = i`**, not with the library's `widen(i)` that the decision's wording and the demos use (`ProjectFortress/demos/fact64.fss:22-23`): the specification states the coercion into ℤ64 (`basic-integers.tex:25`) and names no integer `widen`; walk converts at a typed binding (FACTS.md, "Under walk, the interpreter converts by coercion at its three kinds of type check"), measured on the base: the loop sums to 3 and the binding holds a `ZZ64` (`RespelledRanges-base-walk.txt`, W1, W2). Rejected: `widen(i)`, a library method the specification does not list. It is placed after the bullets that define `#`, with the callout after it.
3. **`mySum` changes its parameter only.** Rejected: all of it ZZ32, which changes the sum's type and loses what a ZZ64 sum is for (S2); keeping `i: ZZ64` and narrowing it (`0:narrow(i)`), a library method the specification does not list and a function that fails for a large `i`.
4. **The generator is respelled over ZZ32 throughout, with `mid = lo + (hi - lo) DIV 2`.** Rejected: keeping ZZ64 fields and producing a `SequentialGenerator[\ZZ64\]` from a ZZ32 range by a map, which teaches conversions instead of blocked ranges; keeping the floor midpoint, which is a ℤ (section 3.4); `(lo + hi) DIV 2`, which truncates toward zero (`basic-integers.tex:431-432`), so for `BlockedRange(-3,-2,1)` it gives `hi` (`(-3 + -2) DIV 2` is `-2` under walk, `RespelledRanges-base-walk.txt`, G5) and the first half is the whole range again, recursing without end, and which forms `lo + hi`, past ZZ32 when both bounds exceed 2^30 (row 453's shape in the compiler library). The new midpoint equals the floor whenever `lo <= hi` and the generator's size `hi - lo + 1` is a ZZ32 value; at `(-1, 2147483647)` it raises `IntegerOverflow` at `hi - lo` on both paths (`probes/skeptic/differential3.txt:2-31`), where the generator's own `size` overflows first. The team's sequential loop, `i += 1` after the last element, is kept; at `hi = MAX` it raises `IntegerOverflow` after the last body, row 451's shape, not this rung's.
5. **The adapted generator (R8) is respelled with the figure**, though measurement C's list and the brief name two examples, so that the section declares one `BlockedRange`, whose members the ellipsis stands for. Rejected: leaving it at ZZ64 (the section would declare the object at two types, the elided `seq` a ZZ64 range the decision refuses), or reporting it without choosing: the decision settles it through the figure it adapts. Its midpoint is left (L9).
6. **The factorial property is stated without a range**: `0! = 1` and the recurrence. Rejected: a range over ZZ32 with a conversion, `PROD[\ZZ\][k <- 1:narrow(m)] big(k)` (`narrow` on ℤ and `big` on ℤ32 are the library's, `Library/FortressLibrary.fsi:608`, `:549`), which states the property only below 2^31, names two methods the specification does not list and needs the static argument of the reductions callout (`Specification/basic/expressions/reductions.tex:35-37`). The recurrence is the chapter's own form for `CHOOSE` (Pascal's rule, `basic-integers.tex:557` at the base).
7. **The callout's edit deletes " or a range" and nothing else**, keeping its line count, so that the eight test files that cite lines below it move only by the factorial entry's lines. Rejected: rewrapping it with a pointer to the ranges section, which would move every citation below `:65` for a sentence the ranges section already says.
