## 7. The failure-mode question

The edit replaces a loud failure with a quiet value. At 340 native bodies and 22 calls of `fail` and its loop, the checker's "Could not infer static argument T without context" becomes `T := BottomType` with no error (`Formula.scala:524-527`, `STypesUtil.scala:1937-1940`). For `fail`, `BottomType` is the type the specification gives its `throw` body, so the value is right. For the natives it means their bodies are no longer checked against their declared types (row 309's note). Walk reads none of the three bounds.

On the compiled path the quiet value becomes a late loud one. A call of a result-only parameter bound to `BottomType` in a value position of a concrete type compiles, and then the whole class fails JVM verification at load (`SkStopLocal`). The same call with its argument written runs (`SkStopWritten`). The compiler library avoids this with `: Zilch` (`SkZilchFail`), but that device is outside the specification and fails under walk (`SkZilchLocal`).

The decision's reason why binding `Bottom` is harmless covers the natives, whose bodies the switch-over replaces (POSITIONS 2026-09-27, the numerics plans; row 309). It does not cover `fail`, whose body stays. The one library calls `fail` in value positions at `Library/FortressLibrary.fss:1423`, `:1453`, `:1499` and `:2504`, among others. Nothing fails today, because no compiled program imports the one library. The rung must record this fact (correction 3), and it goes to Pavol (section 12).
