2. Autograd: a scalar that remembers the chain rule

Training needs, for every parameter, the derivative of the loss with respect to it. microgpt gets it by reverse-mode automatic differentiation on scalars: every number in the computation is wrapped in a Value that records which values it was computed from and the local derivative with respect to each. Backpropagation then walks the graph from the loss backwards, applying the chain rule at each node:

{{math:chain}}

The local derivatives of the six operations microgpt uses are:

{{math:localgrads}}

Here is the reference class, minus the reverse-operand helpers:

class Value:
    def __init__(self, data, children=(), local_grads=()):
        self.data = data                # scalar value of this node calculated during forward pass
        self.grad = 0                   # derivative of the loss w.r.t. this node, calculated in backward pass
        self._children = children       # children of this node in the computation graph
        self._local_grads = local_grads # local derivative of this node w.r.t. its children

    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        return Value(self.data + other.data, (self, other), (1, 1))

    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        return Value(self.data * other.data, (self, other), (other.data, self.data))

    def __pow__(self, other): return Value(self.data**other, (self,), (other * self.data**(other-1),))
    def log(self): return Value(math.log(self.data), (self,), (1/self.data,))
    def exp(self): return Value(math.exp(self.data), (self,), (math.exp(self.data),))
    def relu(self): return Value(max(0, self.data), (self,), (float(self.data > 0),))

The Fortress version is an object whose operator methods define +, juxtaposition (Fortress's multiplication: a b means a·b), ^, and the functions log, exp, relu. Each result is built by node(data, (child, ∂/∂child) …): the dependencies are pairs of a child and the local derivative with respect to it, which is exactly the information the chain rule consumes. The pairs are a variable-length argument list (deps: (Value, RR64)...) of a small factory function, because Fortress objects cannot declare varargs constructors.

{{fig:gpt_value}}

Read opr +(self, b: Value): Value = node(data + b.data, (self, 1), (b, 1)) against the first two local derivatives above: the sum's value is data + b.data, and its derivative is 1 with respect to each operand. Multiplication records (self, b.data) and (b, data); the power records n·datan−1; log records 1/data. Python's __radd__/__rmul__/__truediv__ helpers become overloads that accept a plain RR64 on either side; −a, a − b and a / b are derived exactly as in the reference (a·(−1), a + (−b), a·b−1), so the two programs build the same graph.

The backward method is the chain rule verbatim: set ∂L/∂L = 1, visit the nodes in reverse topological order, and for each dependency (c, d) of a node v accumulate c.grad += d · v.grad. Compare with the reference:

    def backward(self):
        topo = []
        visited = set()
        def build_topo(v):
            if v not in visited:
                visited.add(v)
                for child in v._children:
                    build_topo(child)
                topo.append(v)
        build_topo(self)
        self.grad = 1
        for v in reversed(topo):
            for child, local_grad in zip(v._children, v._local_grads):
                child.grad += local_grad * v.grad

The topological sort is the one piece of supporting machinery here. Python keys its visited set by object identity; Fortress's library Set is an ordered set, so every Value gets an integer id from an atomic counter (nextId()), which is what the local function visit records.

{{fig:gpt_topo}}

These 40 lines are the whole autograd engine. A first sanity check, taken from the microgpt article (L = a·b + a with a = 2, b = 3 gives ∂L/∂a = 4, ∂L/∂b = 2) and a finite-difference check on exp(ab) + ln b − a²/b agree with the Fortress gradients to 3·10-10 (the central-difference error; probes/probe11_backward.fss).

Two other shapes for the same node

Before settling on pairs, two other representations were built and run. The Python shape — two parallel lists, children and local gradients — works, but Fortress list literals infer the element type from the literals (<|1, 1|> is a list of integer literals, not of RR64), so every literal needs a static-argument annotation, and the backward pass needs an explicit zip:

{{fig:alt_autograd_lists}}

The original micrograd shape — each node owns a closure that pushes its gradient to its children — also works, and is the most “object-oriented”, but the derivative is buried in imperative code and a function-valued field must be called as (v.propagate)():

{{fig:alt_autograd_closure}}

The pairs form was chosen because it makes the two ingredients of the chain rule — which child and what local derivative — the literal arguments of every operation, and because it typesets without noise.
