## Findings

1. **The compiled code casts `self` where it stands at a type below its trait.** Claim: where an expression has self's type (the checker's `TraitSelfType` with a non-empty list: a trait whose `comprises` clause lists types, or a trait with a self-type parameter) and the declared type is a trait type or a type variable that is a strict subtype of the trait, the code generator emits a cast to the declared type. Conditions: at a single argument of a function, a method or a constructor (`CodeGen.evalArg`), at a typed binding and an assignment (`forExprsSerial`), and at a method's returned value (`generateActualMethodCode`, for a trait's default body, an object's method, a top-level function and a generic method); not where the trait lists a type at a `where`-clause variable. Evidence: `ProjectFortress/src/com/sun/fortress/compiler/codegen/CodeGen.java:7308-7319` and its calls at `:3011`, `:5397`, `:7289`; `compiler_tests/ComprisesValueAtListedTypeCompiled` and `compiler_tests/SelfTypeReturnSelfRun`, each `VerifyError` on the base and `PASS` after; `ant testFast` on `34fb6364d6`: 'Tests run: 1627, Failures: 0', 'BUILD SUCCESSFUL'. Meaning: `trait QQ comprises { Ratio }` of the one library, which passes `self` to `numerator` and `denominator` on 23 lines, no longer fails verification for that reason once a program compiles against it; that is not yet shown by a run, since no program compiles against the one library.

2. **Only `self` gets the reading.** Claim: the compiled checker lets a value stand at a listed type only where the value has self's type; a variable declared at the trait is refused. Conditions: `q: Q = R(1, 2)`, then `den(q)` for `den(r: R)` and `trait Q comprises { R }`. Evidence: `bin/fortress compile` of that program prints 'Could not check call to function den' and 'R->ZZ32 is not applicable to an argument of type Q.' Also `typecase self of Disc => discArea(self)` is refused in `trait Shape comprises { Disc, Square }`: 'Disc->ZZ32 is not applicable to an argument of type (Shape & {Disc, Square})'; with a binder, `c: Disc => discArea(c)`, it compiles and ran on the base. Meaning: the cast's test can read the expression's type alone, and asks the type analyzer nothing at any other argument.

3. **The cast keeps the bytecode of a place that verifies today.** Claim: no cast is added where the value's type is a subtype of the declared type by `extends`. Evidence: `javap -c -p` of every class of a program of such calls, bindings and returns (`takeT(O)`, `t: T = O`, `widen(o: O): T = o`, `up(): T = self`, `takeT(self)` in `trait T`), compiled by the base build and by `34fb6364d6`: `diff` prints nothing over 336 lines. The three jars of the compiler's library hold the same counts on both: `fortress.CompilerBuiltin` 2149 lines with `checkcast` or `castTo` of 15996 instructions, `fortress.CompilerLibrary` 466 of 4620, `fortress.CompilerAlgebra` 1 of 160.

4. **A cast at the checker's type of a `where`-clause size names no class.** Claim: for `mk(): NatParamT` passed to `size[\nat n\](x: Nt[\n\])`, the declared type the code generator sees is `Nt[\n#3\]`, the checker's own variable. Evidence: a form of the cast without the `opensSizes` test turned `compiler_tests/XXXNatOpenRun` from 'VerifyError: Bad type on operand stack' to 'NumberFormatException: For input string: "n#3"'. Meaning: row 307's repair needs the value's own size at run time, not this cast; the landed form leaves the test as it was.

5. **Asking the type analyzer at every argument stops a link that passes today.** Claim: `NodeComparator.compare` of two types with a `bool` static argument throws 'subtypeCompareTo(class com.sun.fortress.nodes.BoolArg class com.sun.fortress.nodes.BoolArg) is not implemented!'. Evidence: `ant testFast` on the first form of the cast, 'Tests run: 1627, Failures: 2', both `XXXBoolStaticArgRun` (its link through `BoolStaticArgRunLink`, and its run). Meaning: a later cast site in the code generator gates on the expression's type before it compares types.

## Revival change

**The change.** The team's code generator emitted no cast where the checker reads `self` as more than its trait: `evalArg`'s single-argument branch evaluated the argument and cast nothing, and a method's body was returned as it stood (`ProjectFortress/src/com/sun/fortress/compiler/codegen/CodeGen.java`, `evalArg` and `generateActualMethodCode` at the team's last commit). The specification gives `self` the type of its trait met with the types its `comprises` clause lists, or with its self-type parameter (`Specification/basic/expressions/var-ref.tex:64-76`), and the compiled checker accepts `den(self)` for `den(r: R)` in `trait Q comprises { R }`, and `twin(self): S = self` in `trait Shape[\S extends Shape[\S\]\]`. The compiled program then failed the JVM's verification when the trait's class loaded: 'VerifyError: Bad type on operand stack ... Type Q is not assignable to R', 'VerifyError: Bad return type'. The tree now casts a value that has self's type to a declared type strictly below its trait, at a single argument of a function, a method or a constructor, at a typed binding, at an assignment and at a method's returned value: `compiler_tests/ComprisesValueAtListedTypeCompiled` and `compiler_tests/SelfTypeReturnSelfRun` run. Three places still fail and are written around by binding `self` at the listed type first, `r: R = self`: a function expression or a local function that returns `self` so (`compiler_tests/XXXComprisesValueFromClosureRun`), a conditional with `self` in one arm and a listed value in the other (`compiler_tests/XXXComprisesValueAtConditionalArmRun`), and a trait that lists a type at a `where`-clause variable (`compiler_tests/XXXNatOpenRun`). A variable declared at the trait, other than `self`, does not stand at a listed type: the checker refuses it. A `typecase` on `self` narrows only through a binder, `c: Disc => f(c)`.
