## Revival change

**The change.** The team's interpreter library declared neither `≡` (`EQV`) nor `≢` (`NEQV`): its boolean operators end at `opr <->(a: Boolean, b:Boolean):Boolean = a=b` (`Library/FortressLibrary.fss:4922` before this change), so walk stopped on `t EQV f` with an internal error, '** bug! Expect all oprefs to be top level EQV', and refused `t NEQV f` before the run, 'Operator NEQV is not defined.' The specification declares `≡` as a method of `Boolean` (`Specification/basic-lib/booleans.tex:252-263`) and `≢` as a generic top-level operator over `BinaryPredicate[\T, ≡\]` (`Specification/basic-lib/Fortress.NegatedOperators.tex:25-35`); the team's compiler library declares both as methods of `Boolean` (`ProjectFortress/LibraryBuiltin/CompilerBuiltin.fsi:465-466`) and a second `NEQV` over `Any` that negates strict equivalence (`Library/CompilerLibrary.fss:71`). The tree now declares `opr EQV(a: Boolean, b:Boolean):Boolean` and `opr NEQV(a: Boolean, b:Boolean):Boolean` as top-level operators of the interpreter's library, after `<->` (`Library/FortressLibrary.fsi:2793-2794`, `Library/FortressLibrary.fss:4923-4924`), so `a EQV b` and `a ≡ b` work on two booleans under walk and compiled against that library (`ProjectFortress/tests/BooleanEquivalenceWalk.fss`; `ProjectFortress/one_library_tests/OneLibraryBooleanEquivalence.test`), and on a program's own objects are a type error: under walk at the call, 'Unification error: Closure/Constructor for EQV param 1 (a:Boolean) got arg Pt of type Pt', compiled statically, 'Could not check call to operator EQV'. The reason: the specification's text gives the operator to booleans ("returns true if both arguments are true or both arguments are false", `Specification/basic-lib/booleans.tex:256-258`), the interpreter's library writes all its boolean operators top-level over two booleans (`Library/FortressLibrary.fsi:2784-2792`), and the compiled path reads that library after the switch-over, where the compiler library's declarations go. Under walk, an equivalence operator that no declaration defines, as `APPROX`, still loads and stops at its call with the same internal error ('** bug! Expect all oprefs to be top level APPROX'; `ProjectFortress/tests/XXXUndeclaredChainOperatorWalk.fss`).
