   The specification lets a nat parameter "appear in any context that a variable of type NN32 can
   appear" (Specification/basic/trait-parameters.tex:82-84) and gives it the type NaturalStatic
   (Specification/basic/expressions/constant.tex:96-97); the revised ranges section makes a
   component of another integer type than ZZ32 a static error (Specification/basic/expressions/ranges.tex:47-48)
   and converts a numeral (:46). The specification's own nat-bounded ranges:

   :1086-1089; Specification/basic/matrix-unpasting.tex:160-161. Under walk a nat parameter is a
   ZZ32 (probes/examples/NatBoundRange-base-walk.txt). Candidates: (a) it converts to ZZ32 as a
   numeral does; (b) it is refused like an NN32; (c) the static-expression chapter decides once
   static expressions are supported. Left unrevised; "Passages not yet revised" says it is open
   (Specification/appendices/changes.tex:1255-1259); ledger row 485 (record.md).
   Pavol's decision of 2026-09-27, a size's range (explorations/coordinator/POSITIONS.md): "A nat
   parameter is an NN32 value and an int parameter a ZZ32 (trait-parameters.tex:82-90); a larger

   does not settle the question; read with ranges.tex:47-48 it can be read as candidate (b).
   Measured by the skeptic: the compiled run accepts seq(0#n) and 1:(n-1) for nat n = 3 (3 and 2
