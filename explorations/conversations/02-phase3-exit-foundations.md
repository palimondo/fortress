## 3. Row 816 and P-158 (10-25 19:06 to 10-26 04:28)

**The argument, in the order he asked for it (19:35:13):**

1. *The two paths call a method differently.* Walk finds a method on the object by name at the call; the trait need not declare it. The compiled path calls through the trait's Java interface; if the trait does not declare the method, the call dies with `NoSuchMethodError`.
2. *The team's two libraries each followed their path.* The compiler's prelude: the api writes `abstract loop(body: ZZ32->()): ()` in `GeneratorZZ32`; the component restates `loop(body: ZZ32->()): ()` with no body; the objects give the body (`Library/CompilerLibrary.fsi:112-120`, `.fss:301-312`). The team's export check enforced it (its count written by Sukyoung Ryu, `ac0d41de0`, 2009-05-08; first written here as Chase's of 2012, `5a68404fd`, a parentless snapshot): a component trait with fewer members than its api trait is refused. The interpreter's library, written for walk and never compiled by the team, sometimes leaves an api's `abstract` member out of the component's trait (`String`'s `split`), and walk does not care.
3. *What the revival changed.* When the checker read the interpreter's library, the team's check refused 12 such members. Two ways: (a) add the 12 declarations to the components, the compiled library's way; (b) weaken the check. Climb batch 21b's rung E took (b) (`031c38bbc`), from a misreading of `apis.tex` ("includes definitions for all declarations other than … abstract" read as "needs no member", where it says "needs no body"). The chain: an Opus ways worker of 10-20 (`reviews/array-sites-ways.md`, "4i", "Decision: none, since it is the text's own rule"); the export probe of 10-23 built it; batch 21's planner made it fork 20 with the default "the team's own text"; its Fable review and I passed it as not consequential; rung E built it; its skeptic found the `NoSuchMethodError` after the build; the 21b review kept it as "it cannot happen yet"; batch 22 carried it as question 1 and I launched batch 22 at about 02:01 on 10-24 without sending him the question. Root cause: one sentence misread; nobody read the code it changed (the team's deliberate count) or asked what a compiled call does; the change cleared errors, which was the batch's goal.
4. *The fix (his option 2).* Restore the team's count; add 12 bodyless declarations to five component traits (`String` 7: `depth`, `isBalanced`, `verify`, `rangeContains`, `balanced`, `splitWithOffsets`, `split`; `Range`'s `isEmpty`; `ReadableArray`'s `opr[_:TrivialOpenRange]`; `ActualReduction`'s `empty` and `join`; `AnyMaybe`'s `holds`).
