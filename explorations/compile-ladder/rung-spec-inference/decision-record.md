## 2. What the revision states, and what it does not

The chapter (`Specification/basic/inference.tex:15-236`) states, for a call of a function, a method, an operator or a constructor whose declaration has static parameters and whose static arguments are not written, and for type parameters and `nat` and `int` parameters only (the scope sentence, `:19-25`, since the repair round):
- **Choice** (`:60-69`): the declaration is chosen as `\secref{resolving-coercion}` describes (cited, not restated); a declaration with static parameters is applicable, with or without coercion, if some instance within its bounds is; declarations are compared on their declared parameter types, quantified over the instances their bounds allow, not on an inferred instance; so a coercion never changes which declaration is chosen when one applies without it.
- **Instantiation** (`:71-106`): a type, `nat` or `int` parameter mentioned inside a parameter type is fixed by that argument by subtyping (`:75-79`); a type parameter mentioned inside the declared return type is fixed by the expected type too (`:80-82`); a type parameter that is the whole type of parameters takes, among its arguments' types and the types they can be coerced to, the narrowest under `⪯` that every argument is substitutable for and its bounds permit; for number arguments the narrowest type every one converts into (ZZ64 for ZZ32 with ZZ64, and for ZZ32 with NN32); otherwise, unless the numeral rule settles the tie, the union of the arguments' types if the bounds permit, with no conversion; every argument admitted by substitutability against the instance's parameter types, coerced where it is not a subtype; the coercions inserted statically.
- **The expected type** (`:108-134`): the contexts that give one (`:109-116`: the right-hand side of a variable or field declaration that declares its type, the right-hand side of an assignment to a variable whose type is declared, a functional's body against its declared return type, a block's last expression where no local declaration precedes it, both branches of an `if` with `else`); used at a call written by tight juxtaposition `f(x)`, a method invocation or an operator application; the instance's return type must be a subtype of it, and failing that the inference runs again without it and the call is accepted only if the result is a subtype of or coerces to the expected type, the result then coerced. Two examples: `a: List[\ZZ64\] = wrap(3)` (T fixed by the expected type, the numeral coerced) and `b: ZZ64 = id(3)` (the numeral's own type, the result coerced).
- **Dispatch** (`:136-139`), in the judgement's words: the converted call dispatches at run time by subtyping, without further coercion, to the most specific declaration applicable to the converted values. One example (`:141-148`): `op(z, w)` with `op[\T extends Number\](a: T, b: T)` and `op(a: Any, b: Any)` chooses the generic declaration, instantiates it at ZZ64 and coerces `z` (`OpAnyZW`'s shape).
- **A numeral whose conversions tie** (`:162-185`, `\seclabel{numeral-default}`), once: read as ZZ32, or ZZ64 or ZZ by its value, in either step; two examples (`g(0)` over `g(x: NN32)` and `g(x: ZZ32)` takes the second; a type parameter only numerals fix, bounded so that ZZ32 and NN32 satisfy its bounds and the numeral's type does not, takes ZZ32); the rule ranks nothing else, and a non-numeral argument that leaves declarations applicable only with coercion tied makes the call a static error.
- **What it does not yet describe** (`:187-210`): the static arguments of a `bool`, `dim`, `unit` or operator parameter (`:189-190`, since the repair round); a static parameter nothing fixes (a result-only type parameter, a reduction's element type), with the BottomType question left open; whether an argument that fixes a parameter through a structure may be converted; an expected type in any other context (an argument, an expression after a local declaration, an `if` without `else`, `typecase`, a `for` body, loose juxtaposition `f x`); a generic object named without a call; whole-program inference of elided types.
- **Three callouts** (`\revision{revival-inference}`): after the chapter's opening paragraph (`:26-51`: the Working Draft's notes, the dates, the new numeral rule, the bound Any assumed where `\secref{type-param}` says Object and the compiled path's row 412 takes Object, the overloading chapters' sentences and the naked-Any rule left to the revision of the overloading chapters, the later Types chapter silent on inference); after the dispatch example (`:149-160`: the interpreter); after the not-described list (`:211-224`: for a type parameter only the return type mentions and that the expected type does not fix, the compiled checker binds it to BottomType except that it refuses a call with no expected type when the parameter is declared `extends Any`, and the interpreter erases such a parameter of a function to BottomType and leaves a generic method's uninstantiated, rows 21, 424, 425, 447 (the second skeptic's RC1, made at the gather); neither implementation infers a `bool` parameter, the checker refusing a `bool`, `dim` or `unit` one by name and the interpreter not unifying a `bool` one, rows 21 and 307; the Working Draft's `bool` example of `\secref{boolparams}` applicable only if its argument fixes the parameter).
- **The team's second draft note** (`:226-236`), kept word for word at the chapter's end; its BottomType question stays open (row 447).

It does not state: the inference of a `bool`, `dim`, `unit` or operator parameter (L26); a size a call cannot fix (answer 12; L25), nor a size fixed through the expected type; how declarations with static parameters are compared in detail (the overloading chapters' revision, L1); which type a structured argument could be converted to (row 432); the walk-only details of K's implementation beyond its callout; the compiled path's run-time instantiation of a dispatched generic declaration (rows 493 to 496; decision 7 below).

The ranges section (`Specification/basic/expressions/ranges.tex:46-58`) states that a `nat` or `int` parameter used as a component converts to ZZ32 as an integer numeral does, the static error kept for any other component; its callout (`:51-58`) says why and how both paths run it.
