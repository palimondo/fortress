## Revival change

**The change.** The team's code generator emits a conditional's arms and a function expression's result with no conversion (`ProjectFortress/src/com/sun/fortress/compiler/codegen/CodeGen.java`, `forIf` at `:3813` and `forFnExpr` at `:3423` in the team's last commit, `a874948ac`), and the team's class loader, to choose a call's opcode while it instantiates a template, loads and initializes the call's owner class (`ProjectFortress/src/com/sun/fortress/runtimeSystem/MethodInstantiater.java:238` there). The tree casts a value of self's type at each arm of a conditional and at a function expression's or a local function's result, where the target type lies strictly below self's trait, and reads the owner's class file to choose the opcode, loading no class. So, compiled, a conditional with `self` in one arm and another value in the other runs at a type that self's trait's `comprises` clause lists and at the trait's self-type parameter (`compiler_tests/ComprisesValueAtConditionalArmRun`, `compiler_tests/SelfTypeArmRun`), as does a `case` expression's clause; a function expression or a local function that returns `self` there runs (`compiler_tests/ComprisesValueFromClosureRun`, `compiler_tests/SelfTypeFromClosureRun`); and a default body that calls a method on a value of the self-type parameter runs where the object lists the trait first (`compiler_tests/SelfTypeParameterReceiverRun`). A `typecase` with `self` in one arm and another value in the other still fails the JVM's verification when its class loads (`compiler_tests/XXXComprisesValueAtTypecaseArmRun`); its workaround stays: bind `self` at the target type in the arm. The reason: the specification types `self` as `T ∩ (U1 ∪ … ∪ Un)` under a `comprises` clause and as `T ∩ X` in the bodies of a trait with a self-type parameter `X` (`Specification/basic/expressions/var-ref.tex:64-80`), the checker accepts these bodies, and on the code before the change each failed when its class loaded: 'java.lang.VerifyError: Bad return type' for the arms and the closures, and 'java.lang.ClassCircularityError: …$Pt' for the default body. The skill's statement of the three failures and their workarounds (`.claude/skills/fortress-repo/references/revival-changes.md:43-47`) holds no longer, but for the `typecase`.
