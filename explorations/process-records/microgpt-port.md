## Timeline

1. Target selection, 2026-08-23T21:33–22:01. The round grew out of a language-comparison conversation (JVM value types, Graal/Truffle, LLVM) when Pavol asked whether "the Fortress syntax [would] be ideal for expressing the AI algorithms in as close to mathematical notation as they are described in papers", then "Nanogpt in Fortress?". The thread sized nanoGPT as three different asks, Pavol corrected himself toward Karpathy's pedagogical line, and the thread's dating of micrograd/minGPT/nanoGPT/llm.c was challenged; a `WebSearch` corrected nanoGPT to 2023 and surfaced microgpt (2026-02-12) as the current, scalar-autodiff member of the family — which became the target because it needs no tensors.

2. Feasibility map, 22:01–22:06. The blog post was fetched with `curl` and the source recovered by regex over its `<pre>` blocks after `raw.githubusercontent.com/karpathy/microgpt` returned nothing for either `master` or `main`; the library was then inventoried against the program's needs (`Random.fsi`, `Shuffle.fsi`, `List`, `File.fsi`, `FortressLibrary.fsi` for `log`/`exp`/`SEQV`/`Char`). Result: `explorations/microgpt-port.md` and goal 6 in `CLAUDE.md`, commit `633a654d6`, with five named gaps — no gaussian sampler, no weighted sampling, no identity-hashed set for the topo sort, the `names.txt` fetch, and two "verify, not assumed" items.

3. Presentation of the map, 22:20–22:24. The map was rendered as an HTML artifact after loading the `artifact-design` skill; Pavol's reply — "Re-read protocol! I just needed you to link MD as artifact, so that I don't have to squint at diff on mobile, didn't need HTML, but OK" — was accepted as a protocol §3 miss, and the lighter form adopted for plain review docs.

4. CPython baseline, 22:24–22:29. The assembled `microgpt.py` was run in the container: 32,033 names, vocab 27, 4,192 parameters, 1000 steps + 20 samples in 120.3 s (~0.12 s/step), loss 3.3660 → ~2.3 band. Two side answers were settled here and written into the map: the original ships no tests, so goldens had to be manufactured; and the compiled path was ruled out for this port because `CompilerLibrary` is a 592-line skeleton against `FortressLibrary`'s 4,518 lines. Commit `4b9b1b926`. The assembled `microgpt.py` was deliberately kept out of the repo (blog code, no license statement).

5. Adversarial pass and step-0 microbenchmark, 22:38–22:48. The pass found five holes and rewrote the risk section: floating-point association (Python's `sum()` is a left fold, Fortress reductions are trees and loops parallel by default) became the top correctness trap and forced a sequential reference port; transcendental ulp drift set the 1e-9/1e-6 tolerances; golden weights were made RNG-free by a deterministic formula; the relu-at-zero and literal-syntax details were pinned; and the performance risk was split into four separately measured costs. `explorations/mgbench.fss` measured them: ~45k loop iterations/s, ~10k `Value` nodes/s, ~2.8k backward-walk nodes/s, projecting ~20 s/step at Karpathy's defaults and 5–6 h for the full run, so the nano config was adopted and node fusion promoted from reserve to likely.

6. Stage 1, `micrograd.fss`, 22:48–22:53. The `Value` object with `opr` overloading, a visited-flag topo sort in place of Python's identity set, analytic golden gradient checks, and a 2→4→1 relu MLP on XOR. The first run collapsed at loss 1.0000035902502540; a Python twin of the same graph collapsed identically, and the same bias-init change cured both. The headline result recorded in the map is that the Fortress and Python trajectories are identical to all 16 printed digits at epochs 100–400, which upgraded the golden strategy from tolerance bands to exact equality for +/·/relu graphs. Commit `352fdd6b0`.

7. Stages 2–3, `microgpt.fss`, 22:55–23:16. A deterministic Python generator produced golden logits, loss and gradients at reference dims (vocab 5, n_embd 4, block 4); the full port — tokenizer, Box–Muller init, KV-cached multi-head attention, Adam with bias correction and linear LR decay, temperature sampling — was written in one pass and then debugged against six successive interpreter refusals (phase 8). The nano training run was launched in the background and a Python twin at the identical config was measured at 22 ms/step, giving the comparison bar.

8. Six interpreter refusals, 22:59–23:05. Five were the bare diagnostic `Syntax Error` with only a line:column — `microgpt.fss:58:5`, `:178:11`, `:246:55`, `:246:56`, `:255:37` — each diagnosed by inspection and fixed by a scripted edit (`at` → `el`; the Box–Muller expression re-parenthesized; `(1.0 - beta2) (p.grad^2.0)`; the `mBuf`/`vBuf` update lines; `THEN` → `then`). The sixth was explicit: `microgpt.fss:102:1-104:66: GPT is not a valid object name.` — all-caps identifiers are operator names — fixed by renaming to `Gpt`.

9. The `names.txt` reader, 23:00–23:05. The first reader used `FileReadStream.lines()`; the run produced no output in 300 s and was killed (`Exit code 143 / Terminated`), the reading being that `lines()` walks all 32k lines through the interpreter regardless of `maxDocs`. Replaced with an early-terminating `readLine()` loop, after checking `File.fsi` for the EOF surface.

10. Fortify figures, 23:16–23:19. Three `.tic` sheets (the `Value` object; rmsnorm + softmax; the attention core) were built on the existing `explorations/fortify/buffons-excerpt.tic` pattern and `bin/fortick`, rendered to light SVG, converted to dark by a `sed` on the `<svg>` tag, and rasterized and looked at as PNGs; the attention sheet was re-cut once after inspection.

11. Chart and page, 23:18–23:23. The `dataviz` skill was loaded and its palette validator run (a first blue/green pair was rejected, `#2a78d6,#eb6834` validated in both modes); a two-series loss chart generator and an assembly script were written and smoke-tested end to end on the partial training log (~560 KB page with six SVGs inlined). The stop hook fired on untracked files and the port, dataset and figures were committed mid-flight as `5f7a31960`.

12. Completion, 00:01–00:06. Training finished (45.4 min); the page was assembled, screenshotted headless and inspected, one label collision at the line ends was fixed by swapping vertical offsets, and the page was published as "A GPT You Can Read". The map's four staging items were ticked (commit `1471048f0`), a push notification was sent, and the Fortify `.tex`/`.pdf`/`.dvi` byproducts were deleted after a second stop-hook complaint.

## Gaps found

The run produced no gap table in the later sense. `explorations/microgpt-port.md` has a "Gaps — all small, all writable in .fss" section with five numbered items (no gaussian sampler, no weighted sampling, no identity-hashed visited set for `backward()`, the `names.txt` fetch, and two verify-not-assumed items), all framed as library gaps closable in Fortress source rather than language gaps; the language-level findings of the run are recorded as prose inside the staging entries — no `E`-notation numerals, `log`/`exp` are functional, `ZZ` division is exact (`DIV`), `at` reserved, all-caps identifiers are operator names. The merged ledger `explorations/fortress-gap-ledger.md` did not exist at the time (created 2026-09-08, commit `b9c8ee33e`), so no row of this run was in it; all were new.

## Findings

The run set its correctness anchor before writing any Fortress code: it measured the original in CPython first, established that microgpt ships no tests, and manufactured goldens from a deterministic no-RNG weight formula, so every later stage had a pass/fail rather than an impression. The adversarial pass Pavol asked for changed the design rather than decorating it — the floating-point-association finding forced a sequential-everywhere port in a parallel-by-default language, which is the single decision the rest of the round rested on. Navigation of the library was done entirely by `grep` over `Library/*.fsi` and the in-tree tests: `Random.fsi`, `Shuffle.fsi`, `File.fsi`, `ArrayListQuick.fss` for timing idioms, `claude_demo.fss` for component conventions, `explorations/fortify/buffons-excerpt.tic` and `bin/fortick` for the figures; the specification LaTeX was never opened, a fact a later audit quantified for this and the following rounds. Time was lost in two places only: six interpreter refusals in six minutes, five of which reported nothing but `Syntax Error` and a line:column and had to be diagnosed by reading the source; and the `lines()` reader, which cost a 300-second timeout before the early-terminating rewrite. The prior work in the tree was used as pattern, not as text: the port reuses the repo's `.fss` conventions and the existing Fortify pipeline unchanged, and the only thing it had to invent was the visited-flag topo sort standing in for Python's identity-hashed set. The staging order — microbenchmark, then `micrograd.fss`, then the golden-checked forward pass, then the full program — meant the throughput verdict (~20 s/step projected at Karpathy's defaults) arrived before the port existed and set the nano config that made a same-evening training run possible. The bit-identity result between Fortress and Python, including a shared failure and a shared fix, is the round's strongest evidence and was obtained as a by-product of debugging rather than as a planned experiment. The result relative to effort: about two hours of one context produced a 292-line running program, three typeset figures, a measured 496× gap against CPython, and a published page, with the whole notation question — how close the code gets to the literature's formulas — left untouched, which is what the next round was called to fix.
