8. What the language gives, what we added, where the mismatches remain

Given by Fortress

  • Operators as library code. +, juxtaposition, ^, DOT, || are ordinary operator declarations (opr), so a user type takes part in arithmetic notation with the same precedence and typesetting as numbers. Juxtaposition being multiplication is what makes W x, alpha V, scale x and n data^(n-1) read as formulas.
  • Generators, reductions, comprehensions. Every collection is a generator; SUM[i <- g] e, BIG MAX, BIG || and ⟨ e | x ← g ⟩ desugar into a generator's generate with a reduction object; the same desugaring makes iterations implicitly parallel. Adding a big operator for a new type is a seven-line reduction object plus a two-line operator.
  • Traits with default behavior. DelegatedIndexed gives Vec the whole generator protocol from a handful of delegations; CommutativeMonoidReduction and MonoidReduction supply the reduction plumbing.
  • Static sizes and nat arithmetic exist (Array1⟦T,0,n⟧, d+d) and were used in the first design.
  • Fortify. Subscripts, Greek letters, hats, blackboard types, the big operators with their bindings, fractions for 1/data, and √ are all produced from the ASCII source.

Added at user level (all shown in the figures above)

  • the autograd Value with 13 operator/method definitions, the node factory, three mixed-operand operators, topo, the id counter;
  • SumValues + the two ∑ operators, after hiding the library's ∑ with an except import;
  • Vec (six delegations, six operators), CatVecs + BIG ||, Mat (four subscripts, entries, two juxtapositions), relu on vectors, and two sequence-lifting helpers.

Line counts of the primary program (non-blank, non-comment): mathematical core — Value operations 27, Vec 20, Mat 9, rmsnorm 5, softmax 6, layer 25, model 9, loss 6, Adam 16, sampler 12; supporting machinery — topological sort 12, ∑ 7, ids/imports/headers 21; smoke test 27.
