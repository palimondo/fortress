## Findings

1. **The compiled checker's Return Type Rule counts, at an object type, only the instances whose domain meets.** Claim: for `f` more specific than `g`, `satisfiesReturnTypeRule` reads a type parameter `T` of `g` that the domains do not force, where `T` is a whole parameter type of `g` and `f` has an object type `C` at that position, as `T ∪ C` in `g`'s domain and return type; every other instance is compared as before. Conditions: `C` is an object type, with or without static arguments, or the self type of one; a parameter inside a static argument, a size, and a position where `f` has a trait, a tuple or a function type are unchanged. ## Revival change

**The change.** The team's compiled checker tested the Return Type Rule at one instance of the less specific declaration, the solution of the domains (`ProjectFortress/src/com/sun/fortress/scala_src/overloading/OverloadingOracle.scala:81-95` at a874948ac), and so accepted `ident[\T\](x: T): T` beside `ident(x: Circle): Circle`, `Circle` an object; the team's code generator returned an arm's result from the dispatcher without a cast (`ProjectFortress/src/com/sun/fortress/compiler/OverloadSet.java:1865-1866` at a874948ac), and the class of the generic declaration's instance at another object type failed the JVM's verification, `VerifyError: Bad return type`. The tree now compares every instance of the less specific declaration whose domain meets the more specific one's: where the more specific declaration's parameter type is an object type and the other's is a type parameter, only the instances at which the parameter holds the object. It accepts the pair, refuses `g[\T\](x: T): T` beside `g(x: Circle): String`, and the dispatcher casts an arm's result to its range where that range is a static parameter, so the pair runs and each call runs the most specific declaration that takes its argument. Tests: `ProjectFortress/compiler_tests/OverloadReturnObjectDomain` (accepts, runs) and `XXXOverloadReturnObjectDomainOtherType` (refuses). The reason: the Return Type Rule speaks of argument types other than `BottomType` (`Specification/advanced/overloading.tex:555-559`), an object trait type excludes any type that is not its supertype (`Specification/basic/types-vals-vars.tex:288`), and the type group's paper sets aside the instances of the special arrow whose domain is `Bottom` (`Papers/Types/overloading-check.tick:180`); the verifier's refusal is quoted in the report.
