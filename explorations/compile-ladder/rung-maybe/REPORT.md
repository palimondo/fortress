## 5. The decision

**The specification's spelling of the empty case was taken, not the corpus's**: `Maybe[\T\] comprises { Just[\T\], NothingObject[\T\] }` with `coerce(_: Nothing) = NothingObject[\T\]` and a separate `value object Nothing end`. This was a decision, and the code did not force it.

**The two candidates cannot coexist, measured.** `probes/DualNothing.fss` declares both spellings of one name in one scope under local names — `value object NothingD[\T extends Any\] extends MaybeD[\T\]` and then `value object NothingD end`. `probes/DualNothing.txt`: the non-parametric declaration takes the name, and both the parametric declaration's own header (`:16`) and the `comprises` clause that mentions it (`:8`) become errors — "Incorrect number of static arguments for type 'NothingD': provided 1, expected 0". So the fork is binary and there is no overload that serves both spellings.

**Why the specification cannot simply be transcribed.** `probes/WhereClauseNothing.fss` is `convenience.tex:49` under local names — `object NothingW extends MaybeW[\T\] where {T extends Object}`. `probes/WhereClauseNothing.txt` records the same single error from `fortress compile` and from `fortress walk`, both rc=255: `T is undefined`, at the `T` inside the extends clause. Name resolution does not let a where clause bind a type variable used in an extends clause, on either path, so neither implementation can express the declaration the specification writes; `CodeGen.java:4088` (`forObjectDeclPrePass`, `header.getWhereClause().isNone()`) would refuse it at codegen even if name resolution admitted it. The compensating mechanism is coercion, which the compile path has and the interpreter does not (`explorations/coordinator/map/spec-to-implementation.md:288`: "nothing: no occurrence of `Coercion` or `coerce` anywhere under `interpreter/`"). That is why the team's draft for this world spells the empty case as it does and the interpreter's prelude does not: the interpreter had no way to write it, and said so at `FortressLibrary.fss:1340-1341`.

**What decided it.** Three things point one way. The prose says `Nothing` is one object (`convenience.tex:49`) and uses it as a value at a `Maybe[\String\]` (`exceptions.tex:122`). The team, writing for *this* world, chose that shape (`CompilerLibrary.fsi:217-229`) and used it in all seven of its own draft tests. And the interpreter's own author records that the parametric form is a workaround for a missing feature, not the design. The compiler world has the compensating feature, and `probes/MaybeCoercionSites.txt` records it working in all three positions the specification writes an unparameterised `Nothing` in — a declared-type binding, a getter's default, a function argument — with `typecase` confirming the coerced value is a `NothingObject[\ZZ32\]` at run time. Against that stands corpus usage, which is evidence of what was written, not of what the language is (rule 4).

**The alternative and its cost.** Taking the corpus's `Nothing[\T\]` would clear `ExceptionScoping.fss` and `oddJuxt.fss` now — both name nothing else the compile path lacks — and would spare the later library route the renames in `List.fss`, `Set.fss`, `Map.fss` and `PureList.fss`. Its cost is that `= Nothing`, the only spelling of a `Maybe` value the prose chapters ever write, would be a static error in the compiler world for good, and this world would carry the interpreter's acknowledged workaround for a feature it does not need the workaround for. The library route is a reserved fork and those files will be rewritten line by line when it opens; `convenience.tex` will not be rewritten. Two ladder files whose spelling the specification does not sanction were judged the smaller loss, and they are not lost silently: they become the provisional ledger row in `record.md`, which names the spelling, both probes, and where the fix lies.

**A second decision: beside `Option`, not over it.** `Maybe` is a second copy of the `Condition` protocol rather than built on `Option`. Three ways to build it over `Option` were considered and rejected. Making `Maybe[\T\]` extend `Option[\T\]` fails because `Option` is declared `comprises { NoneObject[\E19\], Some[\E19\] }` (`CompilerBuiltin.fsi:650`) and a `comprises` clause is closed, so it would have to be widened — a change to a declared type the prelude already has, which `CLIMB-BATCH-1.md` reserves as a stop. Making `Just`/`NothingObject` wrap a `Some`/`NoneObject` field would put an indirection and an allocation under every method to save one-line bodies. A type alias is not available: `Specification/fortress/preamble.tex:81` lists type aliases among the features not yet supported. The copy costs 56 lines of one-line bodies in `CompilerLibrary.fss`; that was judged cheaper than any of the three, and it is also what the team's draft does — its `Maybe` extends `Condition[\T\]`, not `Option`.

**A third, smaller: the commented draft was replaced, not left beside the live code.** `CompilerLibrary.fsi:217-229` now holds live declarations in place of the comment. Leaving the comment beside working declarations of the same names would be a stale second answer in the source, and `explorations/protocol.md` keeps rationale out of the tree. The draft is quoted in full in §4 of this report and recoverable at `git show cb242a2d8:Library/CompilerLibrary.fsi`, so nothing is lost.

## 7. Deviations

1. The specification's single `object Nothing extends Maybe[\T\] ... where {T extends Object}` (`convenience.tex:49`) becomes `value object NothingObject[\T\] extends Maybe[\T\]` plus `value object Nothing end` plus `coerce(_: Nothing) = NothingObject[\T\]`, because that declaration compiles on neither path (`probes/WhereClauseNothing.txt`) and `CodeGen.java:4088` refuses a where clause on an object in any case. The semantics are preserved at all three positions the specification uses the value in (`probes/MaybeCoercionSites.txt`); the spelling `Nothing[\T\]` is not preserved (the ledger row).
2. The specification writes `object`, this writes `value object`, for `Maybe`, `Just`, `NothingObject` and `Nothing` alike — following `Option` (`CompilerBuiltin.fsi:649-661`), the interpreter (`FortressLibrary.fss:1306-1342`) and the draft (`CompilerLibrary.fsi:217-229`), all three of which make the type a value type. The draft writes plain `object Nothing end` (`:229`); `value object None end` (`CompilerBuiltin.fsi:661`) and the team's `GenTest4.fss:454` write `value`, and `value` was taken.
3. The specification's `object Just[\T\](just: T)` (`convenience.tex:51`) names the field `just`; this names it `x`, after `value object Some[\E20 extends Any\](x: E20)` (`CompilerBuiltin.fsi:657`), the draft's `Just[\T\](x:T)` (`CompilerLibrary.fsi:223`) and the interpreter's `Just[\T\](x:T)` (`FortressLibrary.fss:1312`). Three precedents against one, and the field is not read by name from outside.
4. The specification's `isNothing: Boolean` (`convenience.tex:47`) is a field declaration in a trait; this writes `getter isNothing(): Boolean`, the form every member of `Condition` and `Option` is written in (`CompilerBuiltin.fsi:622-655`) and the form `exceptions.tex:122` itself expands the `settable message: Maybe[\String\]` of `:68` into.
5. `Maybe` extends `Condition[\T\]`, which `convenience.tex:46` does not; the draft (`CompilerLibrary.fsi:217`), the interpreter (`FortressLibrary.fss:1307`) and `Option` (`CompilerBuiltin.fsi:649`) all do, and it is what makes a `for` over a `Maybe` work.
6. The specification's `excludes Just[\T\]` on `Nothing` (`convenience.tex:49`) is not written, and neither is any `excludes` clause; `Option` has none either (`CompilerBuiltin.fsi:649-661`), and the exclusion is implied by the closed `comprises` clause.
7. `opr SQCAP` is declared as a comment, not live — as on `Option` (`CompilerBuiltin.fsi:652`) and in the draft (`CompilerLibrary.fsi:220`). It is the interpreter's semilattice meet (`FortressLibrary.fss:1309`); no prose chapter declares it on `Maybe` (`grep -rn SQCAP Specification/basic/ Specification/basic-lib/ Specification/advanced-lib/` finds it only as an operator parameter in `advanced-lib/algebraic-constraints.tex`), and `library_tests/MaybeTest9.fss:66-68` has the team's own `SQCAP` assertions commented out.
8. The coercion is declared once, on the trait; the draft declares it twice, on the trait at `CompilerLibrary.fsi:219` and again on `NothingObject` at `:227`. `Option` declares it once (`CompilerBuiltin.fsi:651`), and once is what works.
9. `AnyMaybe` (`FortressLibrary.fss:1292`), `UniqueItem` (`:1380`) and `NotUnique` (`:1388`) are not declared. Rung 2 already recorded that the compiler world has no referent for `AnyMaybe` when it ported `HasRank` (`CompilerLibrary.fss:552-555` at the base commit); `Library/Set.fsi:65` will need it when the library route opens, and that is that fork's work.
