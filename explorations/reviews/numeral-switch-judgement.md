# The numeral switch under walk: which shape keeps the decision at the least risk

## 1. The question

Pavol decided on 2026-09-27 that a numeral (an integer written in the program, such as `3`) gets a type of its own, `IntLiteral`, that each number type converts from, in the one library and in walk, the interpreter (POSITIONS 2026-09-27, a numeral's type). Batch N's second run, rung Q, was to build it. Probe Q measured the switch under walk first and found that it changes 59 test verdicts, 24 of them failures that no small device repairs, and asked which shape the rung should take. This judgement answers that, and what it means for the queue.

The decision itself is not in question. What is in question is how walk is brought to it, and when.

## 4. The judgement

### 4.1 The model is right, and the decision stands

The specification's design is that numerals are polymorphic and are not converted to any number type until used, "as in common mathematical usage", with the library defining the coercions (`Specification/basic/expressions/literals.tex:127-148`); the numeral hierarchy itself was never written (`:83-95`, "We need to describe the Numeral type hierarchy"). The team's compiled library built the working version in 2009: `IntLiteral` a sibling under `Number`, a coercion into each integer type. The one library's `object IntLiteral extends ZZ32` is the team's placeholder, with its arithmetic commented out "until coercion is implemented" (`FortressBuiltin.fss:497-498`). Coercion is now implemented in walk (batch 4's rung C, batch N's rung K). The team's condition is met.

The warning's consequence, R8's question, is measured: under the switch `3 + 4` is `7 : IntLiteral` and `2147483647 + 1` is `2147483648 : IntLiteral`, no overflow (`PROBE-Q.md` section 5). Arithmetic among bare numerals stays on numerals, exact and unbounded, and lands on a number type at the first typed binding, parameter or operand. That is the specification's intent, not a defect, and microGPT's values do not move. The library's own numeral sites hold: the two strides sum as before, `0 MAX (index - 1)` answers `ZZ32`, the empty sums answer at their types.

So nothing in probe Q argues against the decision. What it shows is where walk cannot follow it yet.

### 4.2 The walk half meets the limit Pavol already accepted on 2026-09-29

R7 (POSITIONS 2026-09-29, walk's run-time choice of coercions): walk has no static types, so it chooses a coercion on the value where the compiled path resolves it statically; accepted as the interpreter's limit, "one now and two after the switch", walk to be matched once the checker runs on interpreter programs after the switch-over and walk takes the static coercions the checker inserts.

The second group of section 3 is the same limit under another name. `<|1, 2, 3|>` at a `List[\ZZ32\]` parameter is typed by the checker from the parameter; walk builds it from the values and gets `List[\IntLiteral\]`. `getDefault(0, 0, 0)` at an instance walk built from `ZZ32` values gets `(Int, Int, Int)`, into which a numeral does not convert. When walk takes the checker's static arguments and coercions, each of these is settled by the same insertion R7 waits for, with nothing built for it in walk. Building it now, as option 1 asks (row 364's repair beside the devices), writes into walk's inference from values an approximation of static typing that the switch-over then replaces, and by the probe's own reading still does not match the checker. That is work the goal does not need: microGPT's values are unchanged under the switch, its static types are concrete, and rows 79, 443, 454 and 437 are agreement rows between walk and the compiled path, on no path to microGPT compiled.

So the walk half of rung Q waits, for the same reason and to the same point as R7's second step. This keeps the decision (walk switches to `IntLiteral`) and moves its date, on evidence he did not have on 2026-09-27.

### 4.3 The library half does not need to wait, and should not

The one library's `IntLiteral` model is what the compiled path needs at the switch-over: when the compiler's prelude is deleted and its tests kept (PLAN phase 4), tests that rely on a numeral's own type (`typecase` answering `other`, `litCoercion`, `NumeralTest`) keep their verdicts only if the one library carries the sibling. On the checker the model costs nothing once `ZZ32` states its four comparisons on itself: 623 against the landed 627, the four fewer being the old `IntLiteral`'s two getter errors and the stage's run-to-run variation (section 2). It closes row 454's integer half on the checker's side (the one library accepts `a: NN32 = 3`) and gives the checker the model rung I's numeral tie rule assumes.

It can land with walk's numeral unchanged. Under walk today every numeral that fits a `ZZ64` is an `Int` or a `Long`, so the sibling `IntLiteral` and its enabled arithmetic are reached only by a numeral below -2^63 (section 2, second addition), and the plan-6.5 probe's three loading stops were all numerals reaching library sites as `IntLiteral`s, which no longer happens. The expected change to walk's outputs is zero; the rung's comparison confirms it or lists what it finds.

Its place is batch 8's library work, beside R9's `NN32` into `RR64` coercion, for the reason R9 was put there and not in 7b's overloading rungs: a new coercion changes which calls need one (POSITIONS 2026-09-29, R9). Seven new coercions and a coerce on `AnyIntegral` are that kind of change, and 7b's rung L reads the library's overload families on the base it is cut from.

### 4.5 The `=` device

Under walk today `i = 0` for a `ZZ32` `i` is `ZZ32`'s own `=` at 1x. Once a numeral is an `IntLiteral`, `Number`'s `=` (rung F's, `Library/FortressLibrary.fss:361-371`) fits as it is and runs: 13x through `exactValue`'s two rational conversions, 5.4x through a promoting `=`. The compiled library's shape, no catch-all `=` on `Number`, cannot be built within rung Q's files: the team's top-level `opr =(a: Any, b: Any)` (`:96`) then takes the call and answers false through `SEQV`.

Judgement: the numeral case in `exactValue` goes into Q-lib now, as the correct answer at one line, unpaid while walk's numeral is an `Int`. Which shape walk runs is Q-walk's question, and by then it may be moot: once walk takes the checker's static coercions, `i = 0` is rewritten to `ZZ32`'s `=` before it runs, the compiled path's own resolution, and the catch-all is reached only by a comparison the checker cannot resolve statically. If it is not moot, the promoting `=` is the measured cheaper correct device, and the choice is phase 6's (POSITIONS 2026-09-19, no performance decision before microGPT runs compiled). One flag for Q-walk's brief: probe Q's microGPT checks under the `exactValue` device ran in 84 min and 71 min against probe K's stock 60 min at a different load, no comparison; Q-walk measures the pair in one run, since the walk checks are what every later rung's microGPT stage pays for.

### 4.8 What could go wrong

- The switch-over's "walk takes the checker's static types" step is R7's plan and is not designed. If it is cut, or comes late, Q-walk needs option 1's full set at that time. The cost then is option 1's cost now, and nothing built meanwhile is lost: Q-lib is needed under every shape.
- Q-lib's expected zero change to walk's outputs rests on the reading that no `IntLiteral` value reaches the library under walk save a numeral below -2^63. The rung's comparison over the 440 tests is the check; a changed output is listed, and a numeral below -2^63 in a test would be the first place to look.
- Row 432 (`SUM <|1, 2, 3|>`) stays open under both halves: the probe found it refused under the switch too, over `ArrayList[\IntLiteral\]`, because `IntLiteral` carries no additive algebra. Whether Q-lib gives `IntLiteral` the algebra every flat number type carries is the rung's choice to list, not this judgement's; the row is not on microGPT's path.
- Item 33's `CMP` per type was measured on the checker for `ZZ32` only (61 and 43 errors gone); the other integer types' `CMP` and the ten `MAXNUM`/`MINNUM` declarations are decision 2's device by reading. The rung's distance capture is their measure.
