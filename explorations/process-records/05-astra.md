## Timeline

1. **2026-09-07 00:13–00:27 UTC — environment and baseline, coordinator side.** Goal: a usable historical Fortress on a machine where system package installation failed "on container user/group operations" (`explorations/astra/SETUP_NOTES.md`). Portable Temurin JDK 25.0.4.1+1 and Ant 1.10.18 were fetched and checksum-verified; the extracted JDK module file "repeatedly shrank from 146,008,035 to 68,550,656 bytes between workspace command calls", and re-extracting under `/tmp/fortress-toolchains` fixed it (`explorations/astra/README.md`, `SETUP_NOTES.md`; the failed first Ant invocation is retained in `evidence/20260907T001350.861073Z-build/`). `ant clean compileAll` then passed in 61.133 s, `ant testFast` 1,377 tests in 467.769 s, `ant testSystem` 382 tests in 129.810 s; the system-test console log lost its tail and its counts come from the copied JUnit reports (`evidence/20260907T002343.795715Z-testSystem/`).

2. **00:15–00:17 UTC — the smoke test twice wrong.** Goal: prove the interpreter executes a program. The first attempt used a nonexistent `interpret` subcommand and exited zero after printing the CLI usage text (`evidence/20260907T001543.994350Z-smoke/output.log`), which `SETUP_NOTES.md` turns into a stated rule: "A zero exit alone is insufficient evidence that a Fortress program executed." The corrected `walk` invocation then rejected the expression `6 * 7` with "Operator * is not defined." (`evidence/20260907T001605.091925Z-interpreter-smoke/output.log`); `40 + 2` printed `42` in 4.332 s (`evidence/20260907T001728.599067Z-interpreter-smoke/`). The worker assignment `WORKER_BRIEF_DRAFT.md` — still titled "assignment, not yet launched", and described in `README.md` as "the maintained worker assignment" — dates from this phase.

3. **01:45–01:47 UTC — first probe burst, overlapping lanes.** Goal: try SUM, juxtaposition, generic reduction, vector construction and autodiff in the actual language before designing a model. Ten records; the vector probe failed first on "Precedence mismatch: juxtaposition and +." (`evidence/20260907T014616.854137Z-vector-function-probe/output.log`) and then, spaced, on "Cannot find definition for method asFloat given receiver 1: ZZ32" (`evidence/20260907T014707.902395Z-vector-function-probe-spaced/output.log`), the two constraints that produce the final program's explicit spacing and its `1.0 i` conversion. The failed sources are kept as `worker/main/VectorProbe-spacing-failure.txt` and `worker/main/VectorProbe.fss`.

4. **05:55–06:02 UTC — resumed; model candidates, the SUM collision, and the library-Vector probe.** Goal: an executable algebraic core. Twenty-eight records in seven minutes: `ModelCandidate` iterations 01–05 failed (numeric suffix, spacing, `asFloat`, indexing a call result, reduction inference — snapshots `worker/main/ModelCandidate-01..05-*.fss.txt`) and 06 printed two scalar smoke results (`evidence/20260907T060134.575775Z-microgpt-model-candidate-06/`). A component-local zero-argument `SUM` collided with the prelude: "Overloading of BIG +[\T extends FortressLibrary.Number\]() … and BIG +():Comprehension[\D,D,D,D\] … fails because their parameter lists have the same types" (`evidence/20260907T055823.426904Z-notation-dual-sum/output.log`), while a one-argument generator SUM and a named generic sum both printed `10.0` / `4.0`. The library route was probed and rejected in one pair: `Vector[D,2]` was accepted despite `T extends Number` and printed `[0#2][ D D ]` (`evidence/20260907T055922.439724Z-notation-number-bound/`), but the shipped `SUM` over that element failed at runtime with `CastError` at `FortressLibrary.fss:36:13-27` (`evidence/20260907T055953.298778Z-notation-builtin-sum-d/`). The Fortify pipeline became usable in the same window (`evidence/20260907T055657.417207Z-fortify-check/`, `…T060039.807128Z-render-helper/`, coordinator-supplied per `README.md`), and the first full forward attempt failed at 06:02:27.

5. **Later on 2026-09-07, exact time unrecorded — ordinary Σ recovered.** Goal: get the canonical big-operator surface for a non-numeric scalar. The resolution was `import FortressLibrary.{...} except { opr BIG + }` with a local zero-argument `opr SUM()` over an AD `Comprehension`; `NotationExceptSum.fss` printed `10.0` and `4.0` (`worker/notation/except-run.log`), and excluding `{ opr SUM }` or `{ SUM }` instead is recorded as a parser error. `BIG MAXNUM` and a user `opr DOT` (rendering as a central dot) were settled in the same pass (`worker/notation/NOTES.md`, `render-except/`, `render-named/`, `render-dot/`). **This phase rests on notes written after the fact**: `TIMELINE.md` states "Notes place these results before integration; there is no precise timestamp for the decisive SUM/DOT calls", and no `command.json` for these runs is in `evidence/`.

6. **20:30–20:32 UTC — the forward-only gate.** Goal: match the Python fixture's logits and loss before touching gradients. `ForwardProbe` failed on a chained subscript, "Failed to find any matching overload, args = ()" at `ForwardProbe.fss:17:33-38` (`evidence/20260907T203055.791853Z-resumed-forward/output.log`; snapshot `worker/main/ForwardProbe-01-chained-index.fss.txt`); binding the row to a local repaired it, and the rerun exits 0 in 3.236 s with all nine logits and the mean loss matching the fixture at maximum absolute difference 5.551115123125783e-17 (`evidence/20260907T203154.764676Z-forward-index-fix/`, `worker/main/MILESTONES.md`). `MILESTONES.md` labels this "verifies forward only, not AD/training/generation".

7. **20:33–20:36 UTC — the reverse pass rewritten as a graph walk.** Goal: a differentiation algorithm that survives shared subexpressions. The retained earlier probe pushes contributions down every parent path (`worker/autodiff/AutodiffProbe.fss`); the replacement marks nodes, builds a reverse chain and propagates once per node (`worker/autodiff/AutodiffGraphProbe.fss`).
