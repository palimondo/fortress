## 1. The finding

`ProjectFortress/library_tests/XXXRR32EqualityRungV.test:3` reads `run_out_contains=PASS`. The program prints `REACHED` (`XXXRR32EqualityRungV.fss:10`), dies at its first assertion, `a = a` (`:11`), with `java.lang.AbstractMethodError` (row 528), and never reaches `println("PASS")` (`:15`). The gate shows exactly that: the link test `OK` (`tmp/gate-batch-6.5b/testFast.txt:347`), the run `REACHED` (`:1140`), the error (`:1141-1161`), "Failed to satisfy run_out_contains; expected PASS" (`:1162-1163`), and `LibraryJUTest` with 86 tests and 1 failure (`:1194-1195`).

The harness reads it that way by construction. In a run test, `failed` comes from the exit code alone (`FileTests.java:524-531`); `trueFailure` is set by any `run_out_*` check that is not met, whatever the exit code (`:534-539`); and `trueFailure` is tested first, failing the test outright (`:583-585`), before the expected-failure comparison `shouldFail != failed` (`:587-590`). `shouldFail` is the `.test` file's name starting with `XXX` (`:932`), handed to the run test (`:1063-1069`). So an `XXX` run test's key must name output the failing run prints. FACTS.md, "The `XXX` expected-failure mechanism in `compiler_tests/` and `library_tests/` can express a compile-stage failure only, and a run-time defect needs two `.test` files", says so: "a marker the failing run does print".

The review's diagnosis is right, and its repair is right: `run_out_contains=REACHED`, batch N's form (`ProjectFortress/compiler_tests/XXXNumeralBeyondWidthMax.test:3`; batch N's `JUDGE-review.md` section 2.4), which rung E's own pairs use too (`compiler_tests/XXXInferResultOnlyCoerced.test:3`). With it:

- placed, the run prints `REACHED` and exits 1: `trueFailure` is null, `failed` equals `shouldFail`, and the harness prints "Saw expected failure (Exit code != 0)" (`:589`);
- on the fix (`explorations/compile-ladder/rung-rr32-sibling/probes/comp/local-fix.patch`), the run prints `REACHED` and `PASS` and exits 0 (`probes/comp/XXXRR32EqualityRungV.localfix.txt`): `failed` is false, `shouldFail` true, and the harness prints "Did not see expected failure" and fails (`:587-588`), which is the red the rule asks for;

That form fits `XXXInferResultOnlyAny` because its class fails verification before any output; this program prints first. So the key is `REACHED` alone. Nothing else in the pair changes: the `.fss` already prints `REACHED` before the first failing line, and the link test passed in the gate.
