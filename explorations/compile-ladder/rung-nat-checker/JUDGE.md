## 4. Decision 3: it stands, and it goes to Pavol as the rung's decision

The specification is silent on inference (`Specification/basic/inference.tex:15`). Pavol's rule gives the direction: an unknown size is an error only where it reaches a type, a name or a value (`POSITIONS.md:47`). But "a name" is ambiguous on the compiled path, where a call's static arguments name the instantiation. The candidates and their costs:
- **The rung's reading**: an unknown size at a call is the no-context error (`ProjectFortress/src/com/sun/fortress/scala_src/typechecker/impls/Functionals.scala:247-249`). It is loud and reversible, and no other rung's file is touched. The costs: `SkDeadArm` is refused where walk and the type twin run, and compiled calls to the library's six vector `DOT` declarations need E3. The review's own E2 text already expects E3, because the fixed export checker "reports the extra parameter" of those six api declarations (`array-design-review.md:79`, `:181`). None of this is reached before the switch-over, because the compiled path does not read `FortressLibrary` until then (`POSITIONS.md:46`).
- **Sizes as types: a "bottom" size that reaches the instantiation name.** No size bottom exists. An `_InferenceVarInt` left in the static arguments trips the `OutAfterTypeChecking` assertion (`REPORT.md:56`), or it reaches `NamingCzar` and code generation, the run-time rung's files, where `CodeGen.java` is a stop for this rung (`CLIMB-BATCH-4.md:119`). And a dead size used as a value would then fail only at run time.
- **Default to 0.** This is E1, which Pavol did not take (`POSITIONS.md:47`).
- **A finer rule**: an error only when the arm's body or return type uses the size. It needs an analysis of the body that the checker does not have. It is larger than a repair round.

I rule that the rung's reading stands. It is the loud side, it can be relaxed later without loss, and every alternative either needs files outside this rung or was declined. It is a decision taken under a silent specification, and it goes to Pavol as such, with (a), (b), (c) and the static-parameter point of section 2 item 1.
