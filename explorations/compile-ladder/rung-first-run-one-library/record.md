## Revival change

**The change.** The team's compiled run time had one set of hand-written value classes, each extending a generated class of the compiler's prelude (`ProjectFortress/src/com/sun/fortress/compiler/runtimeValues/FBoolean.java:14-15`, `FJavaString.java:14-15`, `FJavaBufferedReader.java:16`), so the compiled path could run only programs compiled against that prelude; its helpers named the prelude's exception classes by their whole names, as `"fortress.CompilerBuiltin$IntegerOverflow"` (`ProjectFortress/src/com/sun/fortress/nativeHelpers/simpleIntArith.java:64` at a1c244be36). The tree now builds a second set of these classes, under the same names, for the interpreter's library, and the class path chooses the set by the library that a compile reads; the interpreter's library's `Boolean`, `Char` and `FlatString` and its seven number types are compiled as value objects whose classes extend payload classes that hold the JVM value; a helper names an exception by its simple name, which each set maps to its library's class. Tests: `ProjectFortress/one_library_tests/OneLibraryComponents.test`, `OneLibraryRunHello.test`, `OneLibraryCatchHelperRaises.test`. The reason: the compiler's code generator refused the interpreter's prelude whole at its helpers' wrappers, 'Can't generate header for method floatToString with jvm desc =Ljava/lang/String; stripped = FortressLibrary$String', and a program compiled against it died at its first library class, 'NoClassDefFoundError: fortress/FortressLibrary$String' (the two failing runs of the report); and one build must serve both libraries while the compiler's prelude stays.

**Provenance.** Rung C of climb batch 34b: forks C1 to C6 of `explorations/coordinator/CLIMB-BATCH-34.md`, "Forks the batch takes", with P-33, P-37, P-178, P-164 and P-169; fork C3's typing of `FValue.asString` taken in the second set only, on Compiled17a's failure (the report's decisions).
