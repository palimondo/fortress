## 1. What changed and why

The commits: `7bd7c7dfc7` (the change and its tests), `fe5d146a86` (the `XXX` test of the one fork not built, NEW-C-1), `fa13e6383c` (three revival tests the suite showed broken, respelled). The code of `7bd7c7dfc7` is the final code; the later commits change tests only.

**The default (P-173, fork C1).** A numeral, an `IntLiteralExpr` or `FloatLiteralExpr` node as written or as the fold made it, where nothing fixes a type converts into its default: `ZZ32`, or `ZZ64` or `ZZ` by its value, `RR64` with a radix point. The default applies to a numeral node, never to an expression of a numeral type, so `t = x` inside `coerce(x: IntLiteral)` stays an `IntLiteral`. The sites:

- an untyped binding, top level and local, one variable or several (`scala_src/typechecker/impls/Decls.scala:252`, `:289`, `:343`, `:384`), through `defaultNumeral` (`impls/Functionals.scala:1016`): a numeral alone; each element of a tuple on its own; the branches of an `if` with `else`, a `case`, a block's last expression or a one-block `do`, when every result is a numeral, together into the narrowest default holding them all (`joinNumerals`, `joinInto`, `:1030`, `:1046`);
- a parameter or a typed place whose type holds the numeral without conversion and fixes no type, `Any`, `Object`, `Number`, where the default fits too (`defaultAtUnfixed`, `:1078`): in `checkApplicableWithoutInference` (`:490`), its `Any`-domain branch (`:512`), after the subtyping inference (`:279`), in the coercion attempt (`:410`), and at every typed binding, assignment, field and return through `STypeChecker.checkExpr` (`scala_src/typechecker/STypeChecker.scala:506`);
- a parameter or typed place whose type declares no coercion from the numeral's type but holds its default, as `Index` holds `ZZ32` (`defaultFits`, `:1093`; `STypeChecker.scala:510`, `Functionals.scala:411`, `:491`);
- a type parameter that numerals alone fix, with no expected type: before the subtyping inference (`preDefault`, `:1121`, called at `:198`), and as the coercion attempt's one choice for that parameter (`:385`), the narrowest default holding every value (`numeralDefault`, `:998`), with the attempt's ordinary choices as a fallback where the default finds no candidate (`:417-423`);
- a dotted receiver written as a numeral, where the default type has the member (`defaultReceiver`, `:1105`; called at `:1360` and `impls/Misc.scala:347`), the prototype's receiver rule, so the prelude's `(1).asNN32` keeps its numeral.

It does not apply: at a parameter of a numeral's own type (`isNumeralType`, `:989`), which a coercion's or an operator's parameter is; at a place whose type declares a coercion from the numeral's type (the eight number types on the one library, the prelude's six, a program's type with `coerce(x: IntLiteral)`), where that coercion runs; at a type parameter that a non-numeral argument also fixes, or another parameter type mentions, or the expected type fixes, which the inference sets as before (P-74); to a join with a non-numeral branch; to an `if` without `else`.

**The ranking (fork C4, the prototype's step 5 in its narrow form).** A numeral's coercion into its own default ranks as no coercion wherever it is built: `NumeralConversion.isDefault` and `counts` (`scala_src/typechecker/CoercionOracle.scala:432`, `:439`), read by `counted` (`impls/Functionals.scala:742`) and by `moreSpecificCandidate` (`scala_src/useful/STypesUtil.scala:1147-1148`). It is read from the coercion's form, a `TraitCoercionInvocation` of a numeral node into the library type of its default's name, not from a table of marked nodes, so it holds for every copy of the node and keeps no state. Before the subtyping inference a numeral at a parameter of exactly its default type takes that coercion (`preDefault`), so `ee[\nat n\](x: ZZ32)` fits `ee(5)` as it is. So `gg(5, w)` runs `gg[\T extends Number\](x: ZZ32, y: T)` and the narrower declaration is the checker's static choice, P-173's reading of P-49 (fork C8).

**The narrowest default (fork C1, P-173).** `pick(3, 3000000000)` is `pick[\ZZ64\]` on the prelude (`LiteralDefaultCompiled`); on the one library, read by the count stage's driver, `<|3000000000, 0.5|>` is a `List[\RR64\]` (section 4).

**The written-only rule (P-174, fork C2).** `TypeWellFormedChecker` refuses `IntLiteral` or `FloatLiteral` written in a program's file anywhere but as the whole type of a parameter of a function, method, coercion, operator or function expression: "IntLiteral cannot be written in a program except as a parameter's type." (`scala_src/typechecker/TypeWellFormedChecker.scala:293`). An object's value parameter is a field, and is refused. Files under `Library/` and `LibraryBuiltin/` are exempt. A type that the checker infers from such a parameter keeps the parameter type's span and is not refused: the rule reads written types (`parameterTypeSpans`, `:48`; `numeralTypeWritten`, `:67`). The names are read from `Types.INT_LITERAL` and `Types.FLOAT_LITERAL`, so N's switch of the names by library carries the rule to `NaturalNumeral` and `RadixPointNumeral`.

**No chain (fork C4).** `buildCoercion` returns the coercion it checks (`CoercionOracle.scala:171`), without the prototype's `viaDefault`: `c: CC64 = 3` for a `CC64` with only `coerce(x: ZZ32)` is refused, "Right-hand side has type IntLiteral, but declared type is CC64." (`XXXLiteralNoCoercionRefused`). `defaultFits` does not chain either: it takes the default only where the default is a subtype of the place's type.

**The range refusal (fork C3, row 325).** `NumeralConversion.outOfRange` (`CoercionOracle.scala:459`): an integer numeral outside `ZZ32`, `ZZ64`, `NN32` or `NN64`, and an integer or float numeral whose one rounding into `RR64` or `RR32` is an infinity, has no coercion into that library type (`:172`). At a typed place the checker signals "The numeral 4294967295 is out of range for ZZ32, whose values are -2147483648 to 2147483647." or "The numeral … rounds to infinity in RR64." at the numeral (`STypeChecker.scala:513`); at a call that no candidate fits, each such numeral against each candidate's parameter type, beside the call's own error (`signalNumeralRanges`, `impls/Functionals.scala:1169`, called at `:795`). At an overloaded call, a candidate whose parameter cannot hold the numeral is not applicable, so `z MAX 3000000000` for a `ZZ32` `z` runs `ZZ64`'s `MAX` (`NumeralBeyondWidthMax`, promoted).

**The size read as a value (P-40, fork C5, row 486).** `KindEnv.getType` answers `ZZ32` for a `nat` or `int` parameter (`scala_src/typechecker/staticenv/KindEnv.scala:71-72`), the prelude's `CompilerBuiltin.ZZ32` or the one library's `FortressLibrary.ZZ32` (`sizeValueType`, `:112`); the code generator reads such a value where its type is `ZZ32` and converts the class loader's `IntLiteral` constant by `asZZ32` (`compiler/codegen/CodeGen.java:6342-6364`). So `u: NN32 = n` is refused, "Right-hand side has type ZZ32, but declared type is NN32.", and `v = n` is a `ZZ32`.

**A size the default leaves unknown.** A declaration that only the default at a parameter of its default type makes applicable, and whose size the call then leaves unknown, is checked as the numeral is, without the default (`impls/Functionals.scala:288-292`), so `ee(5)` is not refused by P-40's rule for an unfixed size: section 9, decision 6.

**A static argument of a numeral's own type.** A subtyping inference that a numeral argument fixes at the numeral's own type is left to the attempt with coercion, which reads the numeral by its default (`:172`), where no argument is a function expression still unchecked; `Compiled5.bu`'s `gapply(fn (x) => x + 1, 5)` needed that condition (section 3).

## 9. Decisions

1. **The default recognised by the coercion's form.** A `TraitCoercionInvocation` of a numeral node into the library type named by its default ranks as no coercion (`NumeralConversion.isDefault`). Ways not taken: the prototype's identity table `LiteralDefaults` (`literal-default.patch:1137-1166`), which keeps every marked node for the JVM's life and misses a copied node; a flag on the node, which the AST does not carry. Evidence: the ranking reads the node it is handed (`STypesUtil.scala:1147`).
2. **The written-only rule allows a parameter's whole type, and nothing else.** Ways not taken: the prototype's refusal everywhere ("cannot be written in a program: a numeral has its own type only while the checker types the program"), which P-174's coercions from the numeral types contradict; the rule over inferred types too, which fork C2 declines; a parameter's type anywhere inside, as `Maybe[\IntLiteral\]`, which writes a static argument. An object's value parameter counts as a field. Evidence: fork C2; P-174.
3. **The default where a place's type has no coercion from the numeral's type but holds its default (`defaultFits`)**, so `fi(3)` passes at `Index` and a float numeral at the prelude's `Number`. Way not taken: the default only at `Any`, `Object` and `Number`, the prototype's. Evidence: the judgement's repair 1, "every other type, and no type, takes the default" (`reviews/literal-design-judgement-2026-11-08.md`, section 1), which P-173's text follows.
4. **Joins and tuples at an untyped binding**, through the result positions, and the join's numerals at their narrowest default together. Ways not taken: the prototype's coercion of the whole join, whose branches keep literal values; a join's branches each at its own default, which the judgement's repair 4 declines. Evidence: fork C1.
5. **The range refusal as "no coercion", with the message at typed places and beside a call that no candidate fits.** Ways not taken: a coercion built and an error signalled, which would make an overloaded call refuse `z MAX 3000000000` instead of choosing `ZZ64`'s; the message only at typed places. Evidence: fork C3; `NumeralBeyondWidthMax`'s assertion, "a numeral converts only into a type that holds its value".
6. **A size left unknown after the default is checked without the default.** `ee[\nat n\](x: ZZ32)` fits `ee(5)` as it is by fork C4, but leaves `n` unknown, and P-40 refuses a call whose chosen declaration has a size it cannot fix. The checker so checks the declaration without the default, by subtyping, where it does not apply: `ee(x: Any)` is the static choice, the default makes the argument a `ZZ32`, and the compiled dispatch, which tests run-time types, runs `ee[\nat n\]`, so `ee(5)` gives 1 (`LiteralDefaultCompiled`, `InferO2Pos`). Ways not taken: the static choice of `ee[\nat n\]`, refused by P-40's rule ("Could not infer static argument nat n without context.", the first build of the change); the default not ranked as no coercion at a generic's parameter, which would leave `gg(5, w)` at the plain declaration. No decision of the curator covers the case where P-40 and fork C4 meet; a question below.
7. **The written-only message**: "IntLiteral cannot be written in a program except as a parameter's type." Way not taken: the prototype's text, now false. Evidence: fork C2, "renamed for both names".
8. **C6 not built** (NEW-C-1). The integer literal fold makes `-3` one node before the checker and keeps no reference to the prefix operator, so the checker cannot apply the program's `-` without a reference the disambiguator makes (`compiler/desugarer/IntegerLiteralFoldingVisitor.java:148-153`). Ways not taken: a fresh operator reference built in the checker, which the disambiguator's binding of operators does not reach; refusing a negative numeral at every program's type, which would refuse `c: CC64 = -3` where the type declares `-` too. Until the switch-over the prelude's `IntLiteral` carries the sign, so the coercion reads -3 exactly.
9. **The tests' respellings**: the prototype's `Boolean` arm; the team tests at `ZZ32`, the type their comments name; the nat tests read through types where a value cannot hold the size.
10. **No speed pass**: the profile shows the change in under 0.3 % of the samples.
