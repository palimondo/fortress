## 1. What changed

The compiled type checker now checks `nat` and `int` static parameters, a size such as the `n` of `Vector[\RR64, n\]`, by the plan's minimal design: a size is a symbol or a literal, two sizes are equal when they are the same symbol or the same literal, an inference variable is bound by equality, and there is no arithmetic. A program with a size inferred from an argument, one with the size written out, and a method called on a sized receiver compile; a mismatch is refused; arithmetic in a size and inference of a `bool`, `dim` or `unit` parameter are refused with an error that names them. The checker-count stage reads 125 with the crash row `none`, the numbers the batch record predicted.

## 4. The specification

- **Sizes are part of the language.** "Static parameters may include one or more `nat` and `int` parameters ... These parameters are instantiated at runtime with numeric values. A `nat` parameter may be used to instantiate other `nat` parameters, or to appear in any context that a variable of type ℕ32 can appear" (`Specification/basic/trait-parameters.tex:68-90`). The chapter opens with the 2012 draft's note "Non-type static parameters and static expressions are not yet supported" (`:15-17`), which records the implementation of its day.
- **Inference is assumed, not specified.** "We assume throughout this chapter that all static variables in functional calls have been instantiated or inferred" (`Specification/basic/overloading.tex:137-138`); the inference chapter is a placeholder, "This chapter will include the Fortress static type inference mechanism" (`Specification/basic/inference.tex:15`). How an unknown size is treated is therefore governed by Pavol's rule of 09-21 (`explorations/coordinator/POSITIONS.md:47`): an error only when it reaches a type, a name or a value. What "a name" covers on the compiled path is the rung's reading of that rule (decision 3).
- **Arithmetic in a size is in the language.** "Static expressions which use a restricted subset of operations can occur as static arguments" (`Specification/basic/expressions/constant.tex:23-24`, under the draft note "Static expressions are not yet supported", `:15`). Refusing it is a limit of the minimal design that the specification does not share; its test is an expected failure (section 6).
- **`bool`, `dim` and `unit` parameters are in the language** (`Specification/basic/trait-parameters.tex:101-120`, `:122-145`). Refusing their inference is a limit; its test is an expected failure.
- **The return-type rule.** "Overloaded declarations must have static parameters that are identical (up to α-equivalence) ... Therefore, static parameters ... are ignored in the remainder of this chapter" (`Specification/advanced/overloading.tex:95-103`), and the Subtype Rule requires the more specific declaration's return type to be a subtype of the other's (`:158-170`); the same sentence in the basic chapter is `Specification/basic/overloading.tex:100-107`, Pavol's open decision (`explorations/coordinator/CLIMB-BATCH-4.md:33`). The designers' checker implements the rule of their paper instead: `arrow(d1)` must be a subtype of `∀[Δ1, Δ2](S1 ∩ S2) → T2` (`Papers/Types/overloading-check.tick:166-172`), each declaration's static parameters its own. Section 5, decision 2, and section 9 say where the two readings part.

**Decision 3: a size left unknown in a call's static arguments is an error at the call** ("Could not infer static argument nat m without context.", `Functionals.scala:246-251`, `ApplicationError.scala:114`). This is the rung's reading of Pavol's rule of 09-21, not the rule itself. The judge kept the reading after the first refusal (`explorations/compile-ladder/rung-nat-checker/JUDGE.md` section 4), and it goes to Pavol as the rung's decision.
- **The rule and the reading.** The rule: an unknown size is an error only when it reaches a type, a name or a value, and nothing otherwise (`explorations/coordinator/POSITIONS.md:47`). The rung reads "a name" to cover every static argument of a call, because on the compiled path those arguments name the instantiation the code generator emits (`explorations/perf-probes/nat/java.md:42-45`). The rule's source reads it more narrowly. E2, the option Pavol took, is written as "the interpreter's `BottomType` rule ... the six declarations pass because their dead parameters reach nothing" (`explorations/reviews/array-design-review.md:181`, reasoning at `:81`), and under that rule the interpreter runs a call to a function with a dead size. The specification is silent: the inference chapter is a placeholder (`Specification/basic/inference.tex:15`), and its draft note asks the question for types and leaves it open, "Do we want to forbid such cases where type inference infers BottomTypes for static parameters?" (`:24-25`). The shadow built only the type half (`explorations/perf-probes/nat/REPORT.md:649-655`).
- **(a) Sizes are stricter than types.** A dead type parameter at a call passes, because `killIvars` turns it into `BOTTOM` (`ProjectFortress/src/com/sun/fortress/scala_src/useful/STypesUtil.scala:1937-1940`). A dead size is refused. For a single function: `DeadSize` is refused at both calls (`explorations/compile-ladder/rung-nat-checker/probes/typecheck-probes.txt:26-33`), while its type twin `DeadTypeSingle` checks, compiles and prints 3, 7 (`explorations/compile-ladder/rung-nat-checker/probes/dead-type-single.txt:2-9`), and walk runs both (`explorations/compile-ladder/rung-nat-checker/probes/walk-probes.txt:35-40`, `dead-type-single.txt:10-13`). For the generic arm of an overload set: `SkDeadArm` is refused at `dd("s")` (`explorations/compile-ladder/rung-nat-checker/probes/skeptic/dead-arms.txt:7-12`), while `SkDeadArmT` compiles and prints 2, 1 (`:34-41`). The skeptic's `SkDeadN`/`SkDeadT` pair does not measure this: both are refused because their argument is a numeral (`explorations/compile-ladder/rung-nat-checker/probes/skeptic/differential-2.txt:80-84`, `:108-112`), which is row 401.
- **(b) In an overload set the arm is dropped, not reported.** An arm whose size stays unknown counts as not applicable, so the checker resolves the call to another arm, and run-time dispatch still selects the dropped arm. `SkDeadTop` is accepted and its compiled run prints 1, 2, as walk does (`dead-arms.txt:44-55`). `SkDeadVal`, whose arm returns the size, is accepted and dies compiled with `NoClassDefFoundError: SkDeadVal$n`, where walk dies with "undefined variable [n]" (`:74-95`). - **(c) Every overload shape behind (b), and `SkDeadArm` in (a), pairs a generic declaration with a non-generic one.** The shapes are `dd[\nat n\](x: Any)` beside `dd(x: ZZ32)`, `ee[\nat n\](x: ZZ32)` beside `ee(x: Any)`, and `ev` likewise. That sentence is Pavol's open decision, and this rung neither enforces it nor relaxes it further; the size-generic arm beside a less specific sibling is the one shape the batch excepts (`explorations/coordinator/CLIMB-BATCH-4.md:127`).
