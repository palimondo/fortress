### Rung O, `rung-number-objects`: the five number types as value objects

**The change.** The team's library declared the number types as traits, each comprising native objects: `trait ZZ32 extends { ZZ64, Integral[\ZZ32\] } comprises { Int, IntLiteral }`, `trait RR64 extends Number comprises { Float, FloatLiteral, RR32, QQ }` and the like (`a874948ac:Library/FortressLibrary.fss:422`, `:642`, `:700`, `:770`, `:822`), with `value object Int extends ZZ32`, `Float`, `Long`, `UnsignedLong` and `BigNum` in `FortressBuiltin` (`a874948ac:ProjectFortress/LibraryBuiltin/FortressBuiltin.fss:54`, `:369`, `:378`, `:450`, `:528`), and walk's glue classes `Int`, `Long`, `Float`, `BigNum`, `UnsignedLong` built those objects; the specification presents `ZZ` as a trait (`Specification/basic-lib/basic-integers.tex:229`). The tree now declares each of `ZZ32`, `ZZ64`, `ZZ`, `NN64` and `RR64` as one `value object` of the one library, as `NN32` and `RR32` already were, and walk builds its values from a glue class of the type's own name: `asif` at the type is the value itself, a typecase arm at its name takes its values, its ilk is its name (`ProjectFortress/tests/NumberTypesAreObjectsWalk.fss`), and a program's object below one is refused at load, 'Attempt to extend object type ZZ32' (`ProjectFortress/tests/NumberTypeExtendRefusedWalk.fss`). A program's own number type extends `Number`. The names `Int`, `Long`, `Float`, `BigNum` and `UnsignedLong` declare nothing: as a type they are undefined, and as a typecase arm they take every value. The reason: each trait had exactly one object below it, the reasons for the split (the literal types, the nested tower) are gone; the second names are walk's internals, which a program saw as types; and a program's object below `ZZ32` loaded under walk and then failed at its first native method, 'getInt not implemented for FOrdinaryObject' (measured: `object Mine extends ZZ32` loaded and printed `Mine` on 647163a9c4), while on the compiled path such an object compiles and dies when its class loads, 'class ...$Mine can not implement com.sun.fortress.compiler.runtimeValues.FZZ32, because it is not an interface', since a bare `int` cannot hold it.

**Provenance.** P-178 (each built-in number type one `value object` under its own name; walk's native number objects go), with P-160 (a program's own number type extends `Number`) and P-167; the forks O1 to O7 of climb batch 31's record (`explorations/coordinator/CLIMB-BATCH-31.md`, "Forks the batch takes"), at their defaults; rows 1003, 551 and 866; climb batch 31b, rung O.
