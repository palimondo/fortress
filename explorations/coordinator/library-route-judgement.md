# The library route: judgement

Terms. **Prelude**: the apis every program gets without importing them. **World**: a prelude plus its switches (`Shell.useCompilerLibraries()`); `fortress file.fss` runs the interpreter's world, `fortress compile` the compiler's. **Checker**: the static type checker, which runs only in the compiler's world. **Builtins**: the prelude's lowest layer, where declarations are bound to Java code (**natives**). **Exclusion**: the rule that two types share no value, which lets the checker refuse a trait extending both. **`nat`**: a static parameter that is a number, used for array sizes. **Rung**: one edit plus its test under the full gate (median 54 minutes). **Gated batch**: up to four rungs under one gate (3 to 5 hours landed). **Worker session**: one delegated report with its probe, no gate.

## 1. Is there a reason on record to keep a second library?

No. Nothing on record argues for two libraries as a destination, and Pavol's reading is the record's: the split was made on 2008-12-19 as a "stripped-down minimalist … first crack at compilation"; its switch is commented "hopefully temporary hack" in the tree today (`WellKnownNames.java:109-111`); the team called what went into it "bogus" (2009) and "bogo-trait" (June 2012, its last edit); the specification names one default library and never the compiler's (`library/structure.tex:13-22`, `default-libraries.tex:15-24`; no `.tex` in the tree contains the word `CompilerLibrary`). What the team did not leave is a plan for ending it: they grew the copy for three and a half years behind the wall they named at the wind-down, the type system against the JVM. That is a record of what they could do, not a position; overruling it costs nothing.

Each reason the brief and the reviews raise, judged:

- **A place the interpreter cannot see.** True (`next-climb/worlds.md`: an edit confined to the compiler prelude cannot reach the 384 interpreter tests) and never used: every batch gate has run `testSystem` anyway (`climb-batch-workflow.md:44`). Under one library a library edit is checked by both suites, which is the discipline Pavol set, not a loss. Not a reason for two.
- **Two native mechanisms.** Real, and a reason for two *binding* files, not two libraries: 95.3% of `FortressLibrary.fss` is plain Fortress; the natives are 108 bindings there and 231 in `FortressBuiltin.fss`, the builtins layer the specification itself separates from the library. Work before: re-bind those 339 (79 of the 108 have a `nativeHelpers` counterpart; the 231's overlap is uncounted, though the compiler's 330 `import java` aliases cover the same types). Whether the builtins are one text with `import java` on both paths, or one api with a component per path, is decided by a half-session probe nobody has run: `ForeignJava` is wired into the interpreter at `Driver.java:441` and exercised by no test. Not a reason for two.
- **The desugaring settings and the four well-known types.** One setting differs in substance: the compiler world gives an unbounded type parameter an implicit `extends Object`, and the specification says exactly that (`trait-parameters.tex:49-50`), so the compiler's setting is the spec's and the interpreter's is the divergence; the reconciliation keeps the compiler's. The four types (`String`, `JavaString`, `Exception`, `CheckedException`) are placed by `Types.useFortressLibraries()` once the world is one; the cost is the sources that name `fortress.CompilerBuiltin.X` literally (38 Java/Scala files, 21 of them the runtime's value classes such as `FZZ32`, plus the frozen stub `src/fortress/CompilerBuiltin.java`), a rename in the switch-over batch. Not a reason for two.
- **The checker's `nat` gap.** Blocks every route equally, growing the copy included, because the target vocabulary is sized (ruling of 2026-09-19). It is PLAN step 4 under any library. Not a reason for two.
- **The 27 exclusion sites.** The brief says only the `excludes` clause is in the specification. That is not right. The types chapter states three of the checker's four clauses: the `excludes` clause (`types-vals-vars.tex:212-214`), object-ness ("an object trait type excludes any type that is not its supertype", `:222-224`) and propagation to subtypes (`:163-164`). It does not state exclusion derived from `comprises`, and it contradicts the fourth clause: a trait "is allowed to extend other instantiations of itself" (`trait-parameters.tex:339-345`), while the checker's `checkP` (`TypeAnalyzer.scala:443-457`) makes two instantiations of one generic exclude each other, which is the shape of the numeric tower (`ZZ32 extends ZZ64`, both `Integral[\·\]`) and of the two reductions the library itself comments as a "Hack". Which clause fires at which of the 23 remaining sites was not traced. So this is work before: trace the clause per site (one worker session), then fix the library where a stated rule fires and the checker where the contradicted one does; a decision reaches Pavol only where the spec is silent, the `comprises` clause. The compiler world avoids this today only by keeping its tower flat (`ZZ32 extends { Number, Equality, StandardTotalOrder }`, no `ZZ64`, no `Integral`), the bogo-trait; a copy grown "in the library's own patterns" would meet the same rules. Not a reason for two.

One thing only one library gives: the checker on interpreter programs, which Pavol asked for on 2026-09-15 and which FACTS says means giving the checker the interpreter's prelude. It arrives the day the prelude passes TYPECHECK, before any native is ported.

## 2. The order

Destination: the compiler's prelude is the specification's, `AnyType`, `FortressBuiltin`, `FortressLibrary`, and `CompilerLibrary`, `CompilerBuiltin`, `CompilerAlgebra` are deleted at the switch-over. From `main` at the batch-2 landing:

**Step 0, now: stop adding to the compiler prelude.** Nothing is in flight (the tree is clean; the nine `wip/` remotes are landed batches awaiting deletion). The fourteen fork-free rungs were forecast to move 38 files by one phase and no microGPT component, and every one is a declaration `FortressLibrary` already has. Codegen rungs continue, being compiler work under any library: `forTryAtomicExpr` (row 353), `LetFn` (row 304), `ObjectExpr`, the eleven-file array-literal crash at `Misc.scala:876`. Prelude rungs (`Char`, `Thread`, `round`/`truncate`, `IndexOutOfBounds`) stop. The landed rungs' tests stay; the ten `library_tests` files that use compiler-world spellings (`NothingObject`, `Character`, `ZZ32Vector`) are rewritten at step 5.

**Step 1, the first rung: the interpreter prelude through the checker, as a gate stage.** Edit: `fortress typecheck` gets a `-fortress-lib` switch, the mirror of `-compiler-lib` (`Shell.java:860-863`; `typecheck` calls `useCompilerLibraries()` unconditionally today), or the 46-line `perf-probes/prelude/WorldFlip.java` moves into the harness; a stage in `climb-batch-workflow.js` beside the ladder regression runs the checker over the three apis and what they import under a private cache, prints the per-api error table and the crash line, and lands the table as the comparand. What it proves: that the distance to one library is measured by every gate from now on, and that the world switch is four lines. Stop condition: two runs print the same table (93 errors, 48 sites, 12 apis, `Not yet implemented` at `STypesUtil.scala:557`); the count is red, the suite is green; no library line changes. This is the one place the test-first rule is met by a stage rather than a `.fss`, because no program can yet be compiled against that prelude; the stage is permanent, which is what the rule protects.

Same batch, rungs 2 and 3, the defects with no question attached: family C, the fifteen `RangeInternals.fsi` bounds (`I extends AnyIntegral` where `Integral[\I\]` is required), 26 errors; families D and F and the site that extends and excludes `Condition[\()\]` in one line (`FortressLibrary.fsi:2526`), 4 errors. Gated by `testSystem`, which runs this code. Expected: 93 → 63 at 23 sites, nothing new. Stop: a fix that would change a declared type rather than a bound.

**Step 2, three worker sessions in parallel, no gate.** (a) The exclusion trace: for each of the 23 sites, which of the four clauses fires, beside the spec lines above; output: the sites under a stated rule (library rungs), the sites under the contradicted clause (a checker rung), and the sites under the `comprises` clause, the only decision that reaches Pavol. (b) The `nat` shadow session the review's decision F specifies: where the crash is (Scala or Java, finding 6), the export checker on the six dead-nat declarations (decision E: E2 in the checker, E3 the six-line api diff shown to Pavol), `NatExtends1`, `NatStore1`, and the loader probe that decides decision A (A2, the team's direction, against A3). (c) The half-session probe: a two-declaration component bound with `import java`, run by the interpreter; decides the builtins' shape for step 5.

**Step 3, the `nat` rung, then the exclusion rungs.** PLAN step 4 in the tree, shadow-proven, `.scala` plus whatever `.java` the shadow found: one to two gated batches. Decision E lands inside it. Then step 2(a)'s rungs, zero to two, or the `comprises` decision first. Stop condition of the phase: the stage prints zero errors and no crash, and `FlatArrays.fsi` type-checks with no error of its own (already true but for `nat`, FACTS). Milestone: `fortress typecheck -fortress-lib` works on interpreter programs.

**Step 4, one worker session: the prelude through DESUGAR and CODEGEN once.** No run has ever reached them with this library; the size is not on record. Output: the hole list, each hole a codegen rung, most of them rungs the ladder needs anyway.

**Step 5, the switch-over: at least two gated batches, with the one-`.java`-rung rule relaxed for them (as B1 proposed for the interpreter batch).** Batch one, the natives, re-bound as 2(c) decided: the 29 of 108 without a helper written, the 231 of `FortressBuiltin` matched to the compiler's helpers. Batch two, the names: the 38 sources and the frozen stub re-pointed; the two `useCompilerLibraries()` collapsed to one world with the extends-`Object` setting kept; the compile recipe's five files made three; the five prelude files deleted; the at least 48 compiler-side tests that name compiler-world spellings (a rough grep) rewritten to the spec's (`Nothing[\T\]`, `Char`). Gate: the full suite, the atomic runs, and the ladder regression, where the 85 passes must hold and the 104 fork-blocked files are expected to move off `Array is undefined`. Not settled: whether `FZZ32` implements `FortressLibrary.ZZ32` or `FortressBuiltin.Int` (the interpreter's `Int` is a value object under the trait; the compiler's value class is the trait's implementation); and, if 2(c) says two components, the mechanism, which is the step row 320 found missing (`Linker.whoIsImplementingMyAPI`).

**Step 6, decision D: a diff, no code.** The model's static types (D1 with D3, the review's default) shown to Pavol as the diff of `rmsn` and `step`'s signature, as soon as step 3 lands and before any array rung.

**Step 7, the array rungs against the library's existing `Array`, `Vector`, `Matrix`, with no copy to write.** Decision A's `.java` rungs as 2(b) decided, at least three gated batches (finding 6: `IntArg` in `extends` at `CodeGen.java:5784`, a runtime kind for `nat` arguments, the store); then decision B, unboxing by static type in generated code (B2), the largest codegen work in the plan, its first measurement `kdot` compiled over the store against `KDotPrim`. End state: the 31 declarations of `FlatArrays.fsi` type-check and compile against the one library, the model's text as D decided.

## 3. Costs, and what each route forecloses

| step | units |
|---|---|
| 1 | 1 gated batch (3 rungs) |
| 2 | 2 worker sessions + 1 half session |
| 3 | 1–2 gated batches + 0–2 rungs, or 1 decision first |
| 4 | 1 worker session + codegen rungs, count unknown |
| 5 | ≥ 2 gated batches |
| 6 | one diff |
| 7 | ≥ 3 gated batches, then B, unmeasured |

To the point where the prelude is one and the checker passes it: about four to five gated batches and four worker sessions. The array work after it is the same under any route.

Growing the copy to the same target costs the copy itself, the array layer and the algebra above `Number` written a second time (about 1,200 lines plus `AdditiveGroup`, `MultiplicativeRing`, `Indexed`, `ReadableArray`, finding 3), at least three batches; plus the same `nat` rung, the same A and B, the same exclusion rules as its tower grows; and never the checker on interpreter programs. It is cheaper only for the 38 files it can move by one phase.

Forecloses. One library: the compiler world's spellings (`NothingObject`, `Character`, `Option`/`Some`), which the goal already rules against; the never-used sandbox; the 298 lines of revival prelude text, superseded, their tests kept. Two libraries: the checker on interpreter programs; the array vocabulary without a copy; the standard library ever being one thing.

Not settled by the evidence, in the order it is met: whether `import java` runs under the interpreter (2c); which clause fires at each tower site (2a); whether the `nat` crash is in Scala or Java (2b); whether the loader can select a representation (2b); what the library meets in DESUGAR and CODEGEN (4); the overlap of the 231 builtins with the compiler's helpers (5); the size of B (7).

## 4. The decision

What we do: make the specification's default library, `FortressLibrary` and `FortressBuiltin`, the compiler's prelude, and delete `CompilerLibrary`, `CompilerBuiltin` and `CompilerAlgebra` when the switch-over lands; from now on no declaration goes into the compiler prelude, and codegen rungs continue.

What it changes: the standard library exists once; every library edit is gated by both suites; the checker becomes usable on interpreter programs when the prelude passes it; the array vocabulary is not written a second time; the thirteen revival commits to the compiler prelude are superseded and their tests kept.

Alternatives: keep growing the copy (reaches no microGPT component, runs out at 38 files, every line a copy to delete later); one text with two binding components for the builtins (a variant of the same destination, chosen by the step 2(c) probe, not by Pavol); both at once (two gates, no gain).

Default: one library, the interpreter's, with the builtins' shape decided by the probe. First rung: the interpreter prelude through the checker as a gate stage (step 1).
