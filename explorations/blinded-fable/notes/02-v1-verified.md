# 02 — Milestone: first full Fortress microGPT verified against the reference

Date: 2026-09-08. Evidence: `src/MicroGPT.fss` (library + smoke test in a
`(* TESTS *)` region), `src/check_main.part` + `tools/build.py` → `build/Check.fss`,
`src/MicroGPTData.fss` (generated by `tools/gen_data.py` from
`checks/checks_2steps.json`), output in `checks/check_run_v1_output.txt` and
`transcript.txt`.

## Attempt
Design "v1": scalar reverse-mode autograd `Value` (object with `var data`, `var grad`,
`deps: Generator[\(Value, RR64)\]` built by a varargs factory `node(data, (child, ∂)...)`),
`∑` over Values via a `CommutativeMonoidReduction` after hiding the library's
Number-only `∑` with `import FortressLibrary.{...} except { opr BIG + }`; vectors as
`Indexed[\Value, ZZ32\]` (lists, arrays and slices alike) built by list
comprehensions; matrices as `Array2[\Value,0,m,0,n\]` with `opr juxtaposition` for
`W x` and `opr DOT`; `rmsnorm`, `softmax`, `Layer[\d,f\]` (attention with KV cache,
MLP), `Model[\V,T,d,f\]`, `loss`, `Adam`, `pick`.

## Observation
- Smoke test (random init): loss 3.36 (≈ ln 27), 41.8k nodes for 5 positions;
  forward 4.1 s, backward 27 s; one Adam step lowers the loss to 2.99.
- Reference check (2 training steps on docs "yuheng", "diondre"; 3 samples with the
  recorded uniform draws): ALL CHECKS PASSED. Max abs differences: logits 2.2e-16,
  per-position losses 4.4e-16, loss 4.4e-16, gradients ≤ 2.2e-16 (most ≤ 1e-17),
  parameters after Adam ≤ 3.1e-16, sampling probabilities ≤ 7e-17; all sampled
  tokens and texts identical ("org", "stclyzqwpactmmcx", "ku"). 415k graph nodes
  total; ~40 s per training step.

## Tolerance justification
The tolerance 1e-12 (absolute) is set ~4 orders of magnitude above the observed
differences and ~4 orders below any quantity of interest (logits O(1), losses ≈3.4,
gradients O(1e-3..1e-1), Adam updates O(1e-2)). Differences arise only from
floating-point summation order: Python's `sum()` is a sequential left fold, the
Fortress `∑` reduces in the order chosen by the generator (tree-shaped), which
perturbs a 16–64 term sum by O(n·ε) ≈ 1e-15 relative; softmax/log/Adam do not amplify
this materially over 2 steps. The identical sampled tokens confirm the cumulative-sum
sampler matches Python's `random.choices` decision boundaries at the recorded draws.

## Decision
Keep the sequential-vs-parallel summation difference (do not force `seq` inside `∑`):
it is a numerical-order effect, not a dependency. Proceed to the design exploration
of the notation (alternatives for vectors/matrices/attention) with this verified
baseline as the correctness oracle; every alternative must pass the same check.

## Uncertainty
- Interpreter gaps hit on the way (see notes/01): subscript-then-`^`, `T[n]` types
  with nat parameters, API-boundary unification of nat-generic functions, list
  literal element typing (invariance), no array comprehensions. The v1 notation
  works around them; whether a cleaner form exists per gap is explored next.
