- F-173 **The specification's type-inference chapter states the rule that the compiled checker builds: the declaration is chosen first, then its static arguments are inferred.** It states P-46, P-48 and P-49. A type parameter that is the whole declared type of one or more parameters, as `T` is of `x: T`, takes the narrowest of those arguments' types and the types to which they can be coerced; where none is narrowest, it takes its bound. A type parameter that nothing fixes takes its bound, never `BottomType`. The chapter's callouts give two departures of the compiled path: its prelude lacks the conversion between `ZZ32` and `NN32` (row 442), and it bounds a type parameter written without an `extends` clause by `Object`, not `Any` (row 412, P-42). They also give walk's departures, such as the `BottomType` result of a function expression that declares no return type (row 587) (`Specification/basic/inference.tex:292-295` and `:356-425`). Plain tests gate the first rule on both paths: `compiler_tests/InferLone*` and `tests/InferLone*Walk.fss`. Detail: `compile-ladder/rung-instance-bound/REPORT.md` (the bound rule); `Specification/basic/inference.tex:47-124` (the chapter's rule).
- F-174 **The specification states the type group's 2011 overloading model: declarations of one name may differ in their static parameters, and a declaration with static parameters is read over its instances.** It states P-45 and P-42. The section "Declarations with Static Parameters" states the OOPSLA 2011 paper's three rules: No Duplicates, Return Type and Meet. It gives one more restriction as the compiled path's, not the language's: where one generic declaration is more specific than another with as many static parameters, the two must declare them of the same kinds, position by position (row 398). A functional whose single parameter's type is a type parameter with the bound `Any` written, as `T extends Any`, cannot be overloaded; a type parameter with no `extends` clause does not fall under this rule, and walk applies it (row 534, fixed). Neither path runs every set that the rules allow. Appendix I's entry "Overloading with static parameters" names the sets that each path fails: row 542 (the checker, a more specific declaration over an object type), row 537 (the code generator, two declarations whose bounds differ), row 539 (walk, the Meet Rule's search), and rows 779 and 780 (walk, two generic functional methods one inside the other). Detail: `Specification/advanced/overloading.tex:134-150` and `:531-674`; `compile-ladder/rung-spec-overloading/decision-record.md` sections 3 and 4.

- F-176 **The specification allows arithmetic in a size, and two size arguments are identical when they are written alike once each operation on numerals is replaced by its value.** It states P-55. By the grammar, a size is a numeral, a name, a sum, a difference, a product, a power to a numeral or a name, or a bracketed size. Two types whose size arguments are so identical are identical. A static parameter is not known to differ from a numeral. F-146 gives the compiled checker, and F-222 walk's arithmetic. When walk infers a size parameter from a call's argument type, it matches a numeral and binds a name, and solves no size written as an operation: read in `IntNat.unifyStaticArg` (`interpreter/evaluator/types/IntNat.java:126-147`), and observed in row 767. Source: `Specification/basic/types-vals-vars.tex:49-62`; `Specification/appendices/grammars/concrete-syntax.tex:533-547` (`IntExpr`).
