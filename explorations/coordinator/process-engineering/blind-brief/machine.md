# The machine and its prices

Facts about this container and the tools on it, with numbers. They were checked against `explorations/coordinator/FACTS.md` (its test-harness and container sections), the files it cites, `explorations/coordinator/build-cache-exploration.md`, the header lines of the two measurement scripts and the last full run's summary. Times are wall-clock seconds on this machine; a run beside other work is slower.

## The machine

- **CPUs: 4** (Intel Xeon at 2.8 GHz, `nproc` = 4); about 15 GB of memory (`free -g`, measured now). OpenJDK 25. The suites pin one interpreter thread per JVM (`FORTRESS_THREADS=1`, set in `build.xml`), so the four cores are used by running several JVMs at once (`ant testFast` runs four tracks that occupy the four cores; `ant testSystem` is split into four shards).
- **Heaps.** `bin/fortress` gives its JVM 256 MB unless `JAVA_FLAGS` is set; the `ant testSystem` harness 768 MB; `explorations/experiment/env.sh`, which every measurement script expects to be sourced, sets 4 GB.
- **Disk.** Every run that imports a grammar writes a 5.8 MB parser directory to `/tmp` (`/tmp/fortress<random>rats`) and never deletes it; 723 of them (4.2 GB) once filled the disk allowance and broke a tool's output with "no space left on device". Sourcing `explorations/experiment/env.sh` removes them; check `df` before a long run.
- **Build commands.** `export JAVA_HOME=/usr/lib/jvm/java-25-openjdk-amd64`, `export PATH=$JAVA_HOME/bin:$PATH`, `export FORTRESS_HOME=<repo root>`, `unset JAVA_TOOL_OPTIONS`, then `ant compileAll` from the repository root. `ant compileAll` deletes the whole `default_repository/caches` including the tracked file `default_repository/caches/global.map`: restore it with `git checkout -- default_repository/caches/global.map` after every `ant compileAll`, and never commit its deletion. A compiled run (`fortress compile`, `fortress run`) needs the library compiled in order after a rebuild (AnyType, CompilerBuiltin, CompilerLibrary, CompilerAlgebra, CompilerSystem); stale caches give a misleading `NoSuchMethodError`. Walk does not need that order; its first run warms its own caches.

## The times

- `ant compileAll`: 57 s in the last full run; 82 s on a fresh checkout; 25 to 40 s on an already built tree after a small edit.
- The library compile (the five components in order, after `ant compileAll`): 108 to 112 s (AnyType 17, CompilerBuiltin 63, CompilerLibrary 27, CompilerAlgebra 2, CompilerSystem 2); one component alone 2 to 63 s. A base built from nothing, `ant compileAll` plus the library compile plus one walk run, is about 200 s.
- `ant testFast`: 635 s (10 min 35 s) in the last full run, 1,782 tests, 0 failures; the longest single suite in it takes about 440 s, so more parallelism does not shorten it much.
- `ant testSystem`: 243 s (4 min 3 s) in the last full run, 504 tests in four shards, 0 failures.
- The checker-count measurement (`explorations/coordinator/tools/checker-count/run.sh <out-file> [scratch-dir]`; it counts the errors the compiled checker reports on the library before each api's early return, 1 now): about 20 s alone on an idle machine when first measured (the library has grown since); 139 s when it ran beside other jobs.
- The distance measurement (`explorations/coordinator/tools/distance/run.sh <out-file> [scratch-dir] [setting]`; it runs every phase of the compiled checker over all twelve apis and twelve components in one JVM on one busy core and counts every distinct error, 340 now): 1,212 s (20 min) in the last full run, 732 s of it on `FortressLibrary` alone; 789 s on an idle machine earlier; 14 to 24 minutes under load.
- One walk run of a small program: about 8 s on cold caches. A compile of a small program: about 5 s, its run about 1 s.

## Copying a build, and running the old code

- **A built tree can be copied into a new worktree in about 3 s**: `explorations/coordinator/tools/seed-worktree.sh <base-worktree> <new-worktree> <branch> [<start-point>]`. The base worktree must have been built once (`ant compileAll`, the restore of `global.map`, the library compile). The copy (206 MB: build 40 MB, caches 36 MB) runs walk and the compiled path without building anything, and its paths are translated for the new location.
- **The base's code runs beside the new code** with a private cache folder: `explorations/coordinator/tools/old-fortress.sh <base-build> <private-caches> <fortress arguments>...` (for example `old-fortress.sh <base-build> <dir>/old-caches compile P.fss`, then `... run P`, or `... P.fss` for walk). The private folder is a copy of the base's caches, 36 MB made in 0.04 s; the run writes nothing that stays in the base build. Keep the private folder and the programs outside the base build.

## The agents and their prices

- **How many agents run at once: 2.** The multi-agent harness (the script-driven tool that starts agents in parallel or in sequence) runs two agents at a time on this box; more wait for a free slot.
- **An agent's floor is about 45,000 tokens before it does anything** (system prompt, tools, first message). Prompt caching across parallel agents covers the system prompt and tools only (about 33,000 tokens read) and not the first user message (about 11,000 tokens written by each agent). Agents started with an identical whole prompt share the cache (the second reads what the first wrote and writes nothing); a prompt that differs only in its last line shares only the system prompt and tools (about 35,000 tokens read) and writes the rest again.
- **The prompt cache lives 1 hour for the main session and 5 minutes for a subagent.** A call within the life reads the cache and renews it, so a wait taken in steps shorter than the life costs a cache read per step. A wait longer than the life makes the next call write the agent's whole context again with no cache read: a subagent holding a 250,000-token context that waits 8 minutes on a build writes 250,000 tokens at its next call.
- **The Bash tool's time limit is 10 minutes** (600 s) for a foreground call (default 2 minutes); the call is killed at the limit. A longer command runs in the background and is polled.
- **The project counts cost as tokens written**: cache writes and new input. Cache reads are not counted.
- **Three model tiers are available: Opus, Sonnet and Fable.** Fable is the strongest and draws on a separate, scarcer weekly pool; Sonnet is the cheapest. An agent that names no model inherits the session's.
- **An agent call can come back empty.** The harness returns null for an agent it has marked failed, even when the agent delivered its structured result first (the platform's safety filter has ended agents this way); a design must expect it.
- **The platform stops the session's process after about 13 hours** (12 h 58 min of continuous running; the stops fall at 46,636 to 46,660 s) and restarts it in resume mode within seconds. The restart kills every running harness run and every running agent; the conversation, the worktrees, the transcripts and each run's journal survive. **A run of the harness is resumed from its journal**: agents that had finished keep their results, an unfinished agent runs again from its start. The resume reuses the longest unchanged prefix of the run's agent calls in call order, so it needs the script and its arguments exactly as at launch and the agents called in the same order. A VM restart and an interrupt of the session's current turn also kill running agents; a resume from the journal recovers the harness's agents that had finished.
