## 2. What the base lacks entirely for this program, and the closest existing rule

- **Nested arrays** (`SHP` as a vector of shape pairs, L9; `,¨`/`,/` over them, L10, L28; `⍵⊃SHP`, L11): the base has none by construction — an APL value is an `RR64`, an `Array[\RR64,ZZ32\]`, an `Array[\RR64,(ZZ32,ZZ32)\]` or an `Array3` and nothing else (`AplCore.fsi:1-15`). Closest: the **tuple** of rung 5 (`AplSyntax.fsi:650-652`, `aplEachT2`/`aplEachT3` `AplCore.fss:1761-1763`), which is a strand of ARRAYS and is exactly how C4 writes the nine weight matrices.
- **Rank 4** (`(B,BLK,NH,HD)⍴⍵` and `0 2 1 3⍉`, L16, L17, L24): the grammar's reshape stops at three atoms (`AplSyntax.fsi:186-189`) and the library's top rank is `Array3` (`AplCore.fsi:490-491`). Closest: `aplReshape3` (`AplCore.fss:1283`) and `aplPerm`, which is rank 3 and admits only the permutation `1 0 2` (`AplCore.fss:1329-1331`). C4 does not need rank 4: `heads` folds (doc, head) into one plane axis (`FlatArrays.fss:83-95`).
- **A run-time reshape shape** (`(⍵⊃SHP)⍴…`, L10, L11; `N⍴⍳BLK`, L13): the rank is read off the source text (`AplSyntax.fsi:23-28`), and even a single NAME on the left of `⍴` has no rule — the rules are numerals or a parenthesised 2/3-atom strand (`:186-202`). Closest: `(N,Ne)⍴x`, `AplSyntax.fsi:199-200`, the spelling `gaps.md` row 60 says the rule was written for.
- **`⍤1` dyadic over two rank-3 arrays** (L23): the `aplRankD1` family covers (V,V), (s,V), (V,M), (s,M), (M,M), (V,A3), (s,A3) and stops there (`AplCore.fsi:612-620`). ## 4. The grammar's constraints that bear on this program

- **APL names come from closed sets, one grammar alternative per name.** A name cannot be read through a gap in any position (`gaps.md` row 24: a `TemplateGapId` inside a `VarRef` is never substituted), so every readable name is one alternative of `AplName` (`AplSyntax.fsi:675-737`, 60-odd names today), every function name one alternative of `AplFnName` (`:579-596`), and every strand element one alternative of the third set `AplTName` (`:656-665`). The three sets are disjoint by construction (`:575-578`, `:642-649`). Each name is spelled as one character CLASS per letter glued with `#` and closed by `NOT [A:Za:z0:9]`, because a terminal that is a valid identifier becomes a keyword of the whole language (`gaps.md` row 25); longer names must come first (`:674`).
- **A name may not be a word of two or more uppercase letters** (`gaps.md` row 78, `rung-5/v06_caps.out.0`): such a word is a Fortress operator, so neither the binding's `Id` gap nor `AplName`'s expansion can carry it. One uppercase letter is fine — `A B S Q K` are in the set (`AplSyntax.fsi:690-692`, `:704-705`). The base's own comment says so: "HD, NE, VS and the rest of the program's all-capital names cannot be APL names at all (row 78), so they are Hd, Ne, Vs" (`AplSyntax.fsi:676-677`).
- **A multi-line dfn** is `` `{ SPACE b:AplStm SPACE `} `` (`AplSyntax.fsi:544-545`) — a zero-parameter host lambda whose body is the same statement chain as a block, with the braces needing the backtick escape. Inside it, statements are separated by `⋄`, by the book's own trailing comment, or by a line break above a line that begins with a NAME; a line break does NOT separate when the next line can continue the one above, and since rung 4 a dfn's operand is such a continuation (`gaps.md` row 68, `rung-4/u19_break.out.0`). The last statement of a body may carry a trailing comment (`AplSyntax.fsi:145-150`). `⍺` and `⍵` are frame reads, not parameters (`:624-627`), which is what lets dfns nest.
- **Host values in**: free names in a template resolve at the use site (`AplSyntax.fsi:31`), so a host variable whose spelling is in `AplName` is read directly; anything else enters through the escape `⍎ ( SPACE e:Expr SPACE )` (`AplSyntax.fsi:629`), whose parentheses are load-bearing because an undelimited `Expr` gap is greedy. Rung 1 uses it throughout: `aplShow(apl⦇ ⍴⍎(m1) ⦈)` (`rung-1/Rung1.fss:71`). One measured limit: `⍎( … )` **inside a binding's right-hand side** is a Syntax Error — `w04_cost.fss:24:47`, recorded at `rung-6/REPORT.md:113-116`, and the probe was rewritten to call `aplInner` directly.
- **Host values out**: `apl⦇ … ⦈` is an `Expr` (`AplSyntax.fsi:44-45`), so the block's value is an ordinary Fortress value — `m2 = apl⦇ 1 4⍴⍎(v) ⦈` (`rung-1/Rung1.fss:89`). A name bound by `←` is a lambda PARAMETER, so host code inside the block sees it as itself (`gaps.md` row 23), but the binding cannot escape the block and cannot be rebound (`gaps.md` row 29).
- **A component imports the base** with two lines and nothing else — the rung-6 example, `rung-6/Rung6.fss:28-31`: `component Rung6` / `import AplCore.{...}` / `import AplSyntax.{...}` / `export Executable`. `AplSyntax.fss` is a five-line stub, because a grammar may be declared only in an api and an api still needs a component to be importable. The source path must carry `explorations/apl/base` ahead of the library (`rung-6/REPORT.md:51-53`).
- **Two further shapes the program will meet**: a template cannot expand to a binding or an assignment (`AplSyntax.fsi:35-36`), which is why every `←` is a lambda over the REST of the block and why a lone `v ← e` with nothing after it is a Syntax Error (`:76-77`); and `_` is not accepted by an `Id` gap (`gaps.md` row 69), so a throw-away name must be spelled out.
